# 要件定義書: 設定ファイル自動マージ機能

## 1. 概要

### 1.1 機能概要
duofmの起動時に、設定ファイル（config.toml）に記載のない設定項目をデフォルト値で自動追記する機能を実装する。

### 1.2 背景・目的
- 新しい設定項目がアプリケーションに追加されても、既存の設定ファイルには自動で追記されない
- ユーザーは新機能の設定項目の存在を知る手段がない
- 設定ファイルを常に最新の状態に保ち、全ての設定項目をユーザーに提示する

### 1.3 スコープ
- 対象: `~/.config/duofm/config.toml`
- 対象項目: keybindings、colors、history_limit

## 2. 機能要件

### 2.1 自動追記機能

#### FR-001: 不足項目の検出
- 起動時に設定ファイルを読み込み、デフォルト設定と比較
- 設定ファイルに存在しない項目を特定

#### FR-002: デフォルト値での追記
- 不足している設定項目をデフォルト値で追記
- 有効な値として追記（コメントアウトしない）

#### FR-003: 既存設定の保持
- ユーザーが設定した値は変更しない
- 既存のコメントやフォーマットを可能な限り保持
- 新しい項目はファイル末尾に追記

### 2.2 対象設定項目

#### FR-004: keybindings
- 32種類のアクションに対するキーバインディング
- 不足しているアクションのみ追記

#### FR-005: colors
- 34種類のUI色設定（ANSI 256-color）
- 不足している色設定項目のみ追記

#### FR-006: history_limit
- シェルコマンド履歴の上限設定
- 未設定の場合のみ追記

## 3. 非機能要件

### NFR-001: パフォーマンス
- 追記処理は起動時に1回のみ実行
- 既に全項目が存在する場合は書き込みをスキップ

### NFR-002: 信頼性
- ファイル書き込み失敗時はエラーをログに記録し、アプリケーションは正常に起動
- バックアップは作成しない（ユーザー要件）

### NFR-003: 保守性
- 新しい設定項目が追加された場合、defaults.goの変更のみで対応可能

## 4. 制約事項

### 4.1 技術的制約
- TOML形式の解析・生成には既存のライブラリを使用
- 既存のコメントやフォーマットの完全な保持は保証しない（ベストエフォート）

### 4.2 運用制約
- 設定ファイルが存在しない場合は既存のGenerateDefaultConfig()を使用
- 設定ファイルのパースに失敗した場合は追記処理をスキップ

## 5. ユースケース

### UC-001: 新規インストール後の初回起動
1. ユーザーがduofmを初めて起動
2. 設定ファイルが存在しないため、デフォルト設定ファイルを生成
3. アプリケーションが正常に起動

### UC-002: アップデート後の起動（新設定項目あり）
1. ユーザーがduofmをアップデート
2. 既存の設定ファイルで起動
3. 新しい設定項目を検出し、デフォルト値で追記
4. アプリケーションが正常に起動

### UC-003: 通常起動（全項目存在）
1. ユーザーがduofmを起動
2. 設定ファイルに全項目が存在
3. 書き込み処理をスキップ
4. アプリケーションが正常に起動

## 6. 受け入れ条件

### AC-001
起動時に不足している設定項目がデフォルト値で追記されること

### AC-002
既存のユーザー設定値が変更されないこと

### AC-003
追記後の設定ファイルが有効なTOML形式であること

### AC-004
全項目が存在する場合はファイルが変更されないこと
