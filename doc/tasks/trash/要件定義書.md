# 要件定義書: ゴミ箱機能

## 概要

freedesktop.org Trash Specification準拠のゴミ箱機能を実装する。
ファイルを安全にゴミ箱へ移動し、必要に応じて復元できる。

## 目的

- 誤削除からファイルを保護
- 削除操作の取り消しを可能に
- デスクトップ環境との互換性を維持

## 対象ユーザー

| ユーザータイプ | 説明 |
|----------------|------|
| 一般ユーザー | ファイルを安全に削除したいユーザー |
| パワーユーザー | 直接削除とゴミ箱削除を使い分けたいユーザー |

## ユースケース

### UC01: ファイルをゴミ箱へ移動

**アクター**: ユーザー

**事前条件**:
- ファイルまたはディレクトリが選択されている

**基本フロー**:
1. ユーザーが `Delete` キーを押す
2. システムがファイルを `~/.local/share/Trash/files/` へ移動
3. システムが `.trashinfo` ファイルを生成
4. ファイル一覧が更新される

**代替フロー**:
- 同名ファイルが存在: 連番を付与（file.txt → file.2.txt）
- 異なるファイルシステム: コピー＋削除で移動

**事後条件**:
- ファイルがゴミ箱に存在
- 元の場所からファイルが消える

### UC02: ゴミ箱を開く

**アクター**: ユーザー

**事前条件**:
- なし

**基本フロー**:
1. ユーザーが `T` キーを押す
2. アクティブペインが `~/.local/share/Trash/files/` に移動

**事後条件**:
- ゴミ箱内のファイル一覧が表示される

### UC03: ファイルを復元

**アクター**: ユーザー

**事前条件**:
- ゴミ箱ディレクトリ内にいる
- 復元対象ファイルが選択されている

**基本フロー**:
1. ユーザーが `R` キーを押す
2. システムが `.trashinfo` から元パスを読み取る
3. ファイルを元の場所へ移動
4. `.trashinfo` ファイルを削除

**代替フロー**:
- 元の場所に同名ファイルが存在: ユーザーに選択肢を提示
  - 上書き
  - リネーム
  - スキップ

**事後条件**:
- ファイルが元の場所に復元される
- ゴミ箱からファイルが消える

### UC04: ゴミ箱を空にする

**アクター**: ユーザー

**事前条件**:
- ゴミ箱ディレクトリ内にいる

**基本フロー**:
1. ユーザーが `Shift+E` キーを押す
2. 確認ダイアログが表示される
3. ユーザーが確認
4. システムがゴミ箱内の全ファイルと `.trashinfo` を削除

**事後条件**:
- ゴミ箱が空になる

## 機能要件

### Phase 1（MVP）

| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | ゴミ箱へ移動 | `Delete` キーで選択ファイルをゴミ箱へ移動 | 高 |
| F02 | .trashinfo生成 | 元パスと削除日時を記録 | 高 |
| F03 | 衝突回避 | 同名ファイルに連番付与 | 高 |
| F04 | ゴミ箱ナビゲーション | `T` キーでゴミ箱ディレクトリへ移動 | 高 |

### Phase 2（復元と管理）

| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F05 | ファイル復元 | `R` キーで元の場所へ復元 | 高 |
| F06 | 復元時衝突処理 | 上書き/リネーム/スキップの選択 | 高 |
| F07 | ゴミ箱を空にする | `Shift+E` で全削除（確認あり） | 中 |
| F08 | メタデータ表示 | 元パス・削除日時をファイルリスト列に表示 | 中 |

### Phase 3（拡張）

| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F09 | 外部デバイス対応 | `.Trash-$UID` ディレクトリの利用 | 低 |

## キーバインド

| キー | 動作 | 条件 |
|------|------|------|
| `Delete` | ゴミ箱へ移動 | 常時 |
| `d` | 直接削除（既存維持） | 常時 |
| `T` (Shift+t) | ゴミ箱ディレクトリを開く | 常時 |
| `R` | 復元 | ゴミ箱内のみ |
| `Shift+E` | ゴミ箱を空にする | ゴミ箱内のみ |

## データ要件

### ディレクトリ構造

```
~/.local/share/Trash/
├── files/    # ファイル実体
└── info/     # メタデータ（.trashinfoファイル）
```

### .trashinfoファイル形式

```ini
[Trash Info]
Path=/home/user/Documents/important.txt
DeletionDate=2026-01-25T10:30:00
```

| フィールド | 説明 | 形式 |
|------------|------|------|
| Path | 元の絶対パス | URLエンコード（特殊文字） |
| DeletionDate | 削除日時 | ISO 8601形式 |

### エンコーディング

- ファイル形式: UTF-8
- 特殊文字: URLエンコード
- タイムスタンプ: ISO 8601形式

## 非機能要件

### パフォーマンス

- 同一FS移動: `os.Rename` による高速処理
- 異なるFS: コピー+削除（TaskManager活用で進捗表示）
- ゴミ箱一覧表示: 1000ファイル以下で100ms未満

### 互換性

- freedesktop.org Trash Specification準拠
- 他のデスクトップ環境と相互運用可能

### セキュリティ

- 権限チェック: 書き込み権限の確認
- パス検証: ディレクトリトラバーサル防止

## UI要件

### ゴミ箱表示時の追加列

| 列 | 内容 | 表示位置 |
|-----|------|----------|
| 元パス | .trashinfoのPath | ファイルリスト列として表示 |
| 削除日時 | .trashinfoのDeletionDate | ファイルリスト列として表示 |

### 確認ダイアログ

ゴミ箱を空にする際に確認ダイアログを表示:
- 「ゴミ箱内のすべてのファイルを完全に削除しますか？」
- 選択肢: Yes / No

### 復元時衝突ダイアログ

元の場所に同名ファイルが存在する場合:
- 選択肢: 上書き / リネーム / スキップ

## 制約条件

### 技術的制約

- ホームディレクトリにゴミ箱を作成可能であること
- `.local/share/Trash/` への書き込み権限が必要

### スコープ外

- ゴミ箱の自動削除（期間経過後の自動クリーンアップ）
- ゴミ箱サイズ制限
- ネットワークドライブ対応

## テストシナリオ

### 正常系

- [ ] `Delete` キーでファイルがゴミ箱へ移動
- [ ] .trashinfoファイルが正しく生成される
- [ ] `T` キーでゴミ箱が開く
- [ ] `R` キーでファイルが元の場所へ復元
- [ ] `Shift+E` でゴミ箱が空になる

### 異常系

- [ ] 同名ファイル衝突時に連番付与
- [ ] 復元先に同名ファイル存在時にダイアログ表示
- [ ] 権限不足時にエラー表示
- [ ] 異なるFS間の移動が正常動作

### 境界値

- [ ] 空のゴミ箱で `Shift+E` 押下
- [ ] ゴミ箱外で `R` キー押下（何も起きない）
- [ ] 特殊文字を含むファイル名の処理
- [ ] 長いパス名の処理

## 用語定義

| 用語 | 定義 |
|------|------|
| ゴミ箱 | `~/.local/share/Trash/` ディレクトリ |
| .trashinfo | ゴミ箱内ファイルのメタデータファイル |
| 直接削除 | ゴミ箱を経由せずにファイルを削除 |
| 復元 | ゴミ箱内ファイルを元の場所に戻す |
| 衝突回避 | 同名ファイル存在時に連番を付与 |
