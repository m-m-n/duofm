# 要件定義書: ゴミ箱機能

## 概要

freedesktop.org Trash Specification準拠のゴミ箱機能を実装する。
ファイルを安全にゴミ箱へ移動し、必要に応じて復元できる。
**ゴミ箱の内容は専用ダイアログで表示**し、通常のファイル操作とキーバインドが衝突しない設計。

## 目的

- 誤削除からファイルを保護
- 削除操作の取り消しを可能に
- デスクトップ環境との互換性を維持
- キーバインドの衝突を回避（ダイアログ分離）

## 対象ユーザー

| ユーザータイプ | 説明 |
|----------------|------|
| 一般ユーザー | ファイルを安全に削除したいユーザー |
| パワーユーザー | 直接削除とゴミ箱削除を使い分けたいユーザー |

## ユースケース

### UC01: ファイルをゴミ箱へ移動

**アクター**: ユーザー

**事前条件**:
- ファイルまたはディレクトリが選択されている

**基本フロー**:
1. ユーザーが `Delete` キーを押す
2. 確認ダイアログが表示される
3. ユーザーが `Y` で確認
4. システムがファイルを `~/.local/share/Trash/files/` へ移動
5. システムが `.trashinfo` ファイルを生成
6. ファイル一覧が更新される

**代替フロー**:
- ユーザーが `N` または `Esc` でキャンセル: ファイルはそのまま
- 同名ファイルが存在: 連番を付与（file.txt → file.2.txt）
- 異なるファイルシステム: コピー＋削除で移動

**事後条件**:
- 確認後: ファイルがゴミ箱に存在、元の場所からファイルが消える
- キャンセル後: ファイルは元の場所に残る

### UC02: ゴミ箱ダイアログを開く

**アクター**: ユーザー

**事前条件**:
- なし

**基本フロー**:
1. ユーザーが `T` キーを押す
2. 画面中央にゴミ箱ダイアログが表示される
3. 両ペインが暗くなる（dimmed）

**事後条件**:
- ゴミ箱ダイアログが表示される
- ゴミ箱内のファイル一覧（名前・サイズ・削除日時・元パス）が見える

### UC03: ファイルを復元

**アクター**: ユーザー

**事前条件**:
- ゴミ箱ダイアログが開いている
- 復元対象ファイルが選択されている

**基本フロー**:
1. ユーザーが `R` キーを押す
2. システムが `.trashinfo` から元パスを読み取る
3. ファイルを元の場所へ移動
4. `.trashinfo` ファイルを削除

**代替フロー**:
- 元の場所に同名ファイルが存在: ユーザーに選択肢を提示
  - 上書き
  - リネーム
  - スキップ

**事後条件**:
- ファイルが元の場所に復元される
- ゴミ箱からファイルが消える

### UC04: ゴミ箱を空にする

**アクター**: ユーザー

**事前条件**:
- ゴミ箱ダイアログが開いている

**基本フロー**:
1. ユーザーが `Shift+E` キーを押す
2. 確認ダイアログが表示される
3. ユーザーが確認
4. システムがゴミ箱内の全ファイルと `.trashinfo` を削除

**事後条件**:
- ゴミ箱が空になる

## 機能要件

### Phase 1（MVP）

| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | ゴミ箱移動確認 | `Delete` キーで確認ダイアログを表示 | 高 |
| F02 | ゴミ箱へ移動 | 確認後、選択ファイルをゴミ箱へ移動 | 高 |
| F03 | .trashinfo生成 | 元パスと削除日時を記録 | 高 |
| F04 | 衝突回避 | 同名ファイルに連番付与 | 高 |
| F05 | ゴミ箱ダイアログ | `T` キーで画面中央にダイアログ表示（両ペイン暗転） | 高 |
| F06 | ダイアログ列表示 | 名前・サイズ・削除日時・元パスの4列 | 高 |
| F07 | ダイアログナビゲーション | j/k でカーソル移動 | 高 |

### Phase 2（復元と管理）

| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F08 | ファイル復元 | ダイアログ内で `R` キーにより元の場所へ復元 | 高 |
| F09 | 復元時衝突処理 | 上書き/リネーム/スキップの選択 | 高 |
| F10 | ゴミ箱を空にする | ダイアログ内で `Shift+E` により全削除（確認あり） | 中 |
| F11 | マーク機能 | Space キーでファイルをマーク（バッチ操作用） | 中 |

### Phase 3（拡張）

| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F12 | 外部デバイス対応 | `.Trash-$UID` ディレクトリの利用 | 低 |

## キーバインド

### 通常のファイルリスト

| キー | 動作 |
|------|------|
| `Delete` | ゴミ箱へ移動 |
| `d` | 直接削除（既存維持） |
| `T` (Shift+t) | ゴミ箱ダイアログを開く |
| `R` | リネーム（既存維持） |

### ゴミ箱ダイアログ内

| キー | 動作 |
|------|------|
| `j` / `Down` | カーソル下移動 |
| `k` / `Up` | カーソル上移動 |
| `Space` | マーク/マーク解除 |
| `R` | 復元 |
| `Shift+E` | ゴミ箱を空にする |
| `Esc` / `q` | ダイアログを閉じる |

**注**: `R`キーは**ダイアログ内では復元**、**通常のファイルリストではリネーム**として動作し、衝突しない。

## データ要件

### ディレクトリ構造

```
~/.local/share/Trash/
├── files/    # ファイル実体
└── info/     # メタデータ（.trashinfoファイル）
```

### .trashinfoファイル形式

```ini
[Trash Info]
Path=/home/user/Documents/important.txt
DeletionDate=2026-01-25T10:30:00
```

| フィールド | 説明 | 形式 |
|------------|------|------|
| Path | 元の絶対パス | URLエンコード（特殊文字） |
| DeletionDate | 削除日時 | ISO 8601形式 |

### エンコーディング

- ファイル形式: UTF-8
- 特殊文字: URLエンコード
- タイムスタンプ: ISO 8601形式

## 非機能要件

### パフォーマンス

- 同一FS移動: `os.Rename` による高速処理
- 異なるFS: コピー+削除（TaskManager活用で進捗表示）
- ゴミ箱ダイアログ表示: 1000ファイル以下で100ms未満

### 互換性

- freedesktop.org Trash Specification準拠
- 他のデスクトップ環境と相互運用可能

### セキュリティ

- 権限チェック: 書き込み権限の確認
- パス検証: ディレクトリトラバーサル防止

## UI要件

### ゴミ箱ダイアログ

- **表示位置**: 画面中央
- **背景**: 両ペインが暗転（`DialogDisplayScreen`）
- **タイトル**: "Trash" + アイテム数
- **表示列**: 名前、サイズ、削除日時、元パス
- **フッター**: キーバインドヒント

```
┌─────────────────────────────────────────────────────────────────┐
│ Trash                                                     [5]   │
├─────────────────────────────────────────────────────────────────┤
│ Name                Size    Deleted              Original Path  │
├─────────────────────────────────────────────────────────────────┤
│ document.txt        2.1K    2026-01-25 10:30    ~/Documents/    │
│ photo.jpg           1.2M    2026-01-24 15:45    ~/Pictures/     │
│ project/               -    2026-01-23 09:00    ~/src/          │
├─────────────────────────────────────────────────────────────────┤
│ R:Restore  Shift+E:Empty  Space:Mark  Esc:Close                 │
└─────────────────────────────────────────────────────────────────┘
```

### ゴミ箱移動確認ダイアログ

`Delete` キー押下時に表示:

**単一ファイル選択時:**
- タイトル: "Move to Trash"
- メッセージ: "Move 'filename.txt' to trash?"
- 注釈: "File will not be permanently deleted. Disk space will not be freed until trash is emptied."
- 選択肢: [Y]es / [N]o

**複数ファイル選択時:**
- タイトル: "Move to Trash"
- メッセージ: "Move N items to trash?"（Nはファイル数）
- 注釈: "Files will not be permanently deleted. Disk space will not be freed until trash is emptied."
- 選択肢: [Y]es / [N]o

**目的:**
- ゴミ箱へ移動してもディスク容量が解放されないことをユーザーに明示
- 「削除したのに空き容量が増えない」という誤認を防止

### ゴミ箱を空にする確認ダイアログ

ゴミ箱を空にする際に確認ダイアログを表示:
- 「ゴミ箱内のすべてのファイルを完全に削除しますか？」
- 選択肢: Yes / No

### 復元時衝突ダイアログ

元の場所に同名ファイルが存在する場合:
- 選択肢: 上書き / リネーム / スキップ

## 制約条件

### 技術的制約

- ホームディレクトリにゴミ箱を作成可能であること
- `.local/share/Trash/` への書き込み権限が必要

### スコープ外

- ゴミ箱の自動削除（期間経過後の自動クリーンアップ）
- ゴミ箱サイズ制限
- ネットワークドライブ対応

## テストシナリオ

### 正常系

- [ ] `Delete` キーで確認ダイアログが表示される
- [ ] 確認ダイアログにファイル名とディスク容量の注意書きが表示される
- [ ] `Y` キーで確認後、ファイルがゴミ箱へ移動
- [ ] `N` キーまたは `Esc` でキャンセル
- [ ] .trashinfoファイルが正しく生成される
- [ ] `T` キーでゴミ箱ダイアログが開く
- [ ] ダイアログが画面中央に表示され、両ペインが暗転
- [ ] ダイアログ内で `R` キーでファイルが元の場所へ復元
- [ ] 通常のファイルリストで `R` キーでリネームが動作
- [ ] ダイアログ内で `Shift+E` でゴミ箱が空になる

### 異常系

- [ ] 同名ファイル衝突時に連番付与
- [ ] 復元先に同名ファイル存在時にダイアログ表示
- [ ] 権限不足時にエラー表示
- [ ] 異なるFS間の移動が正常動作

### 境界値

- [ ] 空のゴミ箱でダイアログを開く
- [ ] 空のゴミ箱で `Shift+E` 押下
- [ ] 特殊文字を含むファイル名の処理
- [ ] 長いパス名の処理

## 用語定義

| 用語 | 定義 |
|------|------|
| ゴミ箱 | `~/.local/share/Trash/` ディレクトリ |
| ゴミ箱ダイアログ | ゴミ箱の内容を表示する画面中央のモーダルダイアログ |
| .trashinfo | ゴミ箱内ファイルのメタデータファイル |
| 直接削除 | ゴミ箱を経由せずにファイルを削除 |
| 復元 | ゴミ箱内ファイルを元の場所に戻す |
| 衝突回避 | 同名ファイル存在時に連番を付与 |
