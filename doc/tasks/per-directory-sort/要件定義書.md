# ディレクトリ毎ソート設定保持 - 要件定義書

## 1. 概要

### 1.1 背景
現在のduofmでは、ソート設定はペイン単位でセッション中のみ保持される。ディレクトリを移動しても同じソート設定が維持され、アプリケーション終了時には失われる。ユーザーは特定のディレクトリに対して毎回ソート設定を変更する必要がある。

### 1.2 目的
ディレクトリごとにソート設定を永続化し、そのディレクトリに入った際に自動的に適用する。また、現在のソート状態をヘッダーに常時表示し、ユーザーへのフィードバックを改善する。

### 1.3 スコープ
- ソート設定のディレクトリ毎の永続化
- ディレクトリ移動時の自動適用
- ヘッダーLine2へのソート情報表示
- 保存エントリ数のLRU管理

## 2. ユースケース

### 2.1 ユースケース一覧
| ID | ユースケース名 | アクター | 優先度 |
|----|----------------|----------|--------|
| UC01 | ソート設定の保存 | ユーザー | 高 |
| UC02 | ソート設定の自動適用 | システム | 高 |
| UC03 | ソート状態の確認 | ユーザー | 高 |
| UC04 | デフォルトソートへのフォールバック | システム | 高 |

### 2.2 ユースケース詳細

#### UC01: ソート設定の保存

**アクター**: ユーザー

**事前条件**:
- ユーザーがディレクトリを開いている

**基本フロー**:
1. ユーザーがソートダイアログを開く（Sキー）
2. ソートフィールドとソート順を選択する
3. OKボタンを押してダイアログを確定する
4. システムが現在のディレクトリパスとソート設定を永続化ファイルに保存する

**代替フロー**:
- Escで取り消した場合: 設定は保存されない

**事後条件**:
- ソート設定がファイルに永続化されている
- 次回同ディレクトリを開いた際に自動適用される

#### UC02: ソート設定の自動適用

**アクター**: システム

**事前条件**:
- ユーザーがディレクトリに移動する
- そのディレクトリに対する保存済みソート設定が存在する

**基本フロー**:
1. ユーザーがディレクトリに移動する
2. システムが永続化データから該当ディレクトリの設定を検索する
3. 保存済みの設定をペインのソート設定に適用する
4. ファイル一覧を適用されたソート設定で表示する

**代替フロー**:
- 保存済み設定がない場合: グローバルデフォルト（Name ↑）を使用

**事後条件**:
- ファイル一覧が保存済みのソート順で表示されている

#### UC03: ソート状態の確認

**アクター**: ユーザー

**事前条件**:
- ユーザーがディレクトリを開いている

**基本フロー**:
1. ユーザーがヘッダーLine2を確認する
2. 現在のソート設定（フィールド名 + 方向矢印）が表示されている

**事後条件**:
- なし（表示のみ）

#### UC04: デフォルトソートへのフォールバック

**アクター**: システム

**事前条件**:
- ユーザーがディレクトリに移動する
- そのディレクトリに対する保存済みソート設定が存在しない

**基本フロー**:
1. ユーザーがディレクトリに移動する
2. システムが永続化データを検索するが見つからない
3. グローバルデフォルト（Name ↑）を適用する

**事後条件**:
- デフォルトのソート順でファイル一覧が表示される

## 3. 機能要件

### 3.1 機能一覧
| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | ソート設定の永続化 | ソートダイアログ確定時にディレクトリパスとソート設定をTOMLファイルに保存 | 高 |
| F02 | ソート設定の自動適用 | ディレクトリ移動時に保存済み設定を自動適用 | 高 |
| F03 | ヘッダーソート表示 | ヘッダーLine2に現在のソート状態を常時表示 | 高 |
| F04 | LRU管理 | 保存エントリが1000件を超えた場合に古いエントリを削除 | 中 |
| F05 | 保存ファイルの読み込み | アプリケーション起動時に保存ファイルを読み込み | 高 |

### 3.2 機能詳細

#### F01: ソート設定の永続化

**説明**: ソートダイアログでOKを押した時点で、現在のディレクトリのソート設定をTOMLファイルに保存する。

**保存先**: `~/.config/duofm/dir_sort.toml`（XDG_CONFIG_HOME対応）

**保存データ**:
- ディレクトリパス（絶対パス）
- ソートフィールド（name / size / date）
- ソート順（asc / desc）
- 最終アクセス日時（LRU用）

**ビジネスルール**:
- デフォルトソート（Name ↑）と同じ設定の場合も保存する
- 同一ディレクトリの設定は上書きする
- ファイル書き込みエラー時はサイレントに無視する（ユーザー操作をブロックしない）

#### F02: ソート設定の自動適用

**説明**: ディレクトリに移動した際に、保存済みのソート設定があれば自動的にペインのソート設定を切り替える。

**適用タイミング**:
- `EnterDirectoryAsync()` でディレクトリに入った時
- `NavigateHistoryBackAsync()` / `NavigateHistoryForwardAsync()` で移動した時
- `NavigateToPreviousAsync()` で前のディレクトリに戻った時

**ビジネスルール**:
- 保存済み設定がない場合はグローバルデフォルト（Name ↑）を使用
- ペインの現在のソート設定を上書きする

#### F03: ヘッダーソート表示

**説明**: ヘッダーLine2のマーク情報と空き容量の間に、現在のソート設定を表示する。

**表示形式**: `Name ↑` / `Size ↓` / `Date ↑` など
- SortConfig.String() の戻り値をそのまま使用する

**レイアウト**: `Marked 0/15 0 B  Name ↑  50 GB Free`
- マーク情報（左寄せ）、ソート情報（中央）、空き容量（右寄せ）

**ビジネスルール**:
- 常に表示する（保存済みかどうかに関わらず）
- デフォルトソート時も表示する

#### F04: LRU管理

**説明**: 保存エントリ数が1000件を超えた場合、最終アクセスが古いエントリから削除する。

**ビジネスルール**:
- 上限: 1000件
- 淘汰方式: LRU（最終アクセス日時が古い順に削除）
- 淘汰タイミング: 新しいエントリを追加する際に上限を超える場合
- 最終アクセス日時はディレクトリに移動してソート設定を読み込んだ時に更新する

#### F05: 保存ファイルの読み込み

**説明**: アプリケーション起動時に保存ファイルを読み込み、メモリ上にキャッシュする。

**ビジネスルール**:
- ファイルが存在しない場合は空のマップで初期化する
- ファイルのパースに失敗した場合はログを出力し、空のマップで初期化する
- 起動時に一度だけ読み込む（ホットリロード不要）

## 4. 非機能要件

### 4.1 パフォーマンス要件
- ソート設定の検索: O(1)（メモリ上のマップ）
- ファイル書き込み: 非同期で行い、UIをブロックしない

### 4.2 保守性要件
- 保存ファイルはTOML形式で人間が読める
- 保存ファイルを削除すれば全設定がリセットされる

## 5. データ要件

### 5.1 データモデル

**DirSortEntry**:
| 項目名 | 型 | 必須 | 説明 |
|--------|-----|------|------|
| field | string | ○ | ソートフィールド（"name" / "size" / "date"） |
| order | string | ○ | ソート順（"asc" / "desc"） |
| last_access | datetime | ○ | 最終アクセス日時（RFC 3339） |

**保存ファイル構造** (TOML):
```toml
[dirs]

[dirs."/home/user/Downloads"]
field = "size"
order = "desc"
last_access = 2026-02-09T10:30:00+09:00

[dirs."/home/user/Documents"]
field = "name"
order = "asc"
last_access = 2026-02-08T15:00:00+09:00
```

## 6. 制約条件

### 6.1 技術的制約
- Go標準ライブラリおよび既存の依存関係のみ使用する
- 既存のconfig.tomlとは分離した独立ファイルとする
- 既存のソート機能のインターフェースを変更しない

- [ ] 正常系: ソートダイアログ確定で保存される

- [ ] 正常系: 保存済み設定がない場合はデフォルトが使われる
- [ ] 正常系: ヘッダーにソート情報が表示される
- [ ] 正常系: LRU淘汰が正しく動作する
