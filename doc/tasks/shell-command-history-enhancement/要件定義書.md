# 要件定義書: シェルコマンド履歴機能の拡張

## 1. 概要

### 1.1 背景

既存のシェルコマンド履歴機能（`doc/tasks/shell-command-history/SPEC.md`）を拡張し、より使いやすい履歴操作を実現する。現状では以下の課題がある:

1. **上下キーでの履歴ナビゲーション不可**: bashのように上下キーで履歴を遡れない
2. **検索パターンのフィードバック不足**: Ctrl+R検索時に入力した検索パターンが表示されない

### 1.2 目的

- bash/zsh互換の直感的な履歴ナビゲーションを実現
- インクリメンタルサーチ時の検索パターン可視化

### 1.3 スコープ

**含まれるもの:**
- シェルコマンドモードでの上下キー履歴ナビゲーション
- Ctrl+R検索時の検索パターン表示

**含まれないもの:**
- 履歴の永続化（既に実装済み）
- 履歴の検索アルゴリズム変更
- 履歴編集機能

## 2. 機能要件

### 2.1 上下キーによる履歴ナビゲーション

#### FR1: 上キーによる履歴遡り

| 項目 | 内容 |
|------|------|
| 機能ID | FR1 |
| 機能名 | 上キー履歴ナビゲーション |
| 説明 | シェルコマンドモード（`!:`プロンプト）で上キーを押すと、履歴を新しい順に遡り、コマンドを入力欄に表示する |
| 優先度 | 必須 |

**受け入れ条件:**
- [ ] シェルコマンドモードで上キーを押すと、直前のコマンドが入力欄に表示される
- [ ] さらに上キーを押すと、より古いコマンドに移動する
- [ ] 最も古いコマンドに到達した状態で上キーを押しても、エラーにならない
- [ ] 履歴が空の場合、上キーを押しても何も起きない

#### FR2: 下キーによる履歴順送り

| 項目 | 内容 |
|------|------|
| 機能ID | FR2 |
| 機能名 | 下キー履歴ナビゲーション |
| 説明 | 上キーで履歴を遡った後、下キーで新しい履歴方向に戻る |
| 優先度 | 必須 |

**受け入れ条件:**
- [ ] 上キーで履歴を遡った後、下キーを押すと新しいコマンドに戻る
- [ ] 最新のコマンドの状態で下キーを押すと、元の空の入力状態に戻る
- [ ] 履歴ナビゲーションを開始していない状態で下キーを押しても何も起きない

#### FR3: 入力中の履歴フィルタリング（オプション）

| 項目 | 内容 |
|------|------|
| 機能ID | FR3 |
| 機能名 | プレフィックスマッチ履歴ナビゲーション |
| 説明 | 文字を入力した状態で上キーを押すと、入力文字列から始まるコマンドのみを対象にナビゲート |
| 優先度 | 任意（将来拡張） |

**注:** この機能は初期リリースでは実装せず、将来の拡張として検討する

### 2.2 Ctrl+R検索時の検索パターン表示

#### FR4: bash風インライン表示

| 項目 | 内容 |
|------|------|
| 機能ID | FR4 |
| 機能名 | 検索パターンインライン表示 |
| 説明 | Ctrl+Rインクリメンタルサーチ時に、bashと同様の形式で検索パターンとマッチしたコマンドを表示する |
| 優先度 | 必須 |

**表示形式:**
```
(reverse-i-search)`検索パターン': マッチしたコマンド
```

**例:**
- 検索パターン「git」でマッチ: `(reverse-i-search)'git': git push origin main`
- 検索パターン「docker」でマッチ: `(reverse-i-search)'docker': docker-compose up -d`
- マッチなし: `(reverse-i-search)'xyz': `

**受け入れ条件:**
- [ ] Ctrl+R押下時、プロンプトが `(reverse-i-search)'': ` に変わる
- [ ] 文字入力ごとにプロンプトの検索パターン部分が更新される
- [ ] マッチしたコマンドがプロンプトの後に表示される
- [ ] Backspaceで検索パターンから文字を削除できる
- [ ] マッチがない場合、コマンド部分は空になるがエラー表示はしない

## 3. 非機能要件

### 3.1 パフォーマンス

| 要件ID | 内容 | 基準 |
|--------|------|------|
| NFR1 | 上下キーナビゲーション応答 | 50ms以内 |
| NFR2 | 検索パターン更新の反映 | 100ms以内 |

### 3.2 互換性

| 要件ID | 内容 |
|--------|------|
| NFR3 | 既存のCtrl+R検索機能を破壊しない |
| NFR4 | 既存のEnter/Esc動作を維持 |
| NFR5 | 既存の履歴永続化と連携 |

### 3.3 ユーザビリティ

| 要件ID | 内容 |
|--------|------|
| NFR6 | bash/zshに慣れたユーザーが直感的に操作できる |
| NFR7 | 検索中の現在位置が視覚的に明確 |

## 4. ユーザーストーリー

### US1: 直前コマンドの再実行

**As a** パワーユーザー
**I want to** 上キーで直前のコマンドを呼び出して実行したい
**So that** 繰り返し使うコマンドを素早く実行できる

**シナリオ:**
1. ユーザーが`!`を押してシェルコマンドモードに入る
2. 上キーを押す
3. 直前に実行したコマンドが入力欄に表示される
4. Enterで実行、または編集後に実行

### US2: 履歴の検索と可視化

**As a** ユーザー
**I want to** Ctrl+Rで検索時に何を入力しているか確認したい
**So that** 意図した検索パターンで正確に検索できる

**シナリオ:**
1. ユーザーが`!`を押してシェルコマンドモードに入る
2. Ctrl+Rを押してインクリメンタルサーチを開始
3. 「git」と入力すると、`(reverse-i-search)'git': git push origin main` と表示される
4. さらにCtrl+Rを押すと次のマッチに移動
5. Enterで選択したコマンドを実行

## 5. 画面・表示仕様

### 5.1 シェルコマンドモード（通常状態）

```
!: █
```
- 上下キーで履歴をナビゲート可能

### 5.2 シェルコマンドモード（履歴表示中）

```
!: git push origin main█
```
- 履歴からコマンドが表示された状態
- 編集可能
- 編集後も履歴ナビゲーションは継続可能（bashと同様）

### 5.3 Ctrl+R検索モード

```
(reverse-i-search)'git': git push origin main
```
- 検索パターン「git」
- マッチしたコマンド「git push origin main」
- カーソルは検索パターンの後に位置

### 5.4 Ctrl+R検索モード（マッチなし）

```
(reverse-i-search)'xyz':
```
- 検索パターン「xyz」
- マッチなし

## 8. リスクと対策

| リスク | 影響 | 対策 |
|--------|------|------|
| 既存Ctrl+R動作の破壊 | ユーザー混乱 | 既存テストの維持・拡充 |
| 上下キーが他の用途と競合 | 誤操作 | シェルコマンドモードでのみ有効 |
| プロンプト表示の文字化け | 視認性低下 | Unicode対応の確認 |

## 9. 今後の拡張可能性

1. **プレフィックスマッチ（FR3）**: 入力中の上下キーで接頭辞マッチ
2. **Ctrl+S**: 逆方向検索（forward-i-search）
3. **複数行コマンド履歴**: 複数行コマンドの履歴対応
4. **履歴のエクスポート/インポート**: 履歴ファイルの管理機能
