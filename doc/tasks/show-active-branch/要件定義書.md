# 要件定義書: Gitブランチ表示機能

## 1. 概要

### 1.1 機能概要
duofmのファイルペインにおいて、Git管理下のディレクトリを表示している場合に、現在のGitブランチ名をヘッダーに表示する機能。

### 1.2 背景・目的
- ファイルマネージャーでGitリポジトリ内を操作する際、現在のブランチを把握することは重要
- ターミナルのプロンプトでブランチ表示がある環境でも、duofm使用中は画面がフルスクリーンになるため確認できない
- ユーザーが誤ったブランチで作業することを防ぐ

### 1.3 想定ユーザー
- Gitを日常的に使用する開発者
- 複数のGitリポジトリを行き来するユーザー
- duofmをメインのファイルマネージャーとして使用するユーザー

## 2. 機能要件

### 2.1 表示要件

| 要件ID | 要件 | 優先度 |
|--------|------|--------|
| FR-001 | Git管理下のディレクトリではブランチ名を表示する | 必須 |
| FR-002 | ブランチ名はヘッダー1行目の右端に配置する（右寄せ） | 必須 |
| FR-003 | 表示形式は `[ブランチ名]` とする | 必須 |
| FR-004 | Git管理外のディレクトリでは何も表示しない | 必須 |
| FR-005 | 左右のペインは独立してブランチを表示する | 必須 |

### 2.2 表示位置の詳細

```
┌─────────────────────────────────────────────┐
│ ~/project/src                        [main] │  ← ヘッダー1行目（パス左寄せ、ブランチ右寄せ）
│ Marked 0/15 100 MB                10.5 GB   │  ← ヘッダー2行目
├─────────────────────────────────────────────┤
│ file1.txt                                   │
│ file2.go                                    │
```

**レイアウト仕様:**
- パス（`~/project/src`）は左寄せ
- ブランチ名（`[main]`）は右寄せ
- パスとブランチの間はスペースで埋める
- パスが長い場合はブランチ表示を優先し、パスを切り詰める

### 2.3 非機能要件

| 要件ID | 要件 | 優先度 |
|--------|------|--------|
| NFR-001 | ディレクトリ変更時のブランチ取得は100ms以内 | 必須 |
| NFR-002 | Git未インストール環境でもエラーなく動作する | 必須 |
| NFR-003 | 既存のパス表示と調和するスタイルで表示する | 必須 |

## 3. スコープ

### 3.1 含まれるもの
- ブランチ名の取得と表示
- 各ペイン独立でのブランチ表示
- Git管理外ディレクトリでの非表示処理

### 3.2 含まれないもの（将来検討）
- detached HEAD状態の表示
- リベース/マージ中の状態表示
- 未コミット変更の表示（dirty状態）
- ブランチ名の色分け

## 4. ユーザーストーリー

### US-001: ブランチ確認
**As a** 開発者
**I want to** 現在のディレクトリがどのブランチにあるか確認したい
**So that** 誤ったブランチで作業することを防げる

**受け入れ条件:**
- [ ] Git管理下のディレクトリで `[main]` のようにブランチ名が表示される
- [ ] ヘッダー1行目の右端に表示される
- [ ] ディレクトリを移動すると新しいディレクトリのブランチが表示される

### US-002: 非Gitディレクトリ
**As a** ユーザー
**I want to** Git管理外のディレクトリでは余計な表示がない
**So that** 画面がすっきりする

**受け入れ条件:**
- [ ] Git管理外のディレクトリではブランチ表示がない
- [ ] エラーメッセージが表示されない

### US-003: デュアルペイン操作
**As a** 開発者
**I want to** 左右のペインで異なるリポジトリのブランチを確認したい
**So that** 複数プロジェクト間での操作時に混乱しない

**受け入れ条件:**
- [ ] 左ペイン: `/home/user/project-a` → `[main]`
- [ ] 右ペイン: `/home/user/project-b` → `[develop]`
- [ ] 各ペインが独立して正しいブランチを表示する

## 5. 制約事項

### 5.1 技術的制約
- Gitコマンド（`git rev-parse`）の実行が必要
- ディレクトリ変更の度にGitコマンドを実行する

### 5.2 依存関係
- Git がシステムにインストールされていること（オプション）
- 既存のパス表示機能（`pane_render.go`）

## 6. 用語定義

| 用語 | 定義 |
|------|------|
| Git管理下 | `.git` ディレクトリが存在する（または親ディレクトリに存在する）ディレクトリ |
| ブランチ名 | `git rev-parse --abbrev-ref HEAD` で取得できる現在のブランチ名 |
| ペイン | duofmの左右どちらかのファイル表示領域 |
