# 実装計画書: Show Active Git Branch

## 概要

Git管理下のディレクトリを表示している場合に、現在のGitブランチ名をペインのヘッダー1行目の右端に `[branch]` 形式で表示する機能を実装する。

## 目的

- 開発者が現在作業中のブランチを常に把握できるようにする
- 誤ったブランチでの作業を防止する
- 左右のペインで異なるリポジトリの状態を同時に確認可能にする

## 前提条件

### 開発環境
- Go 1.21以上
- make（ビルド自動化用）

### 依存関係
- 既存の `internal/ui/pane.go` が存在すること
- 既存の `internal/ui/pane_render.go` が存在すること
- `github.com/mattn/go-runewidth` パッケージ（既に使用中）

### 必要な知識
- Bubble Tea アーキテクチャの理解
- Go の `os/exec` パッケージによる外部コマンド実行
- Pane 構造体の状態管理パターン

## アーキテクチャ概要

### 技術スタック
- **言語**: Go 1.21+
- **フレームワーク**: Bubble Tea (github.com/charmbracelet/bubbletea)
- **スタイリング**: Lip Gloss (github.com/charmbracelet/lipgloss)
- **文字幅計算**: go-runewidth (github.com/mattn/go-runewidth)

### 設計アプローチ

ブランチ取得は外部コマンド（`git rev-parse --abbrev-ref HEAD`）を使用する。各ペインが独立してブランチ状態を管理し、ディレクトリ変更時に更新する。Git未インストール環境やGit管理外ディレクトリでは、エラーを表示せず単にブランチ表示を省略する（graceful degradation）。

### コンポーネント連携

```
ディレクトリ変更
    |
    v
SetPath() / NavigateTo() / async loading完了
    |
    v
GetGitBranch(path) 呼び出し
    |
    +---> Git管理下 ---> ブランチ名を返す
    |
    +---> Git管理外/エラー ---> 空文字列を返す
    |
    v
Pane.gitBranch に格納
    |
    v
viewInternal() でヘッダー1行目をレンダリング
    |
    +---> gitBranch が非空 ---> パス + ブランチ表示
    |
    +---> gitBranch が空 ---> パスのみ表示
```

## 実装フェーズ

### Phase 1: Git ユーティリティの実装

**目標**: Gitブランチ取得関数を実装し、単体テストで動作を検証する

**作成するファイル**:
- `internal/fs/git.go` - Git操作ユーティリティ
- `internal/fs/git_test.go` - Git操作のテスト

**主要コンポーネント**:

| コンポーネント | 責務 | 事前条件 | 事後条件 |
|---------------|------|----------|----------|
| GetGitBranch | 指定パスのGitブランチ名を取得 | 有効なパス文字列 | ブランチ名または空文字列を返す |

**処理フロー**:
```
GetGitBranch(path) 呼び出し
    |
    v
context.WithTimeout(100ms) でコンテキスト作成
    |
    v
git -C <path> rev-parse --abbrev-ref HEAD を実行
    |
    +---> 成功 ---> 出力をトリムしてブランチ名を返す
    |
    +---> 失敗（Git未インストール/非Gitディレクトリ/タイムアウト）---> 空文字列を返す
```

**実装ステップ**:

1. **GetGitBranch 関数の作成**
   - パスを受け取り、gitコマンドを実行してブランチ名を取得する
   - 留意点:
     - `exec.Command` を使用してコマンドインジェクションを防止
     - `context.WithTimeout` で100msのタイムアウトを設定（NFR1.1準拠）
     - エラー時（タイムアウト含む）は空文字列を返し、エラーログは出力しない

2. **単体テストの作成**
   - Git管理下ディレクトリでのブランチ取得
   - 非Gitディレクトリでの空文字列返却
   - サブディレクトリでのブランチ取得

**依存関係**:
- 必要: なし（新規ファイル）
- ブロック: Phase 2

**テストアプローチ**:

*単体テスト*:
- テスト用の一時ディレクトリに `git init` で新規リポジトリを作成し、明示的なブランチ名でテスト
- `/tmp` などの非Gitディレクトリで空文字列が返る
- 存在しないディレクトリで空文字列が返る
- **注意**: 「現在のリポジトリ」に依存するテストは環境依存でフレーキーになるため避ける。`t.TempDir()` と `git init` を使用して独立したテスト環境を構築すること

**受け入れ基準**:
- [ ] GetGitBranch が Git 管理下ディレクトリでブランチ名を返す
- [ ] GetGitBranch が非 Git ディレクトリで空文字列を返す
- [ ] GetGitBranch がエラー時に空文字列を返す（パニックしない）
- [ ] 単体テストがすべてパスする

**推定工数**: 小 (1-2日)

**リスクと対策**:
- **リスク**: テスト環境にGitがインストールされていない
  - **対策**: CI環境でGitが利用可能であることを確認、またはテストをスキップする条件を追加

### Phase 2: Pane への統合

**目標**: Pane構造体にブランチ状態を追加し、ディレクトリ変更時に更新、ヘッダーに表示する

**変更するファイル**:
- `internal/ui/pane.go`:
  - `gitBranch` フィールドを追加
  - ブランチ取得呼び出しを追加
- `internal/ui/pane_render.go`:
  - ヘッダー1行目のレンダリングを変更
- `internal/ui/model_update.go`:
  - 非同期ナビゲーション完了時のブランチ取得

**主要コンポーネント**:

| コンポーネント | 責務 | 事前条件 | 事後条件 |
|---------------|------|----------|----------|
| Pane.gitBranch | 現在のGitブランチ名を保持 | - | 空文字列または有効なブランチ名 |
| Pane.updateGitBranch | パス変更時にブランチを更新 | パスが設定済み | gitBranchが更新される |
| viewInternal | ブランチ付きヘッダーをレンダリング | Pane状態が有効 | ヘッダー1行目にパスとブランチを表示 |

**処理フロー**:

*ディレクトリ変更時*:
```
ナビゲーション/パス設定
    |
    v
パスを更新
    |
    v
GetGitBranch(新パス) を呼び出し
    |
    v
結果を gitBranch に格納
```

*レンダリング時*:
```
viewInternal() 呼び出し
    |
    v
displayPath を構築（[H]、フィルタインジケータ含む）
    |
    v
gitBranch が非空か確認
    |
    +---> 非空 ---> "[" + gitBranch + "]" を構築
    |
    +---> 空 ---> branchDisplay = ""
    |
    v
利用可能幅を計算
    |
    v
パス幅 = 全幅 - ブランチ幅 - セパレータ幅
    |
    v
パスが長すぎる場合はパスを切り詰め（ブランチは切り詰めない）
    |
    v
パス + パディング + ブランチ でヘッダー行を構築
```

**実装ステップ**:

1. **Pane構造体の拡張**
   - `gitBranch` フィールドを追加
   - 責務: 現在のGitブランチ名を保持

2. **ブランチ更新の統合**
   - 同期的なディレクトリ読み込み時: `LoadDirectory` または `SetPath` でブランチを取得
   - 非同期ナビゲーション完了時: `DirectoryLoaded` メッセージ処理でブランチを取得
   - 留意点:
     - すべてのパス変更経路でブランチが更新されること
     - `NewPane` での初期化時も含む

3. **ヘッダーレンダリングの変更**
   - `viewInternal()` でヘッダー1行目の構築を変更
   - 留意点:
     - 既存の `[H]` やフィルタインジケータとの共存
     - パスとブランチの間にパディングを入れて右寄せ
     - ブランチ表示を優先し、パスを切り詰め
     - **注意**: lipglossのWidth/Paddingスタイルと手動スペース挿入を併用すると競合する可能性があるため、既存のヘッダーレンダリングパターンに従い、`go-runewidth`で文字幅を計算して手動でパディングを行うこと

**依存関係**:
- 必要: Phase 1 (GetGitBranch)
- ブロック: Phase 3

**テストアプローチ**:

*単体テスト*:
- gitBranch が設定されている場合のヘッダーレンダリング
- gitBranch が空の場合のヘッダーレンダリング
- 長いパスが切り詰められることの確認
- `[H]` インジケータとの共存

*統合テスト*:
- Pane作成時にブランチが取得される
- ディレクトリ変更時にブランチが更新される

**受け入れ基準**:
- [ ] Pane構造体に gitBranch フィールドが追加されている
- [ ] NewPane でブランチが初期化される
- [ ] ディレクトリ変更時にブランチが更新される
- [ ] ヘッダー1行目にブランチが `[branch]` 形式で右寄せ表示される
- [ ] 非Gitディレクトリではブランチ表示がない
- [ ] パスが長い場合、パスが切り詰められブランチは完全表示される

**推定工数**: 中 (3-5日)

**リスクと対策**:

## リスク評価

### 技術的リスク

1. **Gitコマンドのパフォーマンス**
   - **リスク**: 大規模リポジトリやネットワークドライブでgitコマンドが遅い
   - **可能性**: 低
   - **影響**: 中（UX低下）
   - **対策**:
     - `git rev-parse --abbrev-ref HEAD` は軽量コマンド
     - 100ms以内で完了することを検証
     - 問題があれば非同期化を検討

2. **Git未インストール環境**
   - **リスク**: Gitがインストールされていない環境でエラーが発生
   - **可能性**: 低
   - **影響**: 中
   - **対策**:
     - コマンド実行エラーを適切にハンドリング
     - エラー時は空文字列を返し、機能を無効化

### 実装リスク

1. **パス変更経路の漏れ**
   - **リスク**: 一部のナビゲーション経路でブランチが更新されない
   - **対策**: すべてのパス変更箇所を洗い出し、統合テストで検証

## パフォーマンス考慮事項

1. **ブランチ取得**
   - `git rev-parse --abbrev-ref HEAD` は軽量（通常 <50ms）
   - ディレクトリ変更時のみ呼び出し（遅延評価）
   - キャッシュは行わない（ブランチは外部で変更される可能性がある）

2. **レンダリング**
   - ブランチ表示の追加は文字列操作のみ
   - パフォーマンスへの影響は無視できる

## セキュリティ考慮事項

1. **コマンドインジェクション**
   - `exec.Command` を使用し、引数を分離（シェル解釈なし）
   - パスをそのままコマンドに渡すが、`-C` フラグで指定するため安全

2. **パストラバーサル**
   - Gitコマンドは指定ディレクトリ内でのみ動作
   - 追加のパス検証は不要
