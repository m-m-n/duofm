## Design

### Current app behavior the tests must follow (read from `internal/ui` at the base commit)
- The context menu opens on `@`. Items are numbered, and a number key selects and runs the item at once (no Enter). For a regular file without marks, the order is: Open, Open with ..., Copy to other pane, Move to other pane, Delete, Copy file name, Copy full path, Compress, then Extract archive only for supported archive files. Compress is therefore item 8 and Extract archive item 9. With marks the Compress label is "Compress N files". Disabled items still take a number.
- The format dialog ("Select Archive Format") lists formats numbered from 1. A number key selects at once. Choosing tar opens the archive name dialog directly. Other formats open the compression level dialog first.
- Compress and extract write into the inactive pane's directory. The right pane does not start in `/testdata/user_owned`.
- The default archive name is the source file's base name plus the format extension for one file, and the parent directory's name plus the extension for several files.

### Numbered selection rule
Before pressing a number key in the context menu or the format dialog, assert that the list shows that number with the expected label (for example "8. Compress"). If the numbering shifts (new menu items, different installed archive tools), the test then fails with a clear message instead of selecting the wrong item.

### Destination pane rule
Tests that check output first make the inactive pane show the intended directory under `/testdata/user_owned` (the existing sync-pane flow, as in the directory tests), then check the output at that exact path.

### Flow per test (behavioral)
1. Remove this test's own fixture names, then create its fixtures under `/testdata/user_owned`.
2. Start duofm and bring the active pane to `/testdata/user_owned` by name.
3. For tests that check output, apply the destination pane rule (`/testdata/user_owned`, or the test's own subdirectory such as the conflict or extract destination) before starting the operation.
4. Reach the source entry by name.
5. Press `@`, assert the numbered line for the wanted item ("8. Compress", "8. Compress 3 files", "9. Extract archive"), then press that number.
6. In the format dialog, assert the numbered line for the wanted format (tar = 1, tar.gz = 2), then press that number.
7. Continue through the level, name, and conflict dialogs as the test's purpose requires, asserting each dialog's own text.
8. Check outcomes on disk where required, using the inline check convention.
9. Remove every file and directory the test created, including produced archives, whatever the earlier checks returned.

### Per-test decisions
- `test_compress_format_dialog_opens`: the menu check asserts the numbered Compress item, not the bare word "Compress".
- `test_multifile_compress`: uses tar.gz instead of zip, so the result does not depend on zip being installed. The "skipped" branch that raised the run count without a pass or fail is removed. Checks: the archive named after the parent directory exists in the destination, and it contains all three marked files. Cleanup removes that archive by its exact name.
- `test_archive_conflict_dialog`: the destination subdirectory already holds an archive with the default name, so accepting the default name shows the conflict dialog. Assert its text and options, then cancel.
- `test_extract_complete_workflow`: the destination is the test's own subdirectory. Check the extracted file's existence and exact content there.
