# Task Plan: task0005 — Help shell-command entry, bookmark hint, and history forward-cleared tests

## Goal

Three single-test fixes. The help test finds the `!` entry by paging and checks its wording. The bookmark test checks the current `d:Delete` hint. The history test proves forward history is cleared using only directories the test user can enter.

## Requirements

- `test/e2e/scripts/tests/history_tests.sh` — test_history_forward_cleared

## Design

### Current app behavior (read from `internal/ui` at the base commit)
- The help dialog is paged. It shows a page indicator, pages forward on Space, and lists the entry "!" with the text "execute shell command".
- The bookmark dialog footer shows the hint "d:Delete" (lowercase d).
- In the E2E image, `/testdata/dir1/subdir` and `/testdata/no_access` have no permissions for the test user. `/testdata/dir1`, `/testdata/dir2`, `/testdata/empty_dir` and `/testdata/user_owned` can be entered. History back and forward use `[` and `]`.

### Help test
1. Open help and assert it is open (for example by its first-page indicator).
2. Page forward until the shell-command entry is visible. Stop after at most the number of pages the dialog reports, so the test cannot loop forever.
3. Assert "execute shell command" is shown. The test fails when the entry is not reached within the bound. The bare `!` check is removed.

### Bookmark test
- Replace the "D:Delete" expectation with "d:Delete". The other hint checks stay as they are.

### History test
1. From `/testdata`, enter an enterable directory A and assert arrival.
2. Go back with `[` and assert arrival back at `/testdata`, so forward history now points at A.
3. Enter a different enterable directory B and assert arrival.
4. Press `]`, assert the pane still shows B, and assert it does not show A's distinguishing content.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: `test_help_shows_shell_command` asserts the help dialog is open, pages forward at most as many times as the dialog has pages, and asserts "execute shell command" is shown. No check of a bare `!` remains.
- [ ] AC-2: `test_bookmark_dialog_opens` expects "d:Delete" and no longer expects "D:Delete".
- [ ] AC-3: `test_history_forward_cleared` enters only directories the test user can enter (never `dir1/subdir` or `no_access`), asserts arrival after each move (A, back to `/testdata`, B), and after `]` asserts it is still in B and not in A.
- [ ] AC-4: None of the three edited tests has a check that passes regardless of the behavior it names. Each test's run-count increase equals its passed plus failed increase.
- [ ] AC-5: No `test_`-prefixed function is renamed, added, or removed in the three files. The bash syntax check passes for all three. If shellcheck is installed, the changed lines add no findings.
- [ ] AC-6: Every literal the edited tests expect on screen appears in the `internal/ui` source at the base commit, or, for directory contents, in `test/e2e/Dockerfile`. The task's test record lists each literal with its source.
