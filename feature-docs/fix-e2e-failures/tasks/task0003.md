## Design

### Current app behavior the tests must follow (read from `internal/ui` at the base commit)
- Rename opens an extension-preserving dialog. Its title names the fixed extension (for a `.txt` file the title contains "Rename (extension: .txt)"). The input is pre-filled with the base name only, and the extension is appended on confirm. The text input supports clearing to the start of the line.
- Deleting marked files shows a confirmation that names the count. It is confirmed with `y`.

### Rename tests
1. Remove both the source and target names of this test, then create the source file (`before_rename.txt` / `navren_before.txt`).
2. Reach the file by name and press `r`.
3. Assert the extension dialog title and the pre-filled base name.
4. Clear the input and type only the new base name (`after_rename` / `navren_after`).
5. Confirm, then check on disk that the target exists and the source does not. `test_rename_file` also asserts that the listing shows the new name.
6. `test_navigation_after_rename` keeps its existing quit-with-`q` check after the rename checks.
7. Remove both names at the end whatever the outcome.

### Batch-delete test
1. Remove, then create, this test's own files (`del1.txt`, `del2.txt`) in `/testdata/user_owned`.
2. Mark each of the two files after reaching it by name. The steps must work whatever else is in the directory (for example leftover rename files that sort before `del1.txt`).
3. Assert the mark count, press `d`, assert the 2-file confirmation, confirm with `y`.
4. Check on disk that both files are gone, and assert the marks are cleared.
5. Remove any of the two files still present at the end.

### Newly listed delete-confirmation tests (IMPLEMENTATION.md D3)
- Compare their keys and expected text with the current delete confirmation dialog. Correct only what differs from current behavior, keep the names, and keep their fixtures (`test_enter_delete.txt`, `test_y_delete.txt`) removed at the end whatever the outcome.
