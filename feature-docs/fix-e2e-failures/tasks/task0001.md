# Task Plan: task0001 — E2E runner: corrected run list and coverage guards

## Goal

The full E2E run (runner with no argument) calls every defined test exactly once. The run fails and names the problem when the run list has a name with no defined function, or when a defined `test_` function is missing from the list. A check-only mode reports the same problems without starting tmux or duofm.

## Design

### Run list (single source)
- The full-run list stays explicit and grouped under the existing group headings (Basic, Directory, File Operation, Copy/Move, Mark, Sort, Cursor, Shell, Config, Bookmark, History Navigation, Archive, Background Command, Cursor Preserve), in the current group order.
- Remove the 3 names with no definition: `test_sort_dialog_hl_navigation`, `test_sort_dialog_jk_navigation`, `test_sort_dialog_confirm`.
- Add the 9 defined tests that were never run, placed in their group and ordered as they appear in their file:
  - Sort: `test_sort_dialog_tab_navigation`, `test_sort_dialog_dropdown_expansion`, `test_sort_dialog_dropdown_jk_navigation`, `test_sort_dialog_q_cancel_with_dropdown`, `test_sort_dialog_jk_major_item_navigation`, `test_sort_dialog_ok_button_confirmation`, `test_sort_dialog_tab_three_items`
  - File Operation: `test_delete_confirmation_enter_ignored`, `test_delete_confirmation_y_key_works`
- The list is a data structure that the full run and the guards both read, so the guards and the executed list cannot drift apart. The group headings stay visible in the full-run output.
- Result: 120 entries, one for each name in the frozen name set (IMPLEMENTATION.md Shared Components).

### Definition set
- The set of defined tests is every top-level function whose name starts with `test_` in any file that matches `tests/*.sh`. Scan the files themselves, not only the category map, so a test file missing from the category map is still detected.

### Guard behavior (one routine used by both modes)
- **Undefined entry**: a run-list name that no file defines. It is never invoked. A line names it, and it counts as exactly one failure (Total +1, Failed +1).
- **Missing entry**: a defined `test_` function absent from the run list. A line names the function and its file, and it counts as exactly one failure.
- Full run (no argument): the guard results go into the same summary as the tests. Every defined listed test still runs. The exit status follows the Full-run outcome contract (non-zero exactly when Failed > 0).
- The runner aborts on the first unguarded failing command. The guard logic must not trigger that abort. It reports and counts instead.

### Check-only option
- New option `--check-list`. It sources the helpers and test files (defining functions only), runs the guard routine, prints one line per problem, and exits with status 0 and a one-line OK message when there are no problems, or a non-zero status otherwise. It never starts tmux or duofm. Add it to the usage text.

### Unchanged behavior
- Category mode (`run_all_tests.sh <category>`), `--list` / `-l`, `--help` / `-h`, and the category map behave as before.
