# Task Plan: task0004 — Sort dialog q tests assert that q does not close the dialog

## Goal

The two sort "q" tests pass only when `q` leaves the sort dialog open, once in the normal state and once with a dropdown expanded. The other sort tests joining the run list match current behavior.

## Requirements

FR4, FR9, NFR1, NFR3

### Files to Create

### Files to Modify

## Design

### Current app behavior (read from `internal/ui` at the base commit)
- The sort dialog shows "Sort by", "Order" and an OK button. With no dropdown expanded, `q` is not a dialog key and does nothing. With a dropdown expanded, keys go to the dropdown first. Escape closes an expanded dropdown only. With none expanded, Escape cancels the dialog. `q` was removed from the sort dialog on purpose (doc/tasks/cancel-key-unification/SPEC.md FR2).

### q tests
1. Open the dialog with `s` and assert it is shown.
2. For the dropdown variant, expand the Sort by dropdown and assert it is expanded, using text that appears only while it is expanded (take it from the dropdown rendering source).
3. Press `q`.
4. Assert the dialog is still shown. Because the checks assert presence, the test fails if `q` closes the dialog or quits the app.
5. Update the check descriptions to say the dialog stays open after `q`.
6. Close the dialog with Escape before stopping the session.

### Newly listed sort tests (IMPLEMENTATION.md D3)
- `test_sort_dialog_dropdown_expansion`, `test_sort_dialog_dropdown_jk_navigation`, `test_sort_dialog_jk_major_item_navigation`, `test_sort_dialog_ok_button_confirmation`, `test_sort_dialog_tab_three_items`: compare keys and expected text with current dialog behavior and correct only what differs, keeping names.
- `test_sort_dialog_tab_navigation` has no assertions. Leave it as is (A5) unless it has to be edited for another reason.
