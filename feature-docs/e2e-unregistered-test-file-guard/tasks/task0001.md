# Task Plan: task0001 — Runner guard for unregistered test files, undefined run_test names, and runner self-test

## Goal

A test that lives in a `tests/*.sh` file not registered in `TEST_FILES` can no longer drop out of the E2E tally: `run_test` counts an undefined name as one failure, the run-list guard reports every unregistered file in the full run and in `--check-list`, and a new bash self-test proves both against fixture copies of the runner.

## Requirements

FR1, FR2, FR3, FR4, FR5, NFR1, NFR2, NFR3, NFR4

## Scope

### Files to Create
- `test/e2e/scripts/runner_self_test.sh` — runner self-test covering TS-1 to TS-5 (contract: IMPLEMENTATION.md Shared Components, D1)

### Files to Modify
- `test/e2e/scripts/helpers.sh` — run_test counts a name that is not a defined shell function as one failure and does not invoke it (FR1)
- `test/e2e/scripts/run_all_tests.sh` — run-list guard collects unregistered files, the full run counts and reports them, the check-list mode reports them, and the header usage comment mentions the new check (FR2, FR3, FR4)

## Design

### 1. `run_test` in `helpers.sh` (FR1)

Contract of `run_test(name)`:

- **Pre**: the tally counters exist (loaded with `helpers.sh`).
- **Post, name is a currently defined shell function**: unchanged — the `--- Running: <name> ---` header is printed, `CURRENT_SESSION` is exported, the function is invoked, its return status is not used for the tally, and the tmux session cleanup is attempted.
- **Post, name is not a defined shell function** (including a name that resolves only to a builtin, an alias, an external command, or nothing): the header is printed; the name is NOT invoked; TESTS_RUN and TESTS_FAILED each increase by exactly 1; TESTS_PASSED is unchanged; one failure line is printed that contains the name, uses the same red cross marker as the other failure lines, and carries a fixed distinctive phrase stating that no test function with that name is defined. The shell's "command not found" diagnostic never appears.
- The decision is a function-definition lookup made before any invocation — never inferred from the exit status (127 or otherwise) of an attempted call.
- Counter updates must not return a non-zero status (callers run with exit-on-error enabled).

### 2. Run-list guard `run_guard_checks` in `run_all_tests.sh` (FR2)

- Adds a third result list next to the existing undefined-entry list (GUARD_UNDEFINED) and missing-entry list (GUARD_MISSING), named in the same style: the unregistered files.
- Unregistered file = the basename of a regular file matching `tests/*.sh` under the runner directory whose basename is exactly equal to no value of `TEST_FILES`. The list is sorted so output is deterministic. No `tests/*.sh` match means an empty list, not an error.
- Returns 1 when any of the three lists is non-empty, 0 otherwise. The computation of the two existing lists is unchanged.
- Stays safe under exit-on-error: it is only ever evaluated as a condition, as today.

### 3. Full run `run_all` in `run_all_tests.sh` (FR3)

- Loading of the files named in `TEST_FILES` is unchanged — unregistered files are still not loaded.
- For each unregistered file: TESTS_RUN +1, TESTS_FAILED +1, and one failure line containing the file's basename plus a fixed distinctive phrase stating that the file is not registered in `TEST_FILES`. The lines belong to the run-list guard report (where the missing-entry failures are reported today); placement within the output is the implementer's choice as long as each file produces exactly one such line.
- A test from an unregistered file that is listed in `FULL_RUN_LIST` is in the static definition set, so it still goes through `run_test` and is counted as a failure by section 1 (A-3). It is not reported as an undefined run-list entry.
- The summary and exit status are still decided by `print_summary` in `main` (unchanged).

### 4. Check-list mode `check_list` in `run_all_tests.sh` (FR4)

- When the guard reports a problem: one line per unregistered file, containing its basename and the same distinctive phrase as the full run, printed together with the existing `Undefined run-list entry:` and `Missing from run list:` lines (their wording unchanged); return 1 so the mode exits 1.
- The `OK: run list matches defined tests ...` line and exit 0 happen only when all three lists are empty.
- Still starts neither tmux nor duofm.

### 5. Runner self-test `runner_self_test.sh` (FR5, NFR1, NFR2, NFR3)

Processing flow:

1. Resolve its own directory; the scripts under test are the `run_all_tests.sh` and `helpers.sh` sitting there (IMPLEMENTATION.md Shared Components).
2. Create its own temporary directory and remove it on exit. Write nowhere else (NFR2).
3. For each scenario, build a fresh fixture directory inside it: copies of the two scripts plus a fixture `tests/` subdirectory. Fixture test functions only update the tally counters and print; they never start tmux or duofm (NFR1). A "passing" fixture test increases TESTS_RUN and TESTS_PASSED by one each. Fixture files must not change counters at load time.
4. Give the runner copy the scenario's own `TEST_FILES` and `FULL_RUN_LIST` (A-2).
   - Preferred: rewrite the two list definitions inside the copy and execute the copy as a program, so `main`, `run_all` / `check_list`, `run_guard_checks`, `run_test`, `print_summary` and the exit status are all exercised exactly as in production.
   - Allowed alternative: load the copy without executing `main` and replace the two lists — only if the scenarios still assert the same exit statuses the program would produce.
   - Either way, confirm the fixture lists actually took effect before judging the scenario (for example, the copy no longer carries production entries). Failure to apply them is a scenario failure (fail closed).
5. Run the scenarios below, capturing combined output and exit status per invocation.
6. Print one result line per scenario (scenario ID, short name, PASS or FAIL), with details on failure. Run every scenario even after a failure.
7. Exit 0 if and only if every scenario passed.

Scenarios (A = registered fixture file with one passing test; B = fixture file not in `TEST_FILES` with one test):

| ID | Fixture | Invocation | Expected |
|----|---------|------------|----------|
| TS-1 | A and B; `TEST_FILES` lists A only; `FULL_RUN_LIST` lists both tests | full run (no argument) | exit status non-zero; summary Total 3, Passed 1, Failed 2; an unregistered-file line naming B's basename; an undefined-function line naming B's test |
| TS-2 | same as TS-1 | `--check-list` | exit status 1; an unregistered-file line naming B's basename; no OK line |
| TS-3 | every fixture file registered; every defined test listed | `--check-list`, then full run | check-list: OK line, exit 0; full run: Failed 0, exit 0 |
| TS-4 | same as TS-1 but B's test is not in `FULL_RUN_LIST` | `--check-list` | exit status 1; an unregistered-file line naming B's basename AND the existing `Missing from run list` line |
| TS-5 | copy of `helpers.sh` loaded into a child shell | `run_test` with a name that is not defined | TESTS_RUN +1, TESTS_FAILED +1, TESTS_PASSED unchanged; an undefined-function line naming it; no "command not found" diagnostic |

"Unregistered-file line" and "undefined-function line" mean lines carrying the distinctive phrases from sections 1 and 3. The existing `Missing from run list: <name> (<file>)` line already contains a file basename, so asserting only "the basename appears somewhere" would not tell the fix apart from the pre-fix behavior (TS-4).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: `run_test` given a name that is not a defined shell function does not invoke it, increases TESTS_RUN and TESTS_FAILED by exactly 1 each, leaves TESTS_PASSED unchanged, prints an undefined-function line containing the name, and produces no "command not found" diagnostic; for a defined function the behavior (invocation, return status not counted, tmux cleanup) is unchanged. (TS-5; FR1)
- [ ] AC-2: The full run on the TS-1 fixture exits non-zero with summary Total 3 / Passed 1 / Failed 2, and its output contains an unregistered-file line naming the unregistered file and an undefined-function line naming its test. (TS-1; FR1, FR2, FR3)
- [ ] AC-3: `--check-list` with an unregistered file exits 1, prints an unregistered-file line naming it, and never prints the OK line — both when that file's test is in `FULL_RUN_LIST` (TS-2) and when it is not, in which case the existing `Missing from run list` line also appears (TS-4). (FR2, FR4)
- [ ] AC-4: With every `tests/*.sh` registered and every defined test listed, `--check-list` prints the OK line and exits 0, and the full run reports Failed 0 and exits 0 — on the TS-3 fixture; and `--check-list` on the real repository (15 files under `test/e2e/scripts/tests/`) prints the OK line and exits 0. (TS-3; FR2, FR3, FR4)
- [ ] AC-5: `runner_self_test.sh` prints one result line per scenario TS-1 to TS-5, exits 0 when all pass, and exits non-zero when any scenario fails or when the fixture lists cannot be applied; placed next to the pre-change `run_all_tests.sh` and `helpers.sh`, it exits non-zero with TS-1, TS-2, TS-4 and TS-5 reported as FAIL. (FR5)
- [ ] AC-6: A self-test run starts no tmux session and no duofm process (the only tmux call allowed is the session cleanup inside `run_test`), writes nothing outside its own temporary directory (its own directory is unchanged afterwards), and uses only bash and basic commands already present in the E2E image. (NFR1, NFR2, NFR3)
- [ ] AC-7: `--help` and `--list` output are byte-identical to the pre-change output, a category run still runs every `test_` function of that category's file through `run_test`, and no file under `test/e2e/scripts/tests/` is modified. (NFR4)

## Test Notes

- The self-test is this task's test suite. Write it first, run it against the current (pre-change) `run_all_tests.sh` and `helpers.sh`, and confirm TS-1, TS-2, TS-4 and TS-5 fail while TS-3 passes (TDD red; also the evidence for AC-5). Then change `helpers.sh` and `run_all_tests.sh` until every scenario passes.
- The summary lines wrap the counts in terminal color sequences. Normalize the captured output before extracting Total / Passed / Failed, compare with exact equality, and treat an unreadable count as a scenario failure.
- Fixture test files may follow the real test-file shape (loading `helpers.sh` relative to their own location resets the counters at load time). The runner loads every registered file before running any test, so this is harmless as long as no fixture changes counters at load time.
- AC-6 is checked outside the self-test: run it with recording stand-ins for tmux and duofm placed first on the command search path and assert that duofm is never called and tmux is only called for session cleanup; compare a recursive listing with checksums of the self-test's directory before and after the run.
- AC-7: capture `--help` and `--list` output from the pre-change scripts (the `--list` counts come from the real `tests/` files) and compare byte for byte. Category-run behavior can be checked on a fixture copy with a category whose file defines two tests.
- `--check-list` on the real repository (AC-4) is safe on the host: it only loads the test files and starts nothing.
- Edge cases worth a check: a name that exists only as a builtin or external command counts as undefined (AC-1); an empty fixture `tests/` directory yields no unregistered files and no error.

## Out of Scope

- Behavior when a `TEST_FILES` value names a file that does not exist (A-4).
- Test functions that run no assertion not appearing in the tally (A-5).
- Changes to files under `test/e2e/scripts/tests/`, to the Makefile, or to `test/README.md`.
- The E2E image's default command (IMPLEMENTATION.md D2).
- New command-line options or environment-variable overrides for the runner.
