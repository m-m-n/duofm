# Task Plan: task0002 — E2E image runs the runner self-test before the suite

## Goal

Every `make test-e2e` run executes the runner self-test inside the container first; the E2E suite runs only when the self-test passes, and a failing self-test makes the run end with a non-zero exit status.

## Requirements

FR6, NFR2, NFR3, NFR4

## Scope

### Files to Create

None.

### Files to Modify
- `test/e2e/Dockerfile` — the default command runs the runner self-test, then the runner only when the self-test passed (FR6)

## Design

Default command behavior (IMPLEMENTATION.md D2 and Shared Components):

1. Run the self-test at its in-image path `/e2e/scripts/runner_self_test.sh` with no arguments.
2. Self-test exits 0 → run the runner at `/e2e/scripts/run_all_tests.sh` with no arguments. The container's exit status is the runner's.
3. Self-test exits non-zero, or cannot be executed (missing, not executable) → the runner is not run and the container exits non-zero (A-1).

Constraints:

- It stays a default command that an explicit command given to the container replaces entirely. Existing explicit invocations — `/e2e/scripts/interactive.sh` as documented in `test/README.md`, or the runner with a category argument or `--check-list` — run on their own, without the self-test. Do not introduce an entry-point wrapper that would also apply to explicit commands.
- Everything else in the Dockerfile stays as it is: base image, package installation, build steps, fixture creation, the scripts copy and recursive permission step (it already covers the new self-test file, IMPLEMENTATION.md D1), `WORKDIR /testdata`, and `USER testuser` (so the self-test runs as testuser, NFR2).
- Update the comment above the default command so it states that the self-test runs first.
- The Makefile needs no change: `make test-e2e` runs the image without a command.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: With a stand-in self-test that exits 0 and a stand-in runner that records its arguments and exits with a chosen status, the image's default command runs the self-test before the runner, runs the runner exactly once with no arguments, and exits with the runner's status (checked with both 0 and a non-zero status). (FR6)
- [ ] AC-2: With a stand-in self-test that exits non-zero, and separately with no self-test file at the in-image path, the default command never runs the runner and the container exits non-zero. (FR6)
- [ ] AC-3: Running the image with an explicit command (for example the runner with `--help`) executes only that command; the self-test does not run. (NFR4)
- [ ] AC-4: The image still runs as testuser with working directory `/testdata`, and the Dockerfile diff is limited to the default command and its comment (base image, package list and build steps unchanged). (NFR2, NFR3)

## Test Notes

- The deliverable is container configuration, so there is no in-repository unit test for it. Test by building the image (`make test-e2e-build`) and running it with stand-in scripts mounted read-only over `/e2e/scripts/runner_self_test.sh` and `/e2e/scripts/run_all_tests.sh`; each stand-in prints a marker and exits with a chosen status. This checks the sequencing without running the real suite and without depending on the real self-test.
- Tasks run in parallel, so the self-test file may not exist in this worktree. Running the image built from this worktree without a mount then exercises the "self-test cannot be executed" branch of AC-2.
- AC-3: mount a stand-in self-test that prints a marker, run the image with an explicit command, and assert the marker is absent.
- AC-4: inspect the built image's configured user and working directory, and review the Dockerfile diff.
- Record each check and its observed result in the task's test record.

## Out of Scope

- The self-test's content and the changes to `run_all_tests.sh` and `helpers.sh`.
- The Makefile, the base image version, and the installed package set.
- Running the full E2E suite as part of this task (the integrated run is checked in the verify phase).
