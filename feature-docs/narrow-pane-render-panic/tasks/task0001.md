# Task Plan: task0001 — Prevent narrow-width render panics in pane and minibuffer views

## Goal

Pane views at pane widths 0–4, the minibuffer view at any input display width, and the whole model view at terminal widths 0–3 render without panicking, with unchanged output at normal widths, and `internal/ui` unit tests detect a recurrence.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, NFR1, NFR2, NFR3

## Scope

### Files to Create

None. All changes go into existing files.

### Files to Modify
- `internal/ui/pane_render.go` — clamp the header separator glyph count at zero in the normal, background-output split and dimmed pane views
- `internal/ui/minibuffer.go` — skip the input-window slicing when the input display width is zero or negative
- `internal/ui/pane_render_test.go` — narrow-width no-panic, separator-count and row-count tests for the four pane views
- `internal/ui/minibuffer_test.go` — narrow-width no-panic and single-line tests for the minibuffer view
- `internal/ui/model_basic_test.go` — model-level no-panic test at terminal widths 0 to 3

## Design

Cross-task conventions (width clamping, row-structure invariant, panic regression test style) and decisions D1–D3 are in IMPLEMENTATION.md; this section covers this task only.

### 1. Header separator row (FR1, FR4, NFR1)

Applies to the three places in `internal/ui/pane_render.go` that draw the header separator: `viewInternal` (reached by `View`, `ViewWithDiskSpace`, `ViewWithMinibuffer`), `ViewWithBgOutput` and `ViewDimmedWithDiskSpace`.

- Contract: the separator row holds exactly max(0, pane width − 2) "─" glyphs, with its existing padding and styling.
- At pane widths 0 and 1 the glyph count is zero, and the separator row is still emitted as its own row (followed by its line break), so the header stays `paneHeaderRows` rows.
- At pane widths ≥ 2 the count equals pane width − 2, so output is unchanged.
- The three sites must compute the count the same way. A small unexported helper inside `internal/ui/pane_render.go` shared by the three views is acceptable; so is clamping at each site.

### 2. Minibuffer input window (FR6, NFR3)

Applies to `Minibuffer.View` in `internal/ui/minibuffer.go`. The input display width is the minibuffer width − prompt length − 2, with prompt length measured as today (unchanged, per NFR3).

- Precondition: the minibuffer is shown; width is any integer (zero and negative included); prompt and input are any strings; the cursor position is within [0, input rune count].
- Postcondition:
  - Never reads outside the input's rune range.
  - Returns a string with no line break.
  - When the input display width ≥ 1, the returned string is byte-identical to the current implementation's.
- When the input display width ≤ 0, the visible input window is not computed from the input (the current computation produces reversed or out-of-range bounds there). SPEC A6 does not specify what is shown in that case. The recommended behavior is an empty input portion, so only the prompt is rendered. Tests must not pin this content, only no panic and no line break.
- The single-line postcondition at widths 0–4 relies on the styled line's content wrap limit being ≤ 0 there, which the styling library treats as "no wrap". The no-line-break test is the guard. Do not change the line styling for input display widths ≥ 1 (NFR3).

### 3. Other narrow-width panic sources (FR2)

Planning found header line 1 / 2, entry formatting, background-output split heights, the output-area header and the status bar already clamped, so no other source is expected. If the new tests expose another source on these render paths:

- If it is inside this task's file set, fix it under the width-clamping convention.
- If it is outside this task's file set, report it as a plan deviation. Do not widen the file set.

### 4. Test fixtures (for the tests below)

- Panes: the existing pane test helper that builds a pane over a temporary directory with n regular files (`newFilesPane`, defined in the mouse hit-test test file; used, not modified). Use a normal height, for example 24, and a few files.
- Background-output split view: turn the pane's background-output mode on, and use an output buffer that already holds some lines. Use a non-empty command string so the output-area header truncation path is exercised.
- Minibuffer-shown pane view: a new minibuffer with prompt "/: ", width set to the pane width, and shown. Run each case once with empty input and once with non-empty input.
- Model-level test: construct the model the way the existing window-size tests in `internal/ui/model_basic_test.go` do, then deliver one window-size message of the given width and a normal height (for example 24).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1, NFR1): For pane widths 0, 1, 2, 3, 4 and 40, the third output row (the separator row) of `View`, `ViewWithBgOutput` and `ViewDimmedWithDiskSpace` contains exactly max(0, width − 2) "─" glyphs. At widths 0 and 1 it contains none.
- [ ] AC-2 (FR2, FR5): For each pane width 0, 1, 2, 3 and 4, each of these calls returns without panicking:
  - `View`
  - `ViewWithBgOutput` with focused false and with focused true, using a non-empty command and an output buffer holding lines
  - `ViewDimmedWithDiskSpace`
  - `ViewWithMinibuffer` with a shown minibuffer (prompt "/: ", width = pane width), once with empty input and once with non-empty input
- [ ] AC-3 (FR4): For pane widths 0 and 1, the output row count (ignoring the trailing line break) of each of the four views equals that view's row count for the same pane at width 40 and the same height. `ViewWithMinibuffer` is measured with the minibuffer shown.
- [ ] AC-4 (FR6, FR5): `Minibuffer.View` returns without panicking, and its output contains no line break, for the shown minibuffer in each of these cases:
  - Every combination of: width 0, 1, 2, 3, 4; prompt "/: " or "!: "; input "", "a" or "abc"; cursor at 0, at half the input rune count (rounded down), or at the input rune count.
  - The additional case: prompt "(reverse-i-search)'': ", width 24, input "a", cursor 1.
- [ ] AC-5 (FR3, FR5): For a model that has received a window-size message of width 0, 1, 2 or 3 at a normal height, `Model.View` returns without panicking in each of three states: (a) no minibuffer shown, (b) after `startSearch` with the incremental search mode, (c) after `startShellCommandMode`.
- [ ] AC-6 (FR5): Before the production fix, both of these fail:
  - The AC-2 tests at pane widths 0 and 1.
  - The AC-4 tests, including the case width 4, prompt "/: ", input "a", cursor 1.

  This red phase is observed and recorded in the task's test record.
- [ ] AC-7 (NFR1, NFR2, NFR3): The full test suite (workflow.yaml `test_command`) passes. This includes the existing width-40 row-alignment / hit-test tests and the existing `TestMinibufferView` and `TestMinibufferViewTruncation`.

## Test Notes

- All criteria are unit tests in package `internal/ui`:
  - AC-1, AC-2 and AC-3 go in `internal/ui/pane_render_test.go` (SPEC TS1, TS2 and the separator-count scenario TS-6 in VERIFICATION.md).
  - AC-4 goes in `internal/ui/minibuffer_test.go` (SPEC TS5).
  - AC-5 goes in `internal/ui/model_basic_test.go` (SPEC TS3).
  - AC-7 is the full suite (SPEC TS4).
- Write the tests first and run them against the unmodified production code to satisfy AC-6.
  - Expected pre-fix failures: the pane views at widths 0 and 1 (negative separator count), every `ViewWithMinibuffer` case whose input display width is ≤ 0, and the minibuffer cases with an input display width ≤ 0.
  - With empty input, the pre-fix minibuffer code is also expected to panic when the input display width is negative. SPEC marks this as not yet confirmed by running it; record the observed result.
- Use table-driven subtests named by width / view / prompt / input / cursor so a failure identifies its case.
- Separator counting (AC-1) counts "─" glyphs in the third row only. Styling escape sequences do not contain that glyph, so no escape stripping is required. In the background-output split view, the output-area header also contains "─" but is on a later row and is not counted.
- Row counting (AC-3) counts line breaks in the returned string; each view ends every row, including the last, with a line break.
- "Half the input rune count" is 0 for "" and "a", and 1 for "abc". Set the cursor by setting the input and then setting the cursor position.
- The model-level test depends on the working directory the model opens; follow the existing window-size tests in `internal/ui/model_basic_test.go`, which run the model in its default state.

## Out of Scope

- Dialog overlay rendering and dialog body rendering (SPEC A4).
- Choosing or testing what the minibuffer shows when its input display width is ≤ 0 (SPEC A6); only no panic and single-line output are required.
- Minibuffer wrapping behavior at widths above 4, and pane rendering at widths above 4 other than the width-40 comparison baseline.
- New E2E tests (SPEC A5).
