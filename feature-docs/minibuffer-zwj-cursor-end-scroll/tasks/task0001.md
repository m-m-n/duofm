# Task Plan: task0001 — ミニバッファの収まり判定を実際の表示幅にする

## Goal

ミニバッファの Minibuffer.View で、入力全体が残りの幅に収まるかどうかを、書記素単位で測った入力全体の実際の表示幅で判定する。
ZWJ 連結の絵文字のように結合で幅が縮む入力が実際に収まるときは、カーソル位置にかかわらず、先頭の code point を削らず、結合文字列を途中で切らずに表示する。

## Requirements

FR1, FR2, FR3, FR4, NFR1, NFR2

## Scope

### Files to Create

なし

### Files to Modify
- `internal/ui/minibuffer.go` — Minibuffer.View の、残りの幅が 1 以上の経路での入力全体の収まり判定を変更
- `internal/ui/minibuffer_test.go` — 回帰テストを追加（既存テストは変更しない）

## Design

### 用語

- 内容幅: ミニバッファの行に表示できる幅（m.width − 4）
- 残りの幅: 内容幅からプロンプトの表示幅を引いた値
- 実際の表示幅: 書記素クラスタ単位で測った表示幅。既存の縮小ループ（D2）が組み立てた行を測るときと同じ測り方（SPEC a5）
- rune ごとの幅の合計: rune を 1 つずつ測った幅の和。ZWJ 連結の絵文字では実際の表示幅より大きくなる（家族の絵文字は rune ごとの合計 8、実際の表示幅 2）

### 変更の対象

Minibuffer.View の、残りの幅が 1 以上の経路のうち、「入力全体とカーソルブロックが収まるので切り詰めずに表示する」分岐に入るかどうかの判定だけを変える。
現在はこの判定に rune ごとの幅の合計を使っているため、実際には収まる入力をスクロール経路に回し、先頭の code point を削っている。

### 表示範囲の決め方（変更後）

1. 入力全体の実際の表示幅 W を測る
2. カーソルが末尾にあり、W + 1（カーソルブロック 1 桁）が残りの幅以下なら、表示範囲を入力全体（開始位置 0、終了位置は入力の末尾）にし、カーソルブロックを末尾に置く（FR1, FR2）
3. カーソルが末尾以外にあり、W が残りの幅以下なら、表示範囲を入力全体にし、カーソル位置の rune を反転表示する（FR1, FR3）
4. 2・3 のどちらにも当たらないときは、既存のスクロール経路（カーソル末尾のスクロール、カーソル位置の文字が単独でも収まらない場合、先頭から収まる場合、カーソル位置の文字を右端に寄せるスクロール）をそのまま使う。これらの経路が rune ごとの幅で候補の範囲を決める点は変えない（SPEC a2）
5. 組み立てた行は、既存の縮小ループ（D2）で、実際の表示幅が内容幅以下になるまで縮める。この処理は変えずに残す（FR4）

### 事後条件

- 2 に当たるとき: 縮小ループに入る前の表示範囲は入力全体で、先頭の code point を削らない
- 3 に当たるとき: 縮小ループに入る前の表示範囲は入力全体。カーソルが書記素の途中の rune にあり、反転表示で結合が分かれて描画幅が増えたときは、縮小ループが 1 行の保証を優先して範囲を縮める（FR3 のただし書き、SPEC a4）
- m.width > 4 のとき、View の結果は改行を含まず、表示幅は m.width − 2 以下（FR4）
- 次のものは変えない（NFR1, SPEC a7）
    - 幅 0〜4 の経路と、プロンプトだけで内容幅を使い切る経路
    - カーソル位置の rune だけを反転表示する描画
    - HandleKey などの編集操作と、cursorPos が rune 単位であること

### テストで使う数値

- プロンプト `(search): ` の表示幅は 10
- 入力（家族の絵文字 U+1F468 U+200D U+1F469 U+200D U+1F467 U+200D U+1F466 + `ls`）は 9 rune。実際の表示幅は 4、rune ごとの幅の合計は 10
- m.width 19〜24 では残りの幅が 5〜10。実際の幅 + 1 = 5 は収まるが、rune ごとの合計 + 1 = 11 は収まらない
- m.width 18 では残りの幅が 4。カーソルが末尾なら、実際の幅 + 1 でも収まらない

## Acceptance Criteria (MANDATORY)

「表示上の文字列」は、View の結果から端末の装飾用エスケープシーケンスを除いた文字列を指す。

- [ ] AC-1（FR1, FR2 / SPEC AC1, AC5）: プロンプト `(search): `、入力が家族の絵文字 + `ls`、カーソルが末尾のとき、m.width 19〜24 の各幅（再現条件の 24 を含む）で、表示上の文字列に `(search): 👨‍👩‍👧‍👦ls` が続けて含まれる（先頭の U+1F468 が削られていない）
- [ ] AC-2（FR1, FR3 / SPEC AC2）: AC-1 と同じプロンプトと入力で、カーソルを `l`（rune 位置 7）または `s`（rune 位置 8）に置いたとき、m.width 19〜24 の各幅で、表示上の文字列に `(search): 👨‍👩‍👧‍👦ls` が続けて含まれる（家族の絵文字が途中で切れず、`s` も表示される）
- [ ] AC-3（FR4 / SPEC AC3）: AC-1 と同じプロンプトと入力で、m.width 18〜30 の各幅とカーソル位置 0〜9 のすべての組み合わせについて、View の結果が改行を含まず、表示幅が m.width − 2 以下である（書記素の途中の rune にカーソルがある組み合わせを含む）
- [ ] AC-4（FR1 / SPEC a2）: AC-1 と同じプロンプトと入力で、カーソルが末尾、m.width 18（実際の幅 + 1 でも収まらない）のとき、表示上の文字列に `ls` が含まれ、AC-3 と同じ 1 行の条件を満たす
- [ ] AC-5（NFR2 / SPEC AC4）: minibuffer_test.go の既存テストを変更せずにすべて通り、go test ./... もすべて通る
- [ ] AC-6（NFR1 / SPEC AC4）: 変更したプロダクトコードとテストのファイルは internal/ui/minibuffer.go と internal/ui/minibuffer_test.go だけで、minibuffer.go の変更は Minibuffer.View の表示計算と、それに関わるコメントに限られる

## Test Notes

- AC-1〜AC-4 は minibuffer_test.go の単体テストにする。E2E テストは追加しない（SPEC a6）。AC-1 と AC-2 は m.width × カーソル位置の表形式にする
- 既存テストの命名（TestMinibufferView_条件_期待）と、既存のヘルパー（assertBoundedSingleLine、mustNotPanic）に合わせる
- フィクスチャの前提（プロンプトの表示幅 10、入力の実際の表示幅 4、rune ごとの幅の合計 10）をテスト内で確かめ、崩れていたら即座に失敗させる。既存の TestMinibufferView_ScrolledInput_CursorCharacterVisible と同じ形にする。これで「rune ごとの合計では収まらないが、実際の幅では収まる」条件を実際に踏んでいることを保証する
- 表示上の文字列の比較は、実行環境の色の設定（装飾用エスケープシーケンスが出るかどうか）によらず成り立つ形にする
- 変更前のコードでは、AC-1 はどの幅でも失敗し、AC-2 は m.width 19〜23 で失敗する（m.width 24 は変更前でも通る）。テストを先に書き、失敗を確かめてから実装する
- 境界として次を必ず含める
    - m.width 19: 残りの幅 5 が、実際の幅 + 1 とちょうど同じ
    - m.width 24: 残りの幅 10 が、rune ごとの合計 + 1 よりちょうど 1 少ない
    - m.width 18: 実際の幅でも収まらず、スクロール経路に入る
- AC-5 と AC-6 はテストを書かず、テストの実行結果と差分のファイル一覧で判定する

## Out of Scope

- 実際の表示幅でも入力が収まらずスクロールが必要なときに、表示範囲の境界が書記素の途中になる挙動（SPEC a2）
- カーソル位置の rune だけを反転表示する描画と、書記素の途中にカーソルがあるとき結合が分かれて描画される挙動（SPEC a4）
- 幅 0〜4 の経路と、プロンプトの切り詰めの経路
- E2E テストの追加（SPEC a6）
- HandleKey などの編集操作と、cursorPos の単位
