# Task Plan: task0003 — Double-click detector

## Goal

Provide a small detector that decides whether a left press completes a
double-click on the same target within 500 ms. The time source is injectable,
so tests can reproduce presses inside and outside the window
deterministically.

## Requirements

FR6, NFR4

## Scope

### Files to Create
- `internal/ui/mouse_doubleclick.go` — `doubleClickWindow`, `clickKey`, the
  `doubleClickDetector` type, `newDoubleClickDetector`, and the detector
  methods `press` and `reset`
- `internal/ui/mouse_doubleclick_test.go` — unit tests for every criterion
  below

### Files to Modify
- (none)

## Design

Implement the Shared Components rows owned by this task, exactly as pinned in
IMPLEMENTATION.md (sequence semantics: D4).

The detector holds:

- an optional record of the previous press: its key and the time it was
  taken;
- the time source supplied at construction. When none is supplied, it uses
  the system clock.

`press(key)` flow:

1. Read the current time from the time source.
2. If a record exists, its key equals `key`, and the elapsed time since the
   record is at least 0 and at most `doubleClickWindow`, clear the record and
   return true.
3. Otherwise store (key, current time) as the record and return false.

`reset()` clears the record.

Key equality compares pane position, directory path and entry name. All
three must match.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (TS-13 timing): Two presses with the same key, 200 ms apart →
      the first returns false and the second returns true.
- [ ] AC-2 (TS-14 window): Same key, presses 600 ms apart → false. Exactly
      500 ms apart → true. 501 ms apart → false.
- [ ] AC-3 (TS-14, different target): Presses 100 ms apart whose keys differ
      only in entry name → false. The same holds when the keys differ only in
      pane, or only in directory.
- [ ] AC-4 (TS-14, triple press): Same key at 0, 100, 200 and 300 ms →
      false, true, false, true. The press after a success starts a new
      sequence.
- [ ] AC-5: A press, then `reset()`, then a press with the same key 100 ms
      later → false.
- [ ] AC-6 (D4): Key A at 0 ms, key B at 100 ms, key A at 200 ms → all three
      return false.
- [ ] AC-7 (NFR4): All criteria above run on an injected fake time source.
      - With no time source supplied, the system clock is used: two
        immediate presses with the same key → the second returns true.
      - A time source that goes backwards (negative elapsed time) → false.

## Test Notes

- Pure unit tests. The fake time source is a test-local adjustable clock
  whose current value each test advances explicitly.
- Test identifiers use the `dcTest` prefix. Test names start with
  `TestDoubleClickDetector`.

## Out of Scope

- Deciding which presses to report or when to reset (the caller decides).
- Performing the Enter action.
- Mouse event handling.
