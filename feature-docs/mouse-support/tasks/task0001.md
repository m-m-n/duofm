# Task Plan: task0001 — Mouse hit test

## Goal

Build the hit test, a pure function that maps a screen coordinate to "no
pane", "a pane's non-entry area", or "a pane's entry at index N". Also build
the clamped row→entry mapping used while dragging, plus read-only adapters
that feed both functions from the live Pane/Model layout. Both functions use
exactly the layout values the renderer uses.

## Requirements

FR1, FR3, FR5, FR7, NFR2, NFR3

## Scope

### Files to Create
- `internal/ui/mouse_hittest.go` — layout constants; `paneHitLayout`,
  `hitKind` (`hitNone` / `hitNonEntry` / `hitEntry`) and `mouseHit`;
  `hitTest`; `clampedEntryIndex`; the Pane adapter `hitLayout`; the Model
  adapters `mouseHitAt` and `mouseDragIndexAt`
- `internal/ui/mouse_hittest_test.go` — unit tests for every criterion below

### Files to Modify
- (none)

## Design

Implement the Shared Components rows owned by this task, and rules H1–H5,
exactly as pinned in IMPLEMENTATION.md. Layout values follow D2.

Layout constants, defined once in `mouse_hittest.go` as named constants:

- One title row (screen row 0) and one status row (screen row height − 1).
- Three pane header rows (screen rows 1–3), so the first entry row is 4.
- Pane width = screen width / 2 (integer division). The left pane covers
  [0, width/2) and the right pane covers [width/2, 2·(width/2)).

`hitTest` flow:

1. Apply H1. Out-of-screen or bar rows, and the leftover column of an odd
   width, give `hitNone`.
2. Pick the pane from x (H2).
3. A row below 4 gives `hitNonEntry` for that pane (H3).
4. Compute r = y − 4. If r < visible lines and scroll offset + r < entry
   count, return `hitEntry` with index scroll offset + r (H4). Otherwise
   return `hitNonEntry` (H5).

Rows H5 covers without special cases:

- **Blank rows below the last entry**: scroll offset + r ≥ entry count.
- **The `(No matches)` row**: a filter with no results displays zero
  entries.
- **Bg split separator and output rows**: r ≥ visible lines, because the
  visible lines already equal the bg split file-list height.
- **The pane's trailing row**: r ≥ visible lines.

`clampedEntryIndex`:

- Compute the unclamped index as scroll offset + (y − 4).
- Clamp it into the displayed range [scroll offset, last displayed index],
  where last displayed index = min(scroll offset + visible lines, entry
  count) − 1.
- Report "no index" when that range is empty.
- There is no x input: the pointer's column never influences the result
  (FR5).

Adapters:

- **Pane `hitLayout`**: reads the pane's scroll offset, `getVisibleLines()`
  and the number of displayed entries. It never re-derives heights on its
  own. While a directory is loading, the displayed entries are used, the
  same as keyboard cursor movement.
- **Model `mouseHitAt`**: combines the Model's width and height with both
  panes' `hitLayout()`. It returns `hitNone` when either pane is absent.
- **Model `mouseDragIndexAt`**: applies `clampedEntryIndex` to the named
  pane's `hitLayout()`. It reports "no index" when that pane is absent.

Purity (NFR2):

- `hitTest` and `clampedEntryIndex` read nothing except their arguments: no
  Model, no Pane, no package-level mutable state.
- They are testable without a terminal.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (TS-1): Width 80 and height 24. Both layouts have scroll offset 0
      and more entries than visible lines. (5, 4) → entry in the left pane,
      index 0. (39, 6) → left pane, index 2. (40, 4) → right pane, index 0.
- [ ] AC-2 (TS-2): The left layout has scroll offset 10 and V visible lines,
      with at least 10 + V entries. y = 4 → index 10. y = 4 + V − 1 → index
      10 + V − 1. y = 4 + V → `hitNonEntry` for the left pane.
- [ ] AC-3 (TS-3): Width 81, height 24, and a pane with 3 entries:
      - y = 0, y = 23 and x = 80 (on any pane row) → `hitNone`.
      - y = 1, 2 and 3 → `hitNonEntry`.
      - y = 8 → `hitNonEntry`.
      - A pane whose filter matches nothing (entry count 0), at row 4 →
        `hitNonEntry`.
      - Negative x or y, and y ≥ height → `hitNone`.
- [ ] AC-4 (TS-4): For a pane with bg output active:
      - `hitLayout()` reports visible lines equal to the bg split file-list
        height.
      - Rows inside the file list map to entries.
      - The separator row and every output row → `hitNonEntry`.
      - This holds both through `hitTest` with that layout and through the
        Model's `mouseHitAt`.
- [ ] AC-5 (FR5): `clampedEntryIndex`:
      - y above the first entry row (including 0 and negative values) → the
        scroll offset.
      - y below the last displayed row (including the status row and
        beyond) → the last displayed index.
      - In a short list, a blank row below the last entry → the last entry's
        index.
      - A row inside the list → scroll offset + (y − 4).
      - A layout that displays no entry → "no index".
- [ ] AC-6 (NFR2, NFR3): Pane `hitLayout()` follows live pane state.
      - Changing the scroll offset, the bg output state or the filter
        changes the reported values accordingly.
      - For the same state, the Model's `mouseHitAt` agrees with `hitTest`
        called on explicitly built layouts.
- [ ] AC-7: With an absent pane, `mouseHitAt` returns `hitNone` and
      `mouseDragIndexAt` reports "no index", without panicking.

## Test Notes

- Pure functions: table-driven tests with hand-built layouts (AC-1..AC-3,
  AC-5).
- Adapter tests:
  - Build panes over `t.TempDir()` directories filled with generated files.
  - A non-root temp directory lists a `..` entry at index 0; count it.
  - Pane height = screen height − 2 and pane width = screen width / 2, the
    same relation the Model uses.
- Use the Pane's existing bg-output toggle for AC-4 and its existing filter
  for the `(No matches)` case.
- Test identifiers use the `htTest` prefix. Test names start with
  `TestHitTest`.

## Out of Scope

- Handling mouse events, activating panes, moving cursors, changing marks.
- Changing any rendering code, or refactoring the renderer to share the
  constants.
- Anything in `internal/fs`.
