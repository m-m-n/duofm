# Task Plan: task0001 — Mouse support in the file panes (hit test, drag marking, double-click, controller)

## Goal

Make the file panes respond to the left mouse button:

- a click moves the cursor and activates the pane;
- a click on a non-entry area activates that pane only;
- a drag marks a range on top of the existing marks, without scrolling;
- a double-click performs exactly the existing Enter action.

All mouse input is ignored in modal states, and every non-left-button input
is ignored too. The hit test is a pure function driven by the renderer's
layout values.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, FR7, FR8, NFR1, NFR2, NFR3, NFR4, NFR5

## Design

All identifiers, contracts and rules H1–H5 are pinned in IMPLEMENTATION.md
(Shared Components). Implement them exactly. The layout values and the
evaluation moment follow D2, the gesture model D3, and the double-click
semantics D4.

### A. Hit test (`mouse_hittest.go`)

Layout constants, defined once in this file as named constants:

- One title row (screen row 0) and one status row (screen row height − 1).
- Three pane header rows (screen rows 1–3), so the first entry row is 4.
- Pane width = screen width / 2 (integer division).

`hitTest` flow:

1. Apply H1. Out-of-screen rows, bar rows, and the leftover column of an odd
   width give `hitNone`.
2. Pick the pane from x (H2).
3. A row below 4 gives `hitNonEntry` for that pane (H3).
4. Compute r = y − 4. If r < visible lines and scroll offset + r < entry
   count, return `hitEntry` (H4). Otherwise return `hitNonEntry` (H5).

`clampedEntryIndex`:

- Computes scroll offset + (y − 4) and clamps it into the displayed range.
- Reports "no index" when nothing is displayed.
- Has no x input.

Adapters:

- **Pane `hitLayout`**: reads the scroll offset, `getVisibleLines()` and the
  displayed entry count. It never re-derives heights on its own. While a
  directory is loading, the displayed entries are used, the same as keyboard
  cursor movement.
- **Model `mouseHitAt`**: combines the Model's width and height with both
  panes' layouts.
- **Model `mouseDragIndexAt`**: uses the named pane's layout.
- Both Model adapters are defensive when a pane is absent.

`hitTest` and `clampedEntryIndex` read nothing except their arguments, so
they can be tested without a terminal (NFR2).

### B. Pane drag marking (`pane_drag.go`)

`snapshotMarks` returns an independent copy of the pane's mark set.

`applyDragMarks(anchor, target, baseline)`:

1. Validate the indices. If either is out of range, return false and change
   nothing.
2. Start the new set as a copy of the baseline.
3. Add the name of every displayed entry between min(anchor, target) and
   max(anchor, target) inclusive, except `..`.
4. Replace the pane's mark set with the new set.
5. Set the cursor to the target. Do not touch the scroll offset or call the
   scroll adjustment.
6. Return true.

Consequences:

- Shrinking the range removes only names this drag added.
- Baseline names stay marked, including names hidden by a filter.
- The header's mark count follows automatically through the existing mark
  statistics.

### C. Double-click detector (`mouse_doubleclick.go`)

The detector holds an optional record (key, time) and the time source it was
given. With no time source, it uses the system clock.

`press(key)`:

1. Read the current time.
2. If a record exists, its key equals `key`, and 0 ≤ elapsed ≤ 500 ms, clear
   the record and return true.
3. Otherwise store (key, now) as the record and return false.

`reset()` clears the record.

### D. Mouse controller (`model_update_mouse.go`, `model.go`, `model_update.go`)

State held in the Model:

- **Drag session**: armed flag, active flag, session pane, anchor index,
  baseline mark set.
- **Detector reference**: the Model constructor creates it with the system
  clock. When a Model value was built without the constructor (as several
  existing tests do), the controller creates one on first use.
- The state persists across update calls through the returned Model.

`model_update.go` hands mouse events, and only mouse events, to
`handleMouse`.

`handleMouse(event)`, in order:

1. Either pane is absent (before the first window-size message) → ignore.
2. Modal state → disarm any session and ignore the event. Each of the
   following counts as modal; every check is nil-safe:
   - a dialog is present;
   - the sort dialog is present and active;
   - incremental search is active;
   - shell command mode is on;
   - the bg output area has focus.
3. Wheel events, and right- or middle-button events of any action → ignore.
   An armed session is left as it is.
4. Left press → press handling.
5. Motion with the left button held → drag update if a session is armed,
   otherwise ignore.
6. Release not attributed to the right or middle button → drag update with
   the release row if a session is armed, then end the session. With no
   session, ignore.
7. Anything else → ignore.

Modifier keys never change handling.

Press handling:

1. Evaluate `mouseHitAt(x, y)` before any change.
2. Discard any existing session.
3. Act on the hit kind:
   - **`hitNone`**: reset the detector.
   - **`hitNonEntry`**: reset the detector. If the hit pane is inactive,
     activate it through the existing pane-switch routine (the one the
     keyboard uses). Cursor and marks stay untouched.
   - **`hitEntry`**:
     1. Activate the pane if it is inactive.
     2. Set its cursor to the hit index.
     3. If activation shrank the pane's visible lines (the bg split appears
        on the bg command's pane) and the cursor fell outside them, apply
        the existing ensure-visible adjustment.
     4. Build the key (pane, pane directory, entry name).
     5. If the detector's `press` returns true, return the result of the
        existing Enter action (the same code path as the Enter key) and arm
        no session.
     6. Otherwise arm a session with anchor = hit index and
        baseline = `snapshotMarks()`.

Drag update(y):

1. Get the target from `mouseDragIndexAt(session pane, y)`. If there is no
   index, do nothing.
2. If the session is not active and the target equals the anchor, do
   nothing: it is still a click.
3. Otherwise:
   1. Mark the session active. On this first activation, reset the detector.
   2. Call `applyDragMarks(anchor, target, baseline)` on the session pane.

The other pane is never touched during a drag, and the pointer column is
never read.

In bg split with the file list focused:

- File-list rows behave normally.
- Separator and output rows are non-entry. The pane is already active, so a
  click there changes nothing.
- A drag pointer over those rows clamps to the last visible file entry.

`cmd/duofm/main.go` is not modified (NFR5).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1, NFR3; TS-1, TS-2): `hitTest` at width 80 and height 24,
      with more entries than visible lines:
      - scroll offset 0: (5,4) → left pane, index 0; (39,6) → left pane,
        index 2; (40,4) → right pane, index 0;
      - left scroll offset 10 with V visible lines: y = 4 → index 10;
        y = 4 + V − 1 → index 10 + V − 1; y = 4 + V → non-entry.
- [ ] AC-2 (FR1, FR3, FR7, NFR2, NFR3; TS-3, TS-4):
      - Width 81, height 24, a pane with 3 entries:
        - y = 0, y = 23, x = 80, negative coordinates and y ≥ height → no
          pane;
        - header rows 1–3 and the blank row y = 8 → non-entry;
        - a filter with no matches (entry count 0) → non-entry at row 4.
      - Bg split: for a pane with bg output active, Pane `hitLayout` reports
        visible lines equal to the bg split file-list height. File-list rows
        map to entries; the separator and output rows are non-entry. This
        holds through `hitTest` and through the Model's `mouseHitAt`.
      - Live adapters: `hitLayout` follows changes to the scroll offset, the
        bg state and the filter.
- [ ] AC-3 (FR5): `clampedEntryIndex`:
      - y above the first entry row (including 0 and negative values) → the
        scroll offset;
      - y below the last displayed row (including the status row and beyond)
        → the last displayed index;
      - a blank row in a short list → the last entry;
      - a row inside the list → scroll offset + (y − 4);
      - nothing displayed → "no index".

      Also: the Model adapters with an absent pane return "no pane" / "no
      index" without panicking.
- [ ] AC-4 (FR4, FR5; TS-8..TS-10 at pane level): `applyDragMarks`:
      - baseline {7}, anchor 1, target 4 → marks {1,2,3,4,7}, cursor 4;

        offset with the target on the window's edge;

        both directions;

        change.
- [ ] AC-5 (FR6, NFR4; TS-13, TS-14 timing), on a fake time source:

      - key A, B, A at 0/100/200 ms → all false;

      - with no time source, two immediate presses → the second is true.
- [ ] AC-6 (NFR1, NFR5, wiring):

## Test Notes

- Component tests (AC-1..AC-5) are table-driven and pure where possible.
- Pane-based tests:
  - Build panes over `t.TempDir()` directories with generated files and
    directories.
  - A non-root temp directory lists `..` at index 0.
  - Keep pane width = screen width / 2 and pane height = screen height − 2,
    the relation the window-size handling uses (for example 80×24 with
    40×22 panes).
- Model-level tests (AC-6..AC-10):
  - Construct mouse events directly as the framework's mouse message values
    with 0-based coordinates. Entry index i of a pane with scroll offset s
    is on screen row 4 + i − s.
  - Inject the fake clock by replacing the Model's detector with one built
    by `newDoubleClickDetector` on a test clock.
  - Set modal states and the bg split state directly on the Model and the
    Pane.
- For every "unchanged" assertion, compare before/after values of the active
  pane, both cursors, both mark sets, both scroll offsets and the modal
  flags, and check that the returned command is nil.
