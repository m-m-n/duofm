# Task Plan: task0002 — E2E mouse scenarios and E2E runner entry point

## Goal

Add the tmux-driven E2E scenarios for click, drag and double-click (TS-20,
TS-21, TS-22) as a new `mouse` test category that the standard E2E run
includes. Also make the E2E image's default command start the existing test
runner, so the project's E2E command actually runs the suite.

## Requirements

FR2, FR4, FR6, NFR1

## Scope

### Files to Create
- `test/e2e/scripts/tests/mouse_tests.sh` — the three mouse scenarios and their shared mouse-sequence sending helper, runnable standalone like other category files

### Files to Modify
- `test/e2e/scripts/run_all_tests.sh` — register the mouse category, list it in the header comment, run the three mouse tests in a Mouse Tests section of the full run
- `test/e2e/Dockerfile` — change only the default command, from the missing run_tests.sh to the existing run_all_tests.sh runner

## Design

This task depends on the mouse behavior only at runtime, through the
observable contract in IMPLEMENTATION.md D5. Double-click timing follows D4.
No Go code is part of this task.

E2E geometry:

- `start_duofm` runs duofm in /testdata with a 120×40 tmux window by default.
- With 1-based terminal coordinates:
  - row 1 is the title bar;
  - rows 2–4 are the pane headers;
  - entry index i of the left pane (scroll offset 0) is on row 5 + i;
  - the left pane spans columns 1–60.
- /testdata lists `..` at index 0.

Mouse input injection:

- Send SGR-encoded mouse sequences to the session as literal text, using
  tmux's literal send mode. All coordinates are 1-based column;row.
  - Left press: ESC [ < 0 ; col ; row M
  - Motion with the left button held: ESC [ < 32 ; col ; row M
  - Left release: ESC [ < 0 ; col ; row m
- Put this helper inside `mouse_tests.sh`. Keep `helpers.sh` unchanged.
- Allow the same short settle delays after sending that the existing tests
  use.

Target rows:

- Where a scenario needs a specific entry (dir2, or the drag endpoints), find
  its row by reading the captured screen: take the line that contains the
  entry name.
- Do not hard-code the sort order. The expected mark count follows from the
  entries actually between the two rows, excluding `..`.

Scenarios:

1. `test_mouse_click_moves_cursor` (TS-20): press and release on the third
   entry row → `assert_cursor_position` reports 3.
2. `test_mouse_drag_marks_range` (TS-21):
   - Press on entry row A.
   - Send one or more motion sequences to entry row B.
   - Release on B.
   - The header shows "Marked N/", where N is the number of entries from A
     to B inclusive, excluding `..`.
3. `test_mouse_double_click_enters_directory` (TS-22):
   - Send two press/release pairs on dir2's row in a single send, well under
     500 ms apart.
   - `assert_contains` finds `another.txt`, which means duofm entered dir2.

Each test starts and stops its own duofm session, like the existing tests.

These scenarios are conditional per the SPEC. SGR injection through tmux is
unverified in the E2E container. The tests still assert normally; they are
never silently skipped. Their pass or failure is judged in the integrated
verification.

Default command:

- The E2E Dockerfile currently names `/e2e/scripts/run_tests.sh`, which does
  not exist in the repository, so the image's default command cannot start.
- Point it at `/e2e/scripts/run_all_tests.sh`. No other Dockerfile line
  changes.

Run-level behavior:

- The full run keeps every existing test and adds the mouse section.
- `run_all_tests.sh mouse` runs only the three mouse tests.
- `--list` shows the new category.

      `make test-e2e-build` succeeds.

## Test Notes

- AC-4 and AC-5 are static checks. AC-6 runs the workflow's E2E command
  (`make test-e2e-build && make test-e2e`).
- Read pass/fail per test from the runner's ✓/✗ lines. In this worktree the
  mouse lines are expected to fail and are not a criterion here.
- If the E2E environment cannot run at all (no container runtime), report
  that as a plan deviation instead of weakening AC-6.

## Out of Scope

- Changing the E2E base image, the Makefile, `helpers.sh`, or any existing
  test.
- Any Go source change.
- Automatic fallback logic that turns mouse-test failures into passes.
