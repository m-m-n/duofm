# Task Plan: task0002 — Pane drag-range marking

## Goal

Provide the Pane operations a drag uses. One captures the marks present when
the drag starts. The other re-computes the pane's marks as "those marks plus
every entry between the drag start row and the current row", moving the
cursor to the current row without ever scrolling.

## Requirements

FR4, FR5

## Scope

### Files to Create
- `internal/ui/pane_drag.go` — Pane methods `snapshotMarks` and
  `applyDragMarks`
- `internal/ui/pane_drag_test.go` — unit tests for every criterion below

### Files to Modify
- (none)

## Design

Implement the Shared Components rows owned by this task, exactly as pinned in
IMPLEMENTATION.md (drag semantics: D3).

`snapshotMarks`:

- Returns an independent copy of the pane's mark set, in the same name→marked
  representation the pane uses internally.
- Mutating the copy never affects the pane, and vice versa.

`applyDragMarks(anchor, target, baseline)` flow:

1. Validate: anchor and target must both be in [0, displayed entry count).
   If either is not, return false and change nothing (this includes an empty
   entry list).
2. Start the new mark set as a copy of `baseline`.
3. For every displayed entry with index between min(anchor, target) and
   max(anchor, target) inclusive, add its name, except the parent entry `..`.
4. Replace the pane's mark set with the new set.
5. Set the cursor to `target`. Do not call the scroll adjustment and do not
   touch the scroll offset.
6. Return true.

Consequences callers rely on:

- The operation is idempotent: the same arguments always give the same
  result.
- Shrinking the range removes only drag-added names; baseline names always
  stay.
- Baseline names that are not currently displayed (for example, hidden by a
  filter) stay marked.
- The header's mark count reflects the result through the existing mark
  statistics, with no extra work.
- The cursor may land on `..` when the target is the `..` row; only the mark
  excludes it.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (TS-8): The baseline contains the entry at index 7. Anchor 1 and
      target 4 → exactly the names at indices 1, 2, 3, 4 and 7 are marked,
      and the cursor is 4.
- [ ] AC-2 (TS-9, shrink): The baseline contains index 2. Apply (1, 5), then
      (1, 2) with the same baseline → indices 1 and 2 are marked and 3, 4
      and 5 are not; index 2 stays marked.
- [ ] AC-3 (TS-9, upward): Anchor 5 and target 3 → indices 3, 4 and 5 are
      marked, and the cursor is 3.
- [ ] AC-4 (TS-10): Entry 0 is `..`. Anchor 0 and target 3 → indices 1, 2
      and 3 are marked and `..` is not; the cursor is 3. Anchor 2 and target
      0 → the cursor is 0 and `..` is still not marked.
- [ ] AC-5 (FR5): The scroll offset is identical before and after every call.
      This includes a pane with a non-zero scroll offset whose target is the
      first or the last displayed row.
- [ ] AC-6: `applyDragMarks` leaves `baseline` unchanged. `snapshotMarks`
      returns a copy that is independent of the pane in both directions.
      Baseline names absent from the displayed entries remain marked after a
      call.
- [ ] AC-7: Anchor or target negative, ≥ the entry count, or used on an empty
      entry list → returns false; marks, cursor and scroll offset are
      unchanged. Valid indices → returns true.

## Test Notes

- Build panes over `t.TempDir()` directories with generated files.
  - A non-root temp directory lists `..` at index 0; include it in the index
    arithmetic.
  - Use enough files to give indices up to at least 8.
- For AC-5, set a pane height small enough, and a scroll offset, so that the
  displayed window does not start at 0.
- Use the existing filter to produce displayed-subset cases for AC-6.
- Test identifiers use the `dragTest` prefix. Test names start with
  `TestPaneDragMarks`.
