# Task Plan: task0004 — Mouse controller (event routing, click, drag, double-click)

## Goal

Route mouse events into the Model and turn them into the specified behavior:

- Ignore everything in modal states and every non-left-button input.
- A click on an entry activates its pane and moves the cursor there.
- A click on a non-entry area activates that pane only.
- A drag marks a range on top of the existing marks.
- A double-click performs exactly the existing Enter action.

This task owns the integration wiring of the shared components.

## Design

Components are used strictly through the Shared Components contracts in
IMPLEMENTATION.md. The gesture model is D3, the double-click semantics D4, the
layout and evaluation moment D2, and the stand-in rule D1.

State held in the Model:

- **Drag session**: armed flag, active flag, session pane, anchor index,
  baseline mark set.
- **Detector reference**: created by the constructor.
- When a Model value was built without the constructor (as several existing
  tests do), the controller creates a system-clock detector on first use.
- The state must persist across update calls through the returned Model.

`handleMouse(event)`, in order:

1. Either pane is absent (before the first window-size message) → ignore.
2. Modal state → disarm any session and ignore the event. Each of the
   following counts as modal; every check is nil-safe:
   - a dialog is present;
   - the sort dialog is present and active;
   - incremental search is active;
   - shell command mode is on;
   - the bg output area has focus.
3. Wheel events, and right- or middle-button events of any action → ignore.
   An armed session is left as it is.
4. Left press → press handling (below).
5. Motion with the left button held → drag update if a session is armed,
   otherwise ignore.
6. Release not attributed to the right or middle button → drag update with
   the release row if a session is armed, then end the session. With no
   session, ignore.
7. Anything else → ignore.

Modifier keys never change handling.

Press handling:

1. Evaluate `mouseHitAt(x, y)` against the current state, before any change
   (D2).
2. Discard any existing session.
3. Act on the hit kind:
   - **`hitNone`**: reset the detector. Nothing else.
   - **`hitNonEntry`**: reset the detector. If the hit pane is not active,
     activate it through the existing pane-switch routine (the same one the
     keyboard uses). Cursor and marks stay untouched.
   - **`hitEntry`**:
     1. Activate the pane if it is inactive, as above.
     2. Set that pane's cursor to the hit index.
     3. If activation shrank the pane's visible lines (the bg split appears
        when the bg command's pane becomes active) and the cursor fell
        outside them, apply the existing ensure-visible adjustment.
     4. Build the key (pane, pane directory, name of the entry at the index).
     5. If the detector's `press` returns true, return the result of the
        existing Enter action, the same code path as the Enter key, and arm
        no session.
     6. Otherwise arm a session: pane = hit pane, anchor = hit index,
        baseline = that pane's `snapshotMarks()`, not active.

Drag update(y):

1. Get the target from `mouseDragIndexAt(session pane, y)`. If there is no
   index, do nothing.
2. If the session is not active and the target equals the anchor, do
   nothing: it is still a click.
3. Otherwise:
   1. Mark the session active. On this first activation, reset the detector.
   2. Call the session pane's `applyDragMarks(anchor, target, baseline)`.

During a drag, the other pane is never touched and the pointer column is
never read. Scroll offsets never change during a drag; only the marking
operation moves the cursor.

In bg split with the file list focused:

- File-list rows behave as described above.
- Separator and output rows are non-entry. The pane is necessarily already
  active, so a click there changes nothing.
- A drag pointer over those rows clamps to the last visible file entry.

`cmd/duofm/main.go` is not modified: the existing cell-motion mouse reporting
option stays the only mouse mode (NFR5).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (wiring, NFR1, NFR5):
      - A left press on an entry row, delivered through the Model's normal
        update entry point, moves that pane's cursor.
      - A mouse event arriving before the panes exist returns no command
        and does not panic.
      - The constructor initializes the detector.
      - Every pre-existing unit test passes unchanged.
      - `cmd/duofm/main.go` has no diff.
- [ ] AC-2 (FR7, TS-16): Run the gesture "left press on an entry row, motion
      to another entry row, release" in each of these states:
      - an error dialog is open;
      - the sort dialog is active;
      - incremental search is active;
      - shell command mode is on;
      - the bg output area has focus.

      Expected in every state:
      - Active pane, both cursors, both mark sets and the modal state are
        unchanged.
      - Every returned command is nil.

      Also: a session armed in a normal state, followed by a modal state
      during which motion arrives, is disarmed. After the modal state ends,
      further motion marks nothing.
- [ ] AC-3 (FR8, TS-18): Wheel up, wheel down, a right-button press and a
      middle-button press, each on an entry row → cursor, marks, active pane
      and scroll offsets are unchanged, and the commands are nil.
- [ ] AC-4 (FR2, TS-5, TS-6, TS-12):
      - TS-5: The left pane is active, with 2 marks and the cursor at 0. A
        press and release on index 3 → cursor 3, the same 2 marks, the
        active pane unchanged.
      - TS-6: The left pane is active. A click on the right pane's index 2 →
        the right pane is active with cursor 2; the left pane's cursor and
        marks are unchanged.
      - TS-12: With no marks, a press and release on index 2 without moving
        → cursor 2, no marks.
      - Clicking `..` moves the cursor to `..`.
- [ ] AC-5 (FR3, FR7, TS-7, TS-17):
      - TS-7: The left pane is active and the right pane's cursor is 1.
        Clicks on the right pane's header row, then on its blank row below
        the last entry → the right pane is active, its cursor stays 1, and
        its marks are unchanged. Clicks on the title bar, the status bar and
        the odd-width leftover column change nothing.
      - TS-17: A bg command runs on the active pane and the file list has
        focus. A click on a file-list row moves the cursor. A click on the
        separator row or on an output row changes nothing.
- [ ] AC-6 (FR4, FR5, TS-8..TS-11, driven through mouse events):
      - TS-8: Index 7 is marked and the cursor is 0. A press at 1, motion to
        4 and release at 4 → 1..4 and 7 are marked, and the cursor is 4.
      - TS-9: Index 2 is marked. A press at 1, motion to 5 and back to 2,
        release at 2 → 1 and 2 are marked, 3..5 are not. Separately, a press
        at 5 and motion up to 3 → 3..5 are marked.
      - TS-10: A press on `..`, a drag to 3 and a release → 1..3 are marked,
        `..` is not.
      - TS-11: Scroll offset 5. The pointer moves above the first entry row,
        onto the title bar, below the last visible row, onto the status bar,
        into the other pane's columns, and onto a blank row in a short
        directory → the range stops at the start pane's first or last
        visible entry. The start pane's scroll offset stays 5. The other
        pane's cursor, marks and scroll offset are unchanged.
      - A drag started on an inactive pane activates that pane first.
- [ ] AC-7 (FR6, NFR4, TS-13..TS-15, on an injected fake clock):
      - TS-13: Two presses 200 ms apart:
        - on a directory → that pane starts loading that directory and a
          non-nil command is returned;
        - on `..` → the pane starts loading its parent directory, the name
          of the directory being left is remembered for cursor placement,
          and a non-nil command is returned;
        - on a readable regular file under the default Enter behavior → a
          non-nil command is returned and the pane directory is unchanged.
      - TS-14:
        - 600 ms apart → no Enter effect.
        - Two different entries 100 ms apart → no Enter effect.
        - Three presses within 500 ms → exactly one Enter effect.
      - TS-15: The left pane is active. A double-click on a directory in the
        right pane → the right pane is active, its cursor is on that entry,
        and it starts loading that directory.
      - A press on the same entry within 500 ms after a drag became active
        does not trigger Enter.

## Test Notes

- Build Models over `t.TempDir()` trees with generated files and
  directories.
  - Set the Model width and height, and keep pane width = width / 2 and
    pane height = height − 2, the same relation the window-size handling
    uses. For example: 80×24, panes 40×22.
  - A non-root temp directory lists `..` at index 0.
- Construct mouse events directly as the framework's mouse message values
  with 0-based coordinates. Entry index i of a pane with scroll offset s is
  on screen row 4 + i − s.
- Inject the fake clock by replacing the Model's detector with one built by
  `newDoubleClickDetector` on a test clock.
- Modal states: set the corresponding Model state directly.
  - An error dialog, the sort dialog, active incremental search, shell
    command mode, bg output focus.
  - For TS-17, mark the active pane's bg output as displayed (bg split) with
    file-list focus.
- For every "unchanged" assertion, compare before/after values of the active
  pane, both cursors, both mark sets, both scroll offsets and the modal
  flags, and check that the returned command is nil.
- Test identifiers use the `mouseTest` prefix. Test names start with
  `TestHandleMouse`.
- When this worktree lacks a producer file and a stand-in is written (D1),
  do not create that producer's test file. This task's tests exercise the
  components only through Model behavior.
