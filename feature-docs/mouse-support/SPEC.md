# Feature: マウス操作サポート (mouse-support)

## Overview

duofm のファイル一覧を左ボタンのマウス操作で扱えるようにする。クリックでカーソルを移動し、ドラッグで範囲をマークし、ダブルクリックで Enter キーと同じ動作を行う。要件は `feature-docs/mouse-support/REQUIREMENTS.md` に記載する。

## Objectives

- ユーザーがファイル一覧をマウスで操作できるようにする（UX の向上）

## User Stories

### US1: クリックでファイルを選択する
duofm のユーザーとして、クリックでファイルを選択したい。

**Acceptance Criteria:**
- [ ] AC1: ファイルをクリックするとカーソルがそのファイルへ移動する（マークは変わらない）。非アクティブなペインのファイルをクリックすると、そのペインがアクティブになり、カーソルがそのファイルへ移動する

### US2: ドラッグで複数のファイルを選択する
duofm のユーザーとして、ドラッグで複数のファイルを選択したい。

**Acceptance Criteria:**
- [ ] AC2: エントリをまたいでドラッグすると、開始行から離した行までのすべてのエントリ（`..` を除く）が既存のマークに追加してマークされ、カーソルは離した行にある。範囲は可視行内に制限され、一覧はスクロールしない

### US3: ダブルクリックで Enter キーと同じ動作をする
duofm のユーザーとして、ダブルクリックで Enter キーと同じ動作をさせたい。

**Acceptance Criteria:**
- [ ] AC3: エントリを 500 ms 以内にダブルクリックすると、そのエントリで Enter キーを押したのと同じ動作になる

### US4: エントリ以外の場所のクリックでペインをアクティブにする
duofm のユーザーとして、ペインのエントリ以外の場所をクリックしてそのペインをアクティブにしたい。

**Acceptance Criteria:**
- [ ] AC4: ペインの空行やヘッダをクリックすると、そのペインがアクティブになるだけである。タイトルバーとステータスバーのクリックでは何も起きない

## Technical Requirements

### Functional Requirements

- **FR1:** ヒットテスト。マウスイベントの画面座標（0 始まり）を、描画と同じレイアウト値で対象に対応付ける。
    - 行 0 はタイトルバー、最終行（height-1）はステータスバー。その間の行がペインに属する
    - ペイン幅は width/2。X が [0, width/2) なら左ペイン、[width/2, 2*(width/2)) なら右ペイン。幅が奇数のときに残る右端の列はどちらのペインにも属さない
    - ペイン内の最初の 3 行（パスヘッダ、情報ヘッダ、枠線）は非エントリ行。エントリ行は画面の行 4 から始まる
    - エントリの index は scrollOffset + (Y - 4)。(Y - 4) がペインの可視行数（getVisibleLines。bg 出力の分割表示を反映済み）未満で、かつ index がエントリ数未満のときだけ有効
    - それ以外のペイン内の行（最後のエントリより下の空行、`(No matches)` の行、bg 出力の区切り行と出力行）は、そのペインの非エントリ領域
- **FR2:** クリックでファイルを選択。エントリ行の左クリックで、そのペインのカーソルをクリックしたエントリへ移動する。
    - 既存のマークは変えない
    - クリックしたペインが非アクティブなら、そのペインをアクティブにし、同じ操作でカーソルをクリックしたエントリへ移動する
    - `..` をクリックするとカーソルは `..` へ移動する
- **FR3:** エントリ以外の場所のクリック。ペイン内の非エントリ領域の左クリックで、そのペインをアクティブにする。
    - そのペインのカーソルとマークは変えない
    - タイトルバー、ステータスバー、両ペインの外の列のクリックは無視する
- **FR4:** ドラッグで複数ファイルを選択。エントリ行で左ボタンを押し、ポインタを別のエントリ行へ動かすと、そのペイン（開始ペイン）でドラッグが始まる。
    - 開始ペインが非アクティブなら、先にアクティブにする
    - ドラッグ中は、ドラッグ開始行から現在のポインタ行までのエントリを、ドラッグ開始時点のマークに追加してマークする
    - 範囲はポインタに合わせてその場で変わる。範囲を縮めると、このドラッグで追加したマークは外れるが、ドラッグ開始時点のマークは外れない
    - `..` はマークしない
    - カーソルはポインタ行に追従し、離した行で止まる
    - 同じ行で押して離し、別の行へ動かさなかった場合はクリック（FR2）であり、ドラッグではない
- **FR5:** ドラッグ範囲の制限。
    - ドラッグ中はポインタの行だけを使う。ポインタがもう一方のペイン、タイトルバー、ステータスバーの上にあっても、範囲は開始ペインの中に留まる
    - ポインタが最初の可視エントリ行より上、または最後の可視エントリ行より下（エントリの少ないディレクトリで最後のエントリより下の空行を含む）にあるとき、範囲は最初／最後の可視エントリで止まる
    - ドラッグ中に一覧はスクロールしない（scrollOffset は変わらない）
- **FR6:** ダブルクリックで Enter と同じ動作。同じエントリ（同じペイン・同じディレクトリ・同じエントリ名）に対する左ボタンの押下が、そのエントリへの前回の押下から 500 ms 以内に来たとき、そのエントリに対して Enter キーと同じ動作を行う。
    - ファイルは EnterBehavior に従って開く。ディレクトリはその中に入る。`..` は親ディレクトリへ移動する
    - 1 回目の押下はクリック（FR2）として動作する。非アクティブなペインのアクティブ化も含む
    - ダブルクリックが成立した後の次の押下は、新しいクリック列の始まりになる（素早い 3 回目の押下で Enter は再度実行されない）
- **FR7:** モーダル状態ではマウスを無視。次の状態の間は、すべてのマウス入力を無視する。
    - ダイアログが開いている（`m.dialog != nil`）
    - ソートダイアログがアクティブ
    - ミニバッファがアクティブ（検索モード、シェルコマンドモード）
    - bg 出力領域にフォーカスがある
    - bg 出力の分割表示でファイル一覧にフォーカスがある場合、ファイル一覧部分のクリックとドラッグは FR1〜FR6 のとおり動作し、区切り行・出力部分のクリックは無視する
- **FR8:** 対象外のマウス入力。
    - ホイールイベントは無視する（ホイールスクロールは対象外）
    - 左ボタンだけを扱う。右ボタン、中ボタンのイベントは無視する

### Non-Functional Requirements

- **NFR1 - キーボード操作の非退行:** 既存のキーボード操作の挙動は変わらず、既存のユニットテストと E2E テストはすべて変更なしで通る。
- **NFR2 - ui パッケージへの配置:** マウス処理は `internal/ui` に置き、`internal/fs` のロジックと分ける。ヒットテストはレイアウト状態（width、height、ペイン幅、scrollOffset、可視行数、エントリ数）だけで決まる純粋な関数とし、端末なしでユニットテストできるようにする。
- **NFR3 - レイアウト値の一元化:** ヒットテストは描画と同じレイアウト値（width/2 のペイン幅、タイトル行、3 行のペインヘッダ、bgSplitHeights を含む getVisibleLines）を使い、行とエントリの対応が描画とずれないようにする。
- **NFR4 - ダブルクリック判定の時刻のテスト容易性:** 500 ms のダブルクリック判定に使う時刻の取得元を差し替え可能にし、ユニットテストで判定時間の内外の押下を決定的に再現できるようにする。
- **NFR5 - 既存のマウスモード:** `cmd/duofm/main.go` の既存のプログラムオプション `tea.WithMouseCellMotion()` をマウス報告モードとして使い続ける。端末モードを追加しない。

## Implementation Approach

### Architecture

**System Architecture:**
```
┌──────────────────────────────────────────────┐
│ cmd/duofm/main.go                            │
│   tea.WithMouseCellMotion() (NFR5)           │
├──────────────────────────────────────────────┤
│ Bubble Tea                                   │
│   マウスイベント (MouseMsg)                  │
├──────────────────────────────────────────────┤
│ internal/ui マウス処理 (NFR2)                │
│   モーダル状態の判定 (FR7)                   │
│   対象外入力の除外 (FR8)                     │
│   ヒットテスト: 純粋な関数 (FR1, NFR3)       │
│   クリック / ドラッグ / ダブルクリック       │
│   (FR2〜FR6)                                 │
├──────────────────────────────────────────────┤
│ 既存のペイン状態                             │
│   カーソル / マーク / アクティブペイン       │
│   Enter キーの処理 (FR6)                     │
└──────────────────────────────────────────────┘
```

**Component Diagram:**
```
ヒットテスト (FR1)
  入力: X, Y, width, height, ペイン幅, scrollOffset, 可視行数, エントリ数
  出力: どのペインにも属さない / ペインの非エントリ領域 / ペインのエントリ (index)

  | 領域               | 条件                                              | 結果                    |
  |--------------------|---------------------------------------------------|-------------------------|
  | タイトルバー       | Y == 0                                            | どのペインにも属さない  |
  | ステータスバー     | Y == height-1                                     | どのペインにも属さない  |
  | 右端の余りの列     | X >= 2*(width/2)                                  | どのペインにも属さない  |
  | 左ペイン           | 0 <= X < width/2                                  | 左ペイン                |
  | 右ペイン           | width/2 <= X < 2*(width/2)                        | 右ペイン                |
  | ペインヘッダ       | Y = 1..3                                          | 非エントリ領域          |
  | エントリ行         | Y >= 4, (Y-4) < 可視行数,                         | エントリ                |
  |                    | scrollOffset+(Y-4) < エントリ数                   | index = scrollOffset+(Y-4) |
  | その他のペイン内行 | 空行, (No matches) 行, bg 出力の区切り・出力行    | 非エントリ領域          |

ドラッグ (FR4, FR5) が使う情報
  開始ペイン, ドラッグ開始行, ドラッグ開始時点のマーク

ダブルクリック判定 (FR6, NFR4) が使う情報
  前回の押下のペイン・ディレクトリ・エントリ名・時刻 (差し替え可能な時刻の取得元)
```

### Data Flow

```
端末 → Bubble Tea (tea.WithMouseCellMotion) → マウスイベント → internal/ui マウス処理
  → モーダル状態なら無視 (FR7)
  → ホイール / 右ボタン / 中ボタンなら無視 (FR8)
  → ヒットテスト (FR1)
  → クリック (FR2, FR3) / ドラッグ (FR4, FR5) / ダブルクリック (FR6)
  → ペインのカーソル・マーク・アクティブペインの更新、または Enter キーと同じ処理
```

### API Design

該当なし

### Database Schema

該当なし

### Dependencies

**Internal Dependencies:**
- ペインの描画レイアウト（width/2 のペイン幅、タイトル行、3 行のペインヘッダ、getVisibleLines、bgSplitHeights）: ヒットテストが同じ値を使う（NFR3）
- Enter キーの処理（EnterBehavior によるファイルのオープン、EnterDirectoryAsync、親ディレクトリへの移動）: ダブルクリックが同じ動作を行う（FR6）
- モーダル状態（`m.dialog`、ソートダイアログ、ミニバッファ、bg 出力のフォーカス）: マウス入力を無視する条件（FR7）

**External Dependencies:**
- Bubble Tea (github.com/charmbracelet/bubbletea): `tea.WithMouseCellMotion()` によるマウス報告とマウスイベントの受け取り（NFR5）

### File Structure

マウス処理は `internal/ui` に置き、`internal/fs` には置かない（NFR2）。ファイル単位の構成は Declared Change Set のとおり create-plan で決める。

## Declared Change Set

このフィーチャー固有のパスは手動で列挙せず、create-plan で `workflow.yaml` の各タスクの `files` から導出する（`references/phases/create-plan-phase.md`）。

すべての SPEC は、フィーチャー固有のパスに加えて、次の 2 つのワークフロー生成エントリをデフォルトで宣言する。

- `feature-docs/mouse-support/**`
- `test-docs/mouse-support/**`

`feature-docs/mouse-support/**` に含まれるもの: `REQUIREMENTS.md`、`SPEC.md`、`IMPLEMENTATION.md`、`workflow.yaml`、`phase-state/`、`tasks/`、`reviews/roundN.yaml`、`VERIFICATION.md`、`retrospect.yaml`、およびデザインステップが生成するデザイン成果物。生成主体は各フェーズドキュメントおよび `references/phase-state.md` であり、この節はそれらを引用するだけでルールは再掲しない。

`test-docs/mouse-support/**` に含まれるもの: タスクごとのテスト記録 `test-docs/mouse-support/{T}.tests.yaml`。生成主体は `implement-phase.md` であり、この節はそれを引用するだけでルールは再掲しない。

この 2 つのデフォルトエントリは、SPEC 作成者が明示的に除外しない限り宣言に含まれる。記載がないことで除外とみなすことはなく、除外は意図的な絞り込みとして明示する。

この宣言はスーパーセット（superset）の主張であり、検証時に観測される実際の変更集合は宣言に含まれる（CONTAINED IN）必要がある。一致する必要はない。implement タスクを 1 つも生成しないフィーチャーは `test-docs/mouse-support/` ディレクトリを生成しないが、宣言された `test-docs/mouse-support/**` は依然として正しい。宣言したパスが生成されなくても違反にはならない。

## Test Scenarios

### Unit Tests

- [ ] TS-1 (FR1, NFR2, NFR3): 左右ペインのエントリ行のヒットテスト
    - 前提: width 80、height 24。両ペインとも可視行数より多いエントリを持ち、scrollOffset は 0
    - 操作: (X=5, Y=4)、(X=39, Y=6)、(X=40, Y=4) をヒットテストする
    - 期待: 左ペインの index 0、左ペインの index 2、右ペインの index 0
- [ ] TS-2 (FR1, NFR3): scrollOffset が 0 でないときのヒットテスト
    - 前提: 左ペインの scrollOffset が 10
    - 操作: Y=4 と Y=4+getVisibleLines()-1 をヒットテストする
    - 期待: index 10 と 10+getVisibleLines()-1。Y=4+getVisibleLines() はエントリ行ではない
- [ ] TS-3 (FR1, FR3): 非エントリ領域のヒットテスト
    - 前提: width 81（奇数）、height 24。エントリが 3 つのペイン
    - 操作: タイトル行 Y=0、ステータス行 Y=23、ペインヘッダ行 Y=1..3、空行 Y=8、右端の列 X=80、フィルタで `(No matches)` を表示しているペインをヒットテストする
    - 期待: タイトル・ステータス・X=80 はどのペインにも属さない。ヘッダ行、空行、`(No matches)` の行はそのペインの非エントリ領域
- [ ] TS-4 (FR1, FR7, NFR3): bg 出力の分割表示でのヒットテスト
    - 前提: bgOutputActive が true のペイン
    - 操作: fileListHeight 内の行と、区切り行・出力領域の行をヒットテストする
    - 期待: ファイル一覧の行は fileListHeight を使ってエントリに対応付く。区切り行・出力行は非エントリ領域
- [ ] TS-5 (FR2): クリックでカーソルが移動し、マークは変わらない
    - 前提: アクティブな左ペインで 2 つのファイルがマーク済み、カーソルは 0
    - 操作: index 3 の行で左ボタンを押して離す
    - 期待: カーソルは 3、マークは同じ 2 つ、activePane は変わらない
- [ ] TS-6 (FR2): 非アクティブなペインのエントリのクリック
    - 前提: 左ペインがアクティブ
    - 操作: 右ペインの index 2 のエントリを左クリックする
    - 期待: 右ペインがアクティブ、右ペインのカーソルは 2。左ペインのカーソルとマークは変わらない
- [ ] TS-7 (FR3): 非エントリ領域のクリック
    - 前提: 左ペインがアクティブ、右ペインのカーソルは 1
    - 操作: 右ペインのヘッダ行、右ペインの空行、タイトルバー、ステータスバーを順に左クリックする
    - 期待: 右ペインがアクティブになり、右ペインのカーソルは 1 のまま。タイトル・ステータスのクリックでは何も変わらない
- [ ] TS-8 (FR4): ドラッグの範囲が既存のマークに追加される
    - 前提: index 7 がマーク済み、カーソルは 0
    - 操作: index 1 で押し、index 4 へ動かし、index 4 で離す
    - 期待: index 1〜4 と 7 がマークされ、カーソルは 4
- [ ] TS-9 (FR4): ドラッグ範囲がポインタに追従して縮む
    - 前提: ドラッグ前に index 2 がマーク済み
    - 操作: index 1 で押し、5 へ動かし、2 へ戻して 2 で離す。別途、5 で押して 3 へ上に動かす
    - 期待: 1 回目のドラッグの終了時は index 1〜2 がマーク（2 は既存のマークとして残る）、3〜5 はマークされない。上方向のドラッグでは 3〜5 がマークされる
- [ ] TS-10 (FR4): ドラッグで `..` はマークされない
    - 前提: エントリ 0 が `..`
    - 操作: `..` で押し、index 3 までドラッグして離す
    - 期待: index 1〜3 がマークされ、`..` はマークされない
- [ ] TS-11 (FR5): ドラッグ範囲が制限され、スクロールしない
    - 前提: scrollOffset 5 の長いディレクトリ。別途、エントリが 3 つの短いディレクトリ
    - 操作: ドラッグ中に、最初のエントリ行より上、タイトルバー、最後の可視行より下、もう一方のペインの X、最後のエントリより下の空行へポインタを動かす
    - 期待: 範囲は開始ペインの最初／最後の可視エントリで止まる。scrollOffset は 5 のまま、もう一方のペインは変わらない
- [ ] TS-12 (FR2, FR4): 同じ行での押下と解放はクリックになる
    - 前提: マークなし
    - 操作: index 2 で押し、別の行へ動かさずに離す
    - 期待: カーソルは 2、マークなし
- [ ] TS-13 (FR6, NFR4): ディレクトリ、ファイル、`..` のダブルクリック
    - 前提: 差し替えた時刻の取得元。エントリは `..`、ディレクトリ、通常のファイル
    - 操作: 同じエントリを 200 ms 間隔で 2 回押す
    - 期待: ディレクトリ: EnterDirectoryAsync のコマンドが返る（Enter と同じ）。ファイル: EnterBehavior に従ったオープンのコマンドが返る。`..`: 親ディレクトリへの移動のコマンドが返る
- [ ] TS-14 (FR6, NFR4): 判定時間外や別エントリではダブルクリックにならない
    - 前提: 差し替えた時刻の取得元
    - 操作: 同じエントリを 600 ms 間隔で 2 回押す。別のエントリを 100 ms 間隔で 2 回押す。同じエントリを 500 ms 以内に 3 回押す
    - 期待: 最初の 2 つのケースでは Enter の動作は行われない。3 つ目のケースでは Enter は 1 回だけ実行される
- [ ] TS-15 (FR6, FR2): 非アクティブなペインのエントリのダブルクリック
    - 前提: 左ペインがアクティブ
    - 操作: 右ペインのディレクトリのエントリをダブルクリックする
    - 期待: 右ペインがアクティブ、カーソルはそのエントリ、そのエントリに Enter の動作が行われる
- [ ] TS-16 (FR7): モーダル状態ではマウスを無視する
    - 前提: 順に、エラーダイアログが開いている、ソートダイアログがアクティブ、検索のミニバッファがアクティブ、シェルコマンドモード、bg 出力にフォーカスがある
    - 操作: エントリ行を左クリックし、ドラッグする
    - 期待: アクティブペイン、カーソル、マーク、モーダル状態は変わらない。コマンドは返らない
- [ ] TS-17 (FR7): ファイル一覧にフォーカスがある bg 分割表示
    - 前提: アクティブなペインで bg コマンドが実行中、bgOutputFocused が false
    - 操作: ファイル一覧の行をクリックし、次に出力領域をクリックする
    - 期待: ファイル一覧のクリックでカーソルが移動する。出力領域のクリックでは何も変わらない

## Assumptions

- A1: クリックはカーソルを移動するだけで、既存のマークは変えない
- A2: ドラッグは開始行から現在行までの範囲を既存のマークに追加してマークする。範囲はポインタにその場で追従し、カーソルは離した行で止まる
- A3: クリック・ドラッグで非アクティブなペインをアクティブにし、同じ操作で動作も行う
- A4: ペインの非エントリ領域のクリックはペインをアクティブにするだけ。タイトルバーとステータスバーのクリックは無視する
- A5: ダイアログ、ソートダイアログ、ミニバッファが開いている間、または bg 出力にフォーカスがある間はマウス入力を無視する。ファイル一覧にフォーカスがある bg 分割表示では、ファイル一覧部分は動作し、出力部分は無視する
- A6: ドラッグ範囲は最初／最後の可視行で止まり、ドラッグ中に一覧はスクロールしない
- A7: ホイールイベントは無視する。実装するのはクリック、ドラッグ、ダブルクリックだけ
- A8: ダブルクリックの判定時間は、同じエントリへの 2 回目の押下で 500 ms 固定
- A9: デザインステップは省略する（推奨の「省略」を自動で採用）
- A10: ドラッグ中はポインタの X 座標を使わない。ポインタがもう一方のペインの上にあっても、範囲は開始ペインの中に留まる。同じ行で押して離し、別の行へ動かさなかった場合はクリックであり、ドラッグではない
- A11: 右ボタンと中ボタンのイベントは無視する。端末の幅が奇数のときに残る列はどちらのペインにも属さず、そこでのクリックは無視する。ペインの読み込み中は、キーボードでのカーソル移動と同じく、表示中のエントリでヒットテストを行う
