# Task Plan: task0002 — Strict initial-value match in the rename dialog's input-field assertion

## Goal

The file-local input-field value assertion in `file_operation_tests.sh`
accepts only whitespace between the input field's borders besides the
expected base name, so both rename tests' initial-value checks fail when the
input field holds one extra non-whitespace character before or after the base
name (`before_rename.`, `xbefore_rename`, `before_renamex`, and the same for
`navren_before`).

## Requirements

FR1, FR2, NFR1, NFR2

### Files to Modify

- `test/e2e/scripts/tests/file_operation_tests.sh` — change the pass

  (`assert_input_field_value`, added by task0001) so that it matches
  IMPLEMENTATION.md's "Input-field value assertion contract": remove the
  allowance of one arbitrary non-whitespace character (the cursor-glyph
  allowance) on each side of the base name.

## Design

The assertion's contract is IMPLEMENTATION.md "Input-field value assertion
contract" and decision D2; this task brings the merged assertion in line with
it and does not restate it. The points this task changes:

- **Pass condition**: a single captured row must contain, in order and with
  nothing else in between: `│`, zero or more whitespace characters, the
  expected base name, zero or more whitespace characters, `│`, zero or more
  whitespace characters, the extension. The base name and the extension stay
  literal text.
- **Removed element**: the "at most one cursor glyph (any single
  non-whitespace character)" element before and after the base name. It is
  what lets `before_rename.` / `xbefore_rename` / `before_renamex` pass today
  (verify failure AC-2). No replacement allowance is added: the cursor is drawn
  by reverse video only and the capture drops attributes (SPEC A-2).
- **Locale independence**: with the removed element gone, the pass condition
  has no "any single character" element; the multi-byte `│` is matched as
  literal text only.
- **Unchanged**: the assertion's name, its positional inputs, the two call
  sites and their arguments (`before_rename` / `.txt`, `navren_before` /
  `.txt`), the one-check-per-call counting, the pass / fail output line, and
  the return status. Every other step of `test_rename_file` and
  `test_navigation_after_rename` is unchanged.

Extra whitespace-only characters around the base name remain outside the
check's scope (SPEC A-6).
