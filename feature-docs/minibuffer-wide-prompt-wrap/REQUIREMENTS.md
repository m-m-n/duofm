# minibuffer-wide-prompt-wrap - 要件定義書

## 1. 概要

### 1.1 背景

ミニバッファの入力表示幅が 0 以下になる狭い幅で、プロンプトを rune 数で切り詰めているため、全角文字を含むプロンプトが表示幅を超えて 2 行に折り返す。ミニバッファは 1 行ぶんしか確保されていないので、ペイン全体の行数も 1 行ずれる。

- レビュー指摘 stable_id: `39b88945803ca2e1`（medium、narrow-pane-render-panic の review round1 で未解決）

再現手順:

1. ミニバッファ幅が 26〜32 程度になる端末幅で duofm を起動する
2. 履歴検索（reverse-i-search）を開き、全角文字（例: 日本語）でパターンを入力する
3. プロンプト `(reverse-i-search)'日本語': ` が 22 rune に切られても表示幅は 25 桁あり、22 桁の表示領域を超えて 2 行になる

現在の実装（確認済みの事実）:

- `availableWidth <= 0` かつ `m.width > 4` のとき、プロンプトを `[]rune` で `contentWidth = m.width-4` 個に切り詰めている（表示幅ではない）（`internal/ui/minibuffer.go:238-247`）
- `availableWidth` は `m.width - len(m.prompt) - 2` で、`len` はバイト数（`internal/ui/minibuffer.go:206-207`）
- 入力の表示範囲は rune 数（`availableWidth` 個）で計算している（`internal/ui/minibuffer.go:248-256`）
- スタイルは `Width(m.width-2)` と `Padding(0,1)`。同ファイルのコメントでは内容幅を `m.width-4` と明記している（`internal/ui/minibuffer.go:230-237,275-279`）
- 履歴検索のプロンプトは `"(reverse-i-search)'" + pattern + "': "` で組み立てている（`internal/ui/model_update_keyboard.go:543`）
- `viewInternal` はミニバッファ表示時にファイル一覧を 1 行減らし、`minibuffer.View()` と改行 1 つを書く。`View` が改行を含むと、ペイン全体の行数が増える（`internal/ui/pane_render.go:67-71,109-113`）
- 既存テストは、幅 0〜4 と ASCII プロンプトでの改行なし・パニックなし、reverse-i-search の ASCII プロンプトの幅 24、幅 0/1 での行数が幅 40 と一致することを確認している。全角プロンプトのテストはない（`internal/ui/minibuffer_test.go:306-357`、`internal/ui/pane_render_test.go:593-677`）
- go-runewidth v0.0.16 と lipgloss v1.1.0 は既存の依存（`go.mod`）

### 1.2 目的

- 全角文字を含むプロンプトや入力があっても、ミニバッファをどの幅でも 1 行で描画する
- ミニバッファ表示時のペイン全体の行数を、プロンプトの文字種によらず一定に保つ

### 1.3 スコープ

- 対象: `Minibuffer.View` の表示計算（プロンプトの幅・入力部分の表示範囲・パディングを考慮した内容幅）。`availableWidth <= 0` と `availableWidth >= 1` の両方の経路を対象とする
- 対象外: `HandleKey` などの編集操作、`cursorPos` が rune 単位であること
- 対象外: 端末ごとの曖昧幅の設定による実際の描画幅の違い
- 対象外: E2E テストの追加

### 2.1 ビジネス目標

- ミニバッファ表示時のペイン全体の行数を、プロンプトの文字種によらず一定に保つ

### 3.2 ユースケース詳細

#### UC01: 狭い幅で全角パターンの履歴検索を行う

**アクター**: duofm の利用者

**事前条件**:
- ミニバッファ幅が 26〜32 程度になる端末幅で duofm を起動している

**基本フロー**:
1. 履歴検索（reverse-i-search）を開く
2. 全角文字（例: 日本語）でパターンを入力する
3. ミニバッファにプロンプト `(reverse-i-search)'日本語': ` が表示される

**代替フロー**:
- プロンプトの表示幅が内容幅以上のとき、プロンプトは表示幅で切り詰められ、入力部分とカーソルブロックは描画されない（FR3）

**事後条件**:
- ミニバッファは 1 行で描画され、ペインの行数は ASCII だけのプロンプトのときと同じである

### 4.2 機能詳細

#### FR1: 表示幅の基準

**説明**: `Minibuffer.View` は、プロンプトと入力部分の幅を、lipgloss が折り返しの判定に使うのと同じ表示幅（`lipgloss.Width` 系）で計算する。バイト数（`len`）や rune 数を表示幅として使わない。

#### FR2: 1 行の保証

**説明**: `m.width > 4` のとき、プロンプト・入力の表示部分・カーソルブロックの合計の表示幅を内容幅（`m.width-4`）以下にする。`availableWidth <= 0` と `>= 1` の両方の経路で、View の結果は改行を含まず、表示幅は `m.width-2` 以下になる。

#### FR3: プロンプトだけで内容幅を使い切るとき

**説明**: プロンプトの表示幅が内容幅以上のときは、プロンプトを表示幅で内容幅以下に切り詰めて描画し、入力部分とカーソルブロックは描画しない。

#### FR4: 入力部分の表示範囲

**説明**: 残りの幅（内容幅 − プロンプトの表示幅）が 1 以上のときは、入力部分の表示範囲を表示幅で決める。カーソル位置の文字（カーソルが末尾にあるときは 1 桁のカーソルブロック）が表示範囲に入るようにする。rune 単位の編集位置（`cursorPos`）と表示の桁数を混同しない。

**ビジネスルール**:
- 残りの幅が 1 桁で、カーソル位置の文字が全角のときは、1 行の保証（FR2）を優先し、FR5 に従ってその文字を描画しない

#### FR5: 全角文字が境界にかかるとき

**説明**: プロンプトの切り詰めや入力の表示範囲の境界に、全角文字が半分しか入らないときは、その文字を描画しない。

#### FR6: 幅 0〜4 の既存の挙動を維持

**説明**: `m.width` が 0〜4 のとき、View はパニックせず、結果に改行を含まない。

#### FR7: ペインの行数

**説明**: ミニバッファを表示しているとき、ペインの出力行数は、プロンプトに全角文字を含む場合も ASCII だけの場合と同じになる。

#### FR8: 収まる内容はそのまま表示

**説明**: プロンプトと入力が内容幅に収まるときは、どちらも切り詰めずに表示する。

### 12.1 テスト観点

- [ ] 境界値: 結合文字や絵文字を含むプロンプト・入力は、書記素単位の表示幅で測る。カーソルが書記素の途中の rune にあっても 1 行の保証を維持する
- [ ] 境界値: 全角文字の上にカーソルがあるとき、反転表示される文字の 2 桁が表示範囲に収まる
- [ ] 境界値: カーソルが末尾にあるとき、カーソルブロックの 1 桁を表示幅に含める
- [ ] 境界値: プロンプトの表示幅が内容幅とちょうど同じ・1 桁少ない・1 桁多いとき

## 13. 用語定義

| 用語 | 定義 |
|------|------|
| 内容幅 | ミニバッファのパディングを除いた表示領域の幅。`m.width-4` |
| 表示幅 | lipgloss が折り返しの判定に使う幅（`lipgloss.Width` 系、書記素単位） |
| 残りの幅 | 内容幅 − プロンプトの表示幅 |
| `availableWidth <= 0` の経路（負の分岐） | プロンプトだけで内容幅を使い切る経路 |
| `availableWidth >= 1` の経路（正の分岐） | プロンプトの後に入力部分を表示する経路 |
| `cursorPos` | 入力内の rune 単位の編集位置 |
