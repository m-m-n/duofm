# Task Plan: task0001 — ミニバッファ描画を表示幅基準にして 1 行を保証する

## Goal

`Minibuffer.View` のプロンプトの切り詰めと入力部分の表示範囲を表示幅で計算するように改め、全角文字・結合文字・絵文字を含むプロンプトや入力でも、どの幅でもミニバッファが 1 行（幅 5 以上では表示幅 `m.width-2` 以下）で描画されるようにする。あわせて、再発を検出する単体テストを追加する。

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, FR7, FR8, NFR1

## Scope

### Files to Create

なし（既存ファイルへの追加・変更だけで構成する）

### Files to Modify

- `internal/ui/minibuffer.go` — View の幅計算を表示幅基準に置き換える。HandleKey などの編集操作と、他のメソッドは変更しない
- `internal/ui/minibuffer_test.go` — TS-1、TS-2、TS-5、TS-6、TS-7 の単体テストを追加する。既存テストは変更しない
- `internal/ui/pane_render_test.go` — TS-3 のペイン行数テストを追加する。既存テストは変更しない

## Design

用語（表示幅・内容幅・残りの幅・収まる）、表示幅の基準（D1）、組み立て後の実測による 1 行保証（D2）、境界にかかる文字の扱い（D3）、幅 0〜4 の扱い（D4）、呼び出し側を変えないこと（D5）、View の事前条件・事後条件は IMPLEMENTATION.md に従う。ここではこのタスク固有の処理の流れだけを示す。

### View の処理の流れ

1. 非表示なら空文字列を返す（既存どおり）。
2. 内容幅を求める。
3. 幅が 0〜4（内容幅が 0 以下）のとき: パニックせず改行を含まない描画にする。0 以下や負の幅を切り詰めの計算に使ってもパニックしないようにする（D4）。
4. プロンプトの表示幅を測り、残りの幅を求める。
5. 残りの幅が 0 以下のとき（FR3）: プロンプトを表示幅で内容幅以下に切り詰める。境界に一部しか入らない文字は描画しない（D3）。入力部分とカーソルブロックは描画しない。
6. 残りの幅が 1 以上のとき（FR4）:
    1. 入力とカーソルブロック（カーソルが末尾にあるときだけ 1 桁）の合計表示幅が残りの幅以下なら、入力を切り詰めずにそのまま表示する（FR8）。
    2. 超えるときは、入力の表示範囲（連続する文字の区間）を表示幅で決める。区間は、カーソル位置の文字（カーソルが末尾にあるときはカーソルブロック 1 桁）を含み、合計表示幅が残りの幅以下になるようにする。
    3. 表示範囲の決め方は既存の方針を表示幅に置き換えたものにする: 入力の先頭から表示し、カーソル位置の文字（またはカーソルブロック）が範囲に入らないときに限り、それが範囲の右端に来るまで開始位置を右へ進める。
    4. 範囲の両端に一部しか入らない文字は描画しない（D3）。残りの幅が 1 でカーソル位置の文字が全角のときは、その文字を描画しない（D3）。
    5. 編集位置（rune 単位）と表示上の桁位置を混同しない。
7. カーソル位置の文字を反転表示する。カーソルが末尾にあるときは反転表示の空白 1 桁をカーソルブロックとして付ける（既存と同じ見た目）。
8. プロンプトと入力の表示部分を連結した内容行について、表示幅が内容幅以下であることを組み立て後の実測で保証する（D2）。
9. 既存のスタイル（幅 `m.width-2`、左右パディング 1、既存の前景色・背景色）で描画して返す。

### 例（幅と境界の具体値）

プロンプト「(reverse-i-search)'日本語': 」の表示幅は 28（ASCII 部分 19 + 「日本語」6 + 末尾 3）。

| 幅 | 内容幅 | 残りの幅 | 期待する描画 |
|----|--------|----------|--------------|
| 24 | 20 | -8 | プロンプトは「(reverse-i-search)'」（19 桁）まで。「日」は境界にかかるため描画しない |
| 25 | 21 | -7 | プロンプトは「(reverse-i-search)'日」（21 桁）まで |
| 26 | 22 | -6 | プロンプトは「(reverse-i-search)'日」（21 桁）まで。「本」は境界にかかるため描画しない |
| 32 | 28 | 0 | プロンプト全体（28 桁）。入力とカーソルブロックは描画しない |
| 33 | 29 | 1 | プロンプト全体と、入力の表示部分 1 桁。カーソル位置の文字が全角なら描画しない |
| 36〜37 | 32〜33 | 4〜5 | プロンプト全体と、カーソル位置を含む入力の表示範囲 |
| 40 | 36 | 8 | 入力「ls」とカーソルブロックは収まるので、プロンプトも入力も切り詰めない |

## Acceptance Criteria (MANDATORY)

- [ ] AC-2: 幅 36〜37 の各幅で、AC-1 と同じプロンプト・入力・カーソル位置の全組み合わせについて、View の結果が CR・LF を含まず、結果の表示幅が `m.width-2` 以下である（TS-1 / FR1, FR2, FR4, FR5）
- [ ] AC-3: 境界の幅（上の例の幅 24・25・26・31・32・33）で、View の結果が CR・LF を含まず表示幅が `m.width-2` 以下である。さらに、幅 24 と 26 では結果に境界にかかる文字（幅 24 では「日」、幅 26 では「本」）が含まれず、切り詰め後のプロンプトの先頭部分（幅 24 では「(reverse-i-search)'」）が含まれる。幅 33 で入力「日本語」・カーソルが先頭のときも、結果は CR・LF を含まず表示幅が `m.width-2` 以下である（TS-2 / FR3, FR5）
- [ ] AC-4: 残りの幅が 1 以上で入力が収まらないとき、入力の文字がすべて異なる入力（ASCII と全角を含む）で、カーソル位置の文字が View の結果に含まれる（カーソル位置の文字の表示幅が残りの幅以下のとき）。カーソルが末尾にあるときは入力の最後の文字が結果に含まれる（その文字の表示幅 + 1 が残りの幅以下のとき）（TS-7 / FR4）
- [ ] AC-5: 結合文字を含む文字列と、ZWJ で連結した絵文字を含む文字列をそれぞれプロンプトと入力に使い、幅 24〜37 の各幅・カーソルが書記素の途中の rune を含む入力内の各位置について、View の結果が CR・LF を含まず、結果の表示幅が `m.width-2` 以下である（TS-5 / FR1, FR2）
- [ ] AC-6: 幅 26 と 37 のそれぞれで、プロンプト「(reverse-i-search)'日本語': 」・入力「echo 日本語」のミニバッファを表示した `ViewWithMinibuffer` の出力行数が、同じ幅でプロンプト「/: 」・入力なしのミニバッファを表示したときの出力行数と一致する（TS-3 / FR7）

## Test Notes

- 先にテストを書き、修正前のコードで AC-1〜AC-3・AC-6 の少なくとも一部が失敗すること（現象の再現）を確かめてから修正する。
- AC-1・AC-2・AC-5 は幅 × 入力 × カーソル位置の表形式のテストにする。「途中」は入力の rune 数の半分、「全角文字の上」は入力内の最初の全角文字の rune 位置とする。
- AC-3 の境界の幅は、プロンプトの表示幅が内容幅とちょうど同じ（幅 32）・1 桁少ない（幅 33）・1 桁多い（幅 31）場合と、全角文字が切り詰めの境界にかかる場合（幅 24・26）を含む。
- AC-4 の「文字がすべて異なる入力」は、どの文字が表示範囲に入ったかを一意に判別できるようにするためのもの。文字の有無の判定は、エスケープシーケンスの有無に依存しない形にする（IMPLEMENTATION.md の Conventions）。
- AC-6 は `internal/ui/pane_render_test.go` の既存のペイン行数テストと同じ組み立て方（`newFilesPane`、`mustNotPanic`）で書く。行数は出力中の改行の数で数える。
- 幅の上限は、View の結果そのものを lipgloss の表示幅計測で測って判定する。行末の空白は描画時に取り除かれうるため、部分ごとの幅の和では判定しない。
- 単体テストだけにする。E2E テストは追加しない。
