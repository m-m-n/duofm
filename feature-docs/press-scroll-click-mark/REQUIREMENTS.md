# press-scroll-click-mark - 要件定義書

## 1. 概要

### 1.1 背景
マウス押下時にスクロール位置が変わると、動かさずに離しただけのクリックが範囲マークになる。

- `handleEntryPress` は、`switchToPane` / `SetCursor` / `EnsureCursorVisible` が動く前のヒットテストで得た index を anchor として記録する（`internal/ui/model_update_mouse.go:99-156`）。
- `updateDrag` は、移動・解放の行をペインの現在の scrollOffset に基づく `clampedEntryIndex` で index に変換する。セッションがアクティブでない間は、target == anchor をクリックとして扱う（`internal/ui/model_update_mouse.go:160-179`、`internal/ui/mouse_hittest.go:83-102,136-145`）。
- `switchToPane` は `syncPaneBgOutputState` を呼ぶ。この呼び出しは、`bgRunner.Pane()` が新しくアクティブになったペインと等しく、`isBgActive()` が真（実行中または bgClosing）のとき、そのペインの bgOutputActive を設定する（`internal/ui/model.go:318-328`、`internal/ui/model.go:368-388`）。
- `Pane.SetBgOutputActive` は `adjustScroll()` を呼び、これは `p.cursor` を使う。マウスの経路では `SetCursor(index)` がその後に動くため、この時点の cursor はクリックしたペインの以前の cursor のままである。`getVisibleLines()` は `bgSplitHeights()` のファイル一覧の高さに縮む（80x24 で 18 行から 11 行）（`internal/ui/pane.go:224-266`、`internal/ui/pane.go:600-603`）。
- 80x24 での例: 右ペインが非アクティブで項目 20 個、cursor=15、scrollOffset=0、右ペインでバックグラウンドコマンドが実行中。行 11（index 7）をクリックすると、`switchToPane` により scrollOffset が 5 に動く。anchor は 7 のままだが、行 11 での解放は 5+7=12 に対応するため、項目 7..12 がマークされる。
- 同じスクロールのずれにより、バックグラウンドコマンドが動く非アクティブペインでのダブルクリックの 2 回目の押下が別の項目に当たることがある。この場合 clickKey が異なり、Enter が発火しない（`internal/ui/model_update_mouse.go:140-146`、`internal/ui/mouse_doubleclick.go`）。
- アクティブ化で bg 分割が現れるペインへの押下を扱う既存テストはない。`TestHandleMouse_BgSplit_FileListClickMovesCursorSeparatorDoesNot` は既にアクティブな左ペインを使い、`TestHandleMouse_PressReleaseNoMove_NoMarks` にはスクロールの変化がない（`internal/ui/model_update_mouse_test.go:277-291,378-395`）。

### 1.2 目的
項目の左押下でクリックしたペインのスクロール位置が変わる場合でも、マウスを動かさずに押下・解放したときにマークが増えない。

### 1.3 スコープ
- 対象: 非アクティブペインの項目への左押下で、そのペインがアクティブになり、アクティブ化でファイル一覧が縮む（bg 分割が現れる）場合の押下・移動・解放・ダブルクリックの処理
- 対象外: Tab によるキーボードでのペイン切り替えと、bg 分割のアクティブ化時のスクロール動作（変更しない）

## 2. ビジネス要件

### 2.1 ビジネス目標

### 3.2 ユースケース詳細

#### UC01: アクティブ化で一覧が縮む非アクティブペインの項目をクリックする

**アクター**: マウスで操作する利用者

**事前条件**:
- クリックするペインが非アクティブである
- そのペインでバックグラウンドコマンドが実行中または終了処理中である

**基本フロー**:
1. 利用者が非アクティブペインの項目を左ボタンで押下する
2. 利用者が別の行へ動かさずに同じ行で離す

**代替フロー**:
- 押下後に別の行へ移動してから離した場合は、anchor..target の範囲をマークする（FR3）
- 押下した項目が縮小後のファイル一覧より下にある場合は、既存の表示範囲調整で押下した項目を最下の表示行に表示する（FR2）

**事後条件**:
- そのペインのマーク集合は押下前と等しい
- カーソルは押下した項目にある

## 4. 機能要件

### 4.1 機能一覧
| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| FR1 | 同じ行での押下・解放でマークが増えない | アクティブ化で一覧が縮むペインで、同じ行の押下・解放はマークを変えない | 高 |
| FR2 | 押下時のスクロール位置維持 | 押下前の scrollOffset を保ち、押下した項目を押下行に残す | 高 |
| FR3 | アンカーと一致するドラッグの対応付け | 押下行へ戻る移動はアンカーに対応する | 高 |
| FR4 | アクティブ化するペインでのダブルクリック | 2 回目の押下が同じ項目に当たり Enter を実行する | 中 |
| FR5 | 回帰テスト | 修正前のコードで失敗する単体テストを追加する | 高 |

### 4.2 機能詳細

#### FR1: 同じ行での押下・解放でマークが増えない

**説明**: 非アクティブペインの項目を左ボタンで押下してそのペインがアクティブになり、そのアクティブ化でファイル一覧が縮む場合（そのペインでバックグラウンドコマンドが実行中または終了処理中のため bg 分割が現れる場合）、別の行へ移動せずに同じ画面行で解放すると、そのペインのマーク集合は押下前の状態と等しい。カーソルは押下した項目へ移動する。

#### FR2: 押下時のスクロール位置維持

**説明**: 押下後、押下した項目が [押下前の scrollOffset, 押下前の scrollOffset + アクティブ化後の表示行数) の範囲にある場合、クリックしたペインの scrollOffset は押下前の値と等しい。押下した項目は押下した画面行に留まる。それ以外の場合（押下した項目が縮小後のファイル一覧より下にある場合）は、既存の表示範囲調整を適用し、押下した項目をファイル一覧の最下の表示行に表示する。

#### FR3: アンカーと一致するドラッグの対応付け

**説明**: このような押下で開始した armed セッション中、押下行へ戻る移動は押下した項目（アンカー）に対応する。別の行へ移動してから解放すると、既存のドラッグ動作と同じく anchor..target の範囲をマークする。

#### FR4: アクティブ化するペインでのダブルクリック

**説明**: FR2 で押下前の scrollOffset が保たれる場合、ダブルクリック判定時間内に同じ行を 2 回目に押下すると同じ項目に当たり、既存の Enter 動作を実行する。押下した項目が縮小後のファイル一覧より下にあり、表示範囲調整で移動した場合は、2 回目の押下が同じ項目に当たることは求めない。

#### FR5: 回帰テスト

**説明**: アクティブ化で bg 分割が現れて scrollOffset がずれる非アクティブペインに対し、`Model.Update` で押下・解放を行う単体テストを追加する。テストはマークが増えないことを検証し、修正前のコードでは失敗する。

## 13. 用語定義

| 用語 | 定義 |
|------|------|
| bg 分割 | ペインでバックグラウンドコマンドが実行中または終了処理中のとき、そのペインのファイル一覧の表示行数が `bgSplitHeights()` のファイル一覧の高さに縮む状態 |
| bgClosing | バックグラウンドコマンドの終了処理中の状態 |
| anchor（アンカー） | `handleEntryPress` が押下時に記録する項目の index |
| armed セッション | 押下で開始したマウスのセッション |
