# Task Plan: task0001 — Keep the pre-press scroll offset when an entry press activates a bg-split pane

## Goal

A left press on an entry of an inactive pane whose activation shows the background-output split keeps that pane's pre-press scroll offset, so the pressed entry stays under the pointer and a same-row press/release adds no marks. Drag and double-click that start from such a press map to the pressed entry. Regression tests pin this through Model.Update.

## Requirements

FR1, FR2, FR3, FR4, FR5, NFR1, NFR2, NFR3, NFR4

## Scope

### Files to Create

None.

### Files to Modify
- `internal/ui/model_update_mouse.go` — entry-press handler (handleEntryPress): record the clicked pane's scroll offset before activation, restore it after activation, then apply ensure-visible only when the pressed entry is outside the visible range.
- `internal/ui/model_update_mouse_test.go` — regression tests for AC-1 to AC-7 and the keyboard guard test of AC-8.

## Design

### Entry-press flow (handleEntryPress), new order

1. Record the clicked pane's current scroll offset (pre-press offset). The pressed index comes from the hit test against this offset, so it is at least the pre-press offset.
2. If the clicked pane is not active, activate it through the existing switchToPane (unchanged; it may shrink the pane's visible lines and move its scroll offset based on the pane's previous cursor).
3. Set the clicked pane's scroll offset back to the pre-press offset.
4. Move the clicked pane's cursor to the pressed index.
5. If the pressed index is outside the visible range starting at the restored offset (with the post-activation visible-line count), apply the existing ensure-visible adjustment.
6. The double-click check and drag-session arming stay as they are: click key from the pressed entry, anchor = pressed index, baseline = mark snapshot taken at this point.

### Postconditions

Clicked pane P, pressed index i, pre-press offset s, post-activation visible lines v:

- P's cursor is i.
- If s <= i < s + v: P's scroll offset is s, and entry i is on the pressed screen row.
- Otherwise: P's scroll offset is i - v + 1, and entry i is on the bottom visible file-list row.
- P's mark set is unchanged by the press.
- The other pane is not touched by this handler beyond what switchToPane already does.
- When P is already active, step 2 is skipped and step 3 changes nothing (same behavior as today).

### Consequences for release, drag and double-click (no code change there)

- In the s <= i < s + v case, the release row is converted with the same scroll offset the press row was hit-tested with, so the press row maps back to the anchor.
- In the other case, the press row is at or below the bottom file-list row; the drag-row mapping clamps it to the bottom visible entry, which is the anchor.
- A second press on the same row within the double-click window (s <= i < s + v case) hits the same entry and the same click key.

### Fixture state used by the Acceptance Criteria

80x24 geometry; left pane active; right pane inactive over 20 generated files (21 entries including ".." at index 0); right pane cursor 15, scroll offset 0; a background command attached to the right pane and running. The right pane shows 18 entry rows without the split and 11 with it. Rows are computed with scroll offset 0 (the pre-press offset). On the unmodified handler, activation moves the right scroll offset to 5, and a same-row release at index 7's row maps to index 12 and marks 7..12.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (TS-1, TS-2; FR1, FR2, FR5): In the fixture state, a left press and a same-row release on the row of right-pane index 7, delivered through Model.Update, leave the right pane's mark set equal to the pre-press set, the right cursor at 7, the right scroll offset at 0, and entry 7 on the pressed screen row. The same holds when the background state is closing instead of running. The running variant fails on the unmodified handler.
- [ ] AC-2 (TS-3; FR1, FR2): Table-driven over the fixture state, with the pressed index (a) above the shifted window (index 3), (b) inside the kept range (index 7), and (c) below the shifted window but on a pre-press visible row (index 16): a same-row press/release adds no marks and the cursor ends on the pressed index. For (a) and (b) the right scroll offset is 0. Cases (a) and (b) fail on the unmodified handler.
- [ ] AC-3 (TS-4; FR1, FR2): In the fixture state, pressing index 13 (at or beyond pre-press offset 0 plus 11 visible lines, on a pre-press visible row) leaves the cursor at 13 on the bottom visible file-list row (scroll offset 3), and a same-row release adds no marks. Fails on the unmodified handler.
- [ ] AC-4 (TS-5; FR1): With right-pane entries marked before the press (at least one inside index range 7..12 and one outside it), a same-row press/release at index 7 in the fixture state leaves the right pane's mark set exactly equal to the pre-press set.
- [ ] AC-5 (TS-6; FR1): In the fixture state, a same-row press/release on the right pane's ".." row adds no marks and leaves the cursor at index 0 on "..".
- [ ] AC-6 (TS-7; FR3): In the fixture state, press at index 7, motion to index 9's row, release there: the mark set is the pre-press set plus exactly entries 7, 8 and 9. Second case: press at index 7, motion to index 9's row, motion back to index 7's row, release there: the mark set is the pre-press set plus exactly entry 7, and the cursor is 7. Both cases fail on the unmodified handler.
- [ ] AC-7 (TS-8; FR4): In a fixture of the same geometry and state whose right-pane index 7 is a directory, with a fake clock: press and release on index 7's row, then a second press on the same row within the double-click window. The second press executes the existing Enter action on that directory (non-nil command; the right pane's path becomes that directory and it starts loading). Fails on the unmodified handler.
- [ ] AC-8 (TS-9, TS-10, TS-11, TS-12; NFR1-NFR4): In the fixture state, switching to the right pane with the keyboard move-right action leaves the right cursor at 15 and the right scroll offset at 5 (current behavior; passes before and after the change). Pane.adjustScroll, Pane.SetBgOutputActive, Model.syncPaneBgOutputState and Model.switchToPane are not modified. The whole test suite passes, gofmt lists no files and go vet reports nothing.

## Test Notes

- All new tests go in `internal/ui/model_update_mouse_test.go` and drive mouse input through Model.Update, reusing the existing helpers of that file (test model builder, row helper, mark assertions, fake clock).
- Background state without a real process: construct, inside the package, a background runner that reports the right pane and a running state. For the closing variant, the runner still reports the right pane but is not running, and the model's closing flag is set. With no runner at all, the background pane resolves to the left pane and the split never appears on the right.
- Write the tests first and confirm that the criteria marked "fails on the unmodified handler" fail before changing the handler (FR5).
- AC-7 needs its own fixture because the generated-files fixture has no directory; directories sort before files after "..", so the fixture decides which entry lands at index 7.
- The keyboard guard in AC-8 may call the move-right action handler directly when the struct-literal test model carries no key bindings.
- The "not modified" part of AC-8 is checked on the diff: this task does not touch `internal/ui/model.go` or `internal/ui/pane.go`.

## Out of Scope

- Changing the shared scroll logic, bg-split activation scrolling, or keyboard pane switching.
- Presses on non-entry rows of an inactive pane (header, blank, separator, output rows): the activation-only path stays as it is.
- Guaranteeing that a second press hits the same entry when the pressed entry had to be scrolled to the bottom row (as-3).
- Changes to the hit test, drag-row mapping, mark application, double-click detector or renderer.
- New E2E tests.
