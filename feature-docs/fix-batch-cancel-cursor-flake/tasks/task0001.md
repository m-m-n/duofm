# Task Plan: task0001 — Display-order marked-file queries, order tests, and E2E batch-cancel hardening

## Goal

The pane's marked-file queries return names and full paths in the pane's display order, with marked names that are not in the current display list appended in ascending name order. Unit tests pin this order, and the E2E test `test_batch_cancel_cursor` waits for the overwrite dialog with an upper bound and verifies the post-cancel filesystem state.

## Requirements

- `test/e2e/scripts/tests/cursor_preserve_tests.sh` — harden test_batch_cancel_cursor (bounded wait for the overwrite dialog, post-cancel state checks)

## Design

### Terms

- **Mark set**: the set of names the pane holds as marked — exactly the names `MarkCount()` counts.
- **Display list**: the pane's current entry list at call time — the filtered and sorted list the pane renders, including the directories-first grouping and the parent entry.

### Contract: `GetMarkedFiles` (signature unchanged, NFR1)

- **Precondition**: none. Valid in every pane state (no marks, active filter, any sort configuration).
- **Postconditions**:
  1. Every name in the mark set appears exactly once and no other name appears; the length equals `MarkCount()` (NFR2).
  2. The leading part of the result is the marked names that are present in the display list, in display-list order (FR1).
  3. The remaining marked names (those not present in the display list, e.g. hidden by an active filter) follow, sorted ascending by plain string comparison of the names — the same comparison the project's name sort uses (FR2).
  4. The result does not depend on the order in which marks were added or on the mark set's internal iteration order; repeated calls with unchanged pane state return identical lists.
  5. The query is read-only: marks, display list, cursor and scroll position are unchanged.

**Flow**:

1. Walk the display list from first to last. For each entry whose name is in the mark set, append the name to the result and note it as emitted.
2. Collect the marked names that were not emitted in step 1 and sort them ascending by name.
3. Append the sorted names from step 2 to the result and return it.

### Contract: `GetMarkedFilePaths` (signature unchanged, NFR1)

- **Postcondition**: the result has the same length as `GetMarkedFiles` at the same pane state, and its i-th element is the pane's current directory path joined with the i-th name of `GetMarkedFiles`, using the same path-join rule as today (FR3).
- The path list is derived from the name list so that the two orders cannot diverge.

### Unchanged behavior

Mark toggling, clearing, `IsMarked`, `MarkCount`, `HasMarkedFiles`, `CalculateMarkInfo`, and every caller of the two queries stay as they are.

### E2E: `test_batch_cancel_cursor` hardening (FR5)

Setup is unchanged: the source directory holds `01_aaa.txt` to `05_eee.txt`; the destination holds a pre-existing `02_bbb.txt` whose content is `existing`; `01_aaa.txt` and `02_bbb.txt` are marked and `m` is pressed.

**Flow after pressing `m`**:

1. Replace the fixed 1.0 s sleep with a bounded wait: capture the screen repeatedly at a short interval (0.1–0.2 s) until the text `already exists` appears or an upper bound of 5 s elapses. The outcome is recorded as one assertion: pass when the text is seen; fail with a short screen excerpt when the bound elapses. The wait never blocks beyond the bound.
2. Send key `2` (Cancel) and keep the existing short settle time.
3. Assert all of:
   - the application is still running (existing assertion);
   - `dst/01_aaa.txt` exists (existing assertion, "First file was moved before cancel");
   - `src/02_bbb.txt` still exists;
   - the content of `dst/02_bbb.txt` is exactly `existing`.
4. Clean up as today (remove both directories, stop the session) regardless of assertion outcomes.

**Constraints**:

- The bounded-wait helper and the file-content assertion helper live in `cursor_preserve_tests.sh`, next to the file's existing assertion helpers. The shared `test/e2e/scripts/helpers.sh` is not modified.
- The E2E runner treats every function whose definition line starts with the `test_` prefix as a test (run list and `--check-list`). New helper names must not start with that prefix.
- Every new check updates the script's run / passed / failed counters the same way the file's existing assertion helpers do.
- The test function name `test_batch_cancel_cursor` stays unchanged (it is listed in the runner's run list).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1, FR4 / T1): With at least three names marked in the reverse of their display order, `GetMarkedFiles` returns them in display order. The call-and-compare is repeated at least 50 times within one test run, and every repetition matches.
- [ ] AC-2 (FR1 / T2): With one or more directories and several files marked in an order different from display order, `GetMarkedFiles` equals the display list's order restricted to marked names, and every marked directory precedes every marked file.
- [ ] AC-3 (FR1, FR4 / T4): After marking, the display order is changed while the marks are kept (sort changed to name descending and re-applied, without reloading the directory); `GetMarkedFiles` follows the new display order at call time.
- [ ] AC-4 (FR2, NFR2 / T3): With an active filter hiding some marked names (at least two hidden, one of them a directory, so that ascending-name order differs from display order), `GetMarkedFiles` returns the visible marked names in display order followed by the hidden marked names in ascending name order; its length equals `MarkCount()` and its elements equal the mark set.
- [ ] AC-5 (FR1, FR2, NFR2 / T6): With zero marks, both queries return empty lists. With exactly one mark, `GetMarkedFiles` returns exactly that name and `GetMarkedFilePaths` returns exactly that name's full path.
- [ ] AC-6 (FR3 / T5): For a state with several marks including at least one filter-hidden mark, `GetMarkedFilePaths` has the same length as `GetMarkedFiles`, and for every i its i-th element equals the pane path joined with the i-th name.
- [ ] AC-7 (FR5 / T7): `test_batch_cancel_cursor`, run through the project's E2E runner, records the bounded wait for `already exists` as an assertion, sends `2`, and passes all of: application still running, `dst/01_aaa.txt` exists, `src/02_bbb.txt` exists, `dst/02_bbb.txt` content is `existing`. The runner's `--check-list` still passes.
- [ ] AC-8 (NFR1, NFR3, NFR4): Both queries keep their existing signatures and all existing callers compile unchanged; `go test ./...` passes, including every pre-existing test in `internal/ui/pane_mark_test.go`; gofmt produces no changes and go vet reports no findings.

## Test Notes

- AC-1 to AC-6 are unit tests in `internal/ui/pane_mark_test.go`. Reuse the file's existing temp-directory pane fixture, or a local variant with more names when a criterion needs them. Derive the expected display order from the pane's display list at call time; hard-code only the structural expectations (directories first, ascending tail).
- AC-1 is TDD-awkward: against the current implementation the red result is probabilistic. The repetition count and the three-or-more marked names make the red observation reliable. Applying the same repetition to the other order checks is cheap and recommended.
- AC-3: change the order through the pane's existing sort configuration and its cursor-preserving sort re-application, which keep the marks. Reloading the directory is not an option, because it clears the marks (pinned by `TestMarksClearedOnDirectoryChange`).
- AC-4 and AC-6: hide marked names with the pane's existing filter application (incremental mode). It rebuilds the display list from all entries without clearing marks. Mark the names before applying the filter.
- AC-7 runs in the containerized E2E harness (`make test-e2e-build && make test-e2e`). Running the Cursor Preserve category several times is recommended to gain confidence; the repeated full-suite runs belong to verify (T8).
- The existing `TestGetMarkedFiles` and `TestGetMarkedFilePaths` stay and must keep passing.
