# header-wrap-hittest - 要件定義書

## 1. 概要

### 1.1 背景
git 管理外のディレクトリで長いパスを開くと、ペインヘッダが折り返して複数行になり、マウスのクリック・ドラッグ・ダブルクリックが意図と違うエントリに作用する。
ヒットテストはヘッダを固定 3 行（`mousePaneHeaderRows=3` / `mouseFirstEntryRow=4`）とみなしており、描画側と定義を共有していない。`internal/ui/pane_render.go` の `renderHeaderLine1` は gitBranch が空のとき displayPath を切り詰めず、lipgloss の `Width(p.width-2)` で折り返す。
レビュー指摘 stable_id: 52107dd60886982b（mouse-support の review round1 で未解決）。

### 1.2 目的
- git 管理外のディレクトリでペイン幅より長いパスを開いたときも、マウスのクリック・ドラッグ・ダブルクリックがクリックした行のエントリに作用する。
- ペインヘッダの行数を1つの定義とし、描画とヒットテストがその定義を共有する（レビュー指摘 stable_id: 52107dd60886982b）。

### 1.3 スコープ
**対象**:
- ペインヘッダ1行目（パス、[H] 表示、フィルタ表示、git ブランチ表示）の描画（`renderHeaderLine1`）
- ヘッダ1行目の切り詰め（`truncateStringWithEllipsis`）
- ペインヘッダ行数の定義と、それを参照するヒットテスト（最初のエントリ行・ドラッグ行の対応）
- 描画側の表示件数計算（通常表示・bg 出力分割表示・dimmed 表示）

**対象外**:
- 既存のヒットテスト規則の変更（A4）
- E2E テストの追加（必須としない。A3）
- 設計工程（省略する。A5）

## 2. ビジネス要件

### 2.1 ビジネス目標
- git 管理外のディレクトリでペイン幅より長いパスを開いたときも、マウスのクリック・ドラッグ・ダブルクリックがクリックした行のエントリに作用する。
- ペインヘッダの行数を1つの定義とし、描画とヒットテストがその定義を共有する。

### 2.2 対象ユーザー
| ユーザータイプ | 説明 |
|----------------|------|
| マウス操作のユーザー | duofm のファイル一覧をマウスのクリック・ドラッグ・ダブルクリックで操作するユーザー |

### 2.3 期待される効果
- ヘッダの行数に関わらず、クリックした行のエントリが選択される。
- ドラッグ・ダブルクリックもクリックした行のエントリに作用する。

### 3.2 ユースケース詳細

#### UC01: 長いパスのディレクトリでエントリをクリックする

**アクター**: マウス操作のユーザー

**事前条件**:
- git 管理外で、ペイン幅より長いパスのディレクトリを開いている

**基本フロー**:
1. ユーザーがファイル一覧のエントリ行を左クリックする
2. クリックした行に表示されているエントリにカーソルが移動する

**代替フロー**:
- なし

**事後条件**:
- クリックした行のエントリが選択されている

#### UC02: 長いパスのディレクトリでドラッグ・ダブルクリックする

**アクター**: マウス操作のユーザー

**事前条件**:
- git 管理外で、ペイン幅より長いパスのディレクトリを開いている

**基本フロー**:
1. ユーザーがエントリ行をドラッグする、またはダブルクリックする
2. ドラッグはドラッグした行の範囲のエントリをマークする
3. ダブルクリックはクリックした行のエントリに Enter 動作を行う

**代替フロー**:
- なし

**事後条件**:
- ドラッグ・ダブルクリックが、操作した行のエントリに作用している

## 4. 機能要件

### 4.1 機能一覧
| ID | 機能名 | 説明 | 状態 |
|----|--------|------|------|
| FR1 | クリック行とエントリの対応 | ヘッダの内容に関わらず、クリックした行のエントリにカーソルが移動する | confirmed |
| FR2 | ドラッグ・ダブルクリックの対応 | ドラッグとダブルクリックも FR1 と同じ行とエントリの対応で動作する | confirmed |
| FR3 | ヘッダ1行目を常に1行に収める | ヘッダ1行目の表示幅を内容幅以下に切り詰める | assumed |
| FR4 | ブランチ単独表示の切り詰め | ブランチ単独表示でもヘッダ1行目を1行に収める | assumed |
| FR5 | 負の幅での安全性 | 内容幅が0以下でも panic せず、負の幅を切り詰め処理に渡さない | assumed |
| FR6 | ヘッダ行数の定義共有 | ヘッダ行数を1つの定義とし、ヒットテストと表示件数計算が参照する | assumed |

### 4.2 機能詳細

#### FR1: クリック行とエントリの対応

**説明**: ペインヘッダの内容（パスの長さ、git ブランチの有無、[H] 表示・フィルタ表示の有無）に関わらず、エントリ行を左クリックすると、その行に表示されているエントリにカーソルが移動する。

**入力**:
- マウスの左クリック位置（エントリ行）

**出力**:
- カーソル位置: クリックした行に表示されているエントリ

**ビジネスルール**:
- ペインヘッダの内容によって、行とエントリの対応が変わらない。

#### FR2: ドラッグ・ダブルクリックの対応

**説明**: ドラッグによる範囲マークとダブルクリックによる Enter 動作も、FR1 と同じ行とエントリの対応で動作する。

**入力**:
- マウスのドラッグ範囲、またはダブルクリック位置

**出力**:
- ドラッグ: ドラッグした行の範囲のエントリがマークされる
- ダブルクリック: クリックした行のエントリに Enter 動作を行う

**ビジネスルール**:
- 行とエントリの対応は FR1 と同じ。

#### FR3: ヘッダ1行目を常に1行に収める

**説明**: ヘッダ1行目（パス、[H] 表示、フィルタ表示、git ブランチ表示）は、git ブランチの有無に関わらず、表示幅がペインの内容幅（p.width-4、0 未満のときは 0）を超えない。超える場合は末尾を「...」で切り詰める。

**入力**:
- パス、[H] 表示、フィルタ表示、git ブランチ表示
- ペイン幅（p.width）

**出力**:
- ヘッダ1行目: 表示幅が内容幅以下の1行の文字列

**ビジネスルール**:
- 内容幅は p.width-4 とし、0 未満のときは 0 とする。
- 内容幅を超える場合は末尾を「...」で切り詰める。
- 切り詰めは先頭を残して末尾を省略する（A2）。

#### FR4: ブランチ単独表示の切り詰め

**説明**: ペイン幅が狭くパス表示幅が4未満になりブランチ表示だけを出す場合も、ブランチ表示がペインの内容幅を超えるときは切り詰め、ヘッダ1行目を1行に収める。

**入力**:
- git ブランチ表示
- ペイン幅（p.width）

**出力**:
- ヘッダ1行目: 表示幅が内容幅以下の1行の文字列

#### FR5: 負の幅での安全性

**説明**: ペイン幅が極端に狭く内容幅が0以下になる場合でも、ヘッダ描画は panic せず、切り詰め処理に負の幅を渡さない（幅は0以上に補正する）。

**エラーケース**:
| エラー | 条件 | 対応 |
|--------|------|------|
| panic | 内容幅が0以下になるペイン幅 | 幅を0以上に補正し、panic しない |

#### FR6: ヘッダ行数の定義共有

**説明**: ペインヘッダの行数は1つの定義とし、ヒットテスト（最初のエントリ行・ドラッグ行の対応）と描画側の表示件数計算（通常表示・bg 出力分割表示・dimmed 表示）がその定義を参照する。

**ビジネスルール**:
- ヒットテストと描画側の表示件数計算は、同じヘッダ行数の定義を参照する。
