# Task Plan: task0001 — ミニバッファのスクロール時の表示範囲を書記素の境目に揃える

## Goal

ミニバッファの Minibuffer.View で、入力が残りの幅に収まらずスクロールするとき、表示範囲の開始位置（displayStart）と終了位置（displayEnd）を常に書記素の境目にする。
ZWJ 連結の絵文字などの結合文字列を途中で切らずに表示し、1 行表示を保つ。

## Requirements

FR1, FR2, FR3, FR4, NFR1, NFR2

## Scope

### Files to Create

なし

### Files to Modify
- `internal/ui/minibuffer.go` — 幅の単位を書記素にする単位分割の補助関数の変更と、Minibuffer.View の残りの幅が 1 以上の経路での表示範囲の計算の変更
- `internal/ui/minibuffer_test.go` — 回帰テストと、テスト用の補助関数を追加（既存テストと既存ヘルパーは変更しない）
- `go.mod` — github.com/rivo/uniseg の // indirect 表記を外す（書記素の区切りのために直接使う場合に限る。SPEC a6）
- `go.sum` — go.mod の上記の変更に伴う変更だけ（変更が出ない場合は触らない）

## Design

### 用語

- 内容幅: ミニバッファの行に表示できる幅（m.width − 4）
- 残りの幅: 内容幅からプロンプトの表示幅を引いた値
- 表示幅の基準: 既存コードと assertBoundedSingleLine が使う幅の測り方（書記素単位。SPEC FR1 が表示幅の基準とするもの）
- 書記素: 表示幅の基準が内部で使う区切り方で分けた、書記素クラスタ
- 幅の単位: 表示範囲を広げる・縮めるときに一まとまりで扱う rune の並び。現行は「正の幅の rune と、それに続く幅 0 の rune の並び」。本タスクで書記素に変える
- カーソルの書記素: カーソル位置の rune を含む書記素。カーソルが書記素の途中の rune（ZWJ などを含む）にあるときも、その書記素全体を指す

### 不具合の原因

現行の幅の単位は、ZWJ 連結の絵文字を正の幅の rune ごとに分ける（家族の絵文字は 4 つの単位になり、単位の幅の合計は 8、実際の表示幅は 2）。
スクロール経路はこの単位の境目で表示範囲の開始位置・終了位置を決めるため、境界が書記素の途中になる。
カーソル位置の文字も rune 1 つとして扱うため、カーソルが書記素の途中にあると、その書記素の一部だけが表示範囲に入る。

### 書記素の区切り方（決定）

- 書記素の区切りには、表示幅の基準が内部で使っている書記素分割と同じもの（github.com/rivo/uniseg）を使う（SPEC FR1, a1）。入力の先頭から順に書記素を一つずつ取り出す
- 入力全体を 1 回だけ書記素に分け、書記素ごとに開始・終了の rune 位置（入力の rune 列への位置）と幅を持つ。幅は、書記素の文字列を表示幅の基準で 1 回だけ測った値とする
- カーソルの書記素の前と後の書記素の列は、入力全体を分けた結果を切り出して得る（前後を別々に分け直さない）。こうすると境目は常に入力全体の書記素の境目と一致する
- rune ごとの幅は、単位の境目の決定にもカーソル位置の文字の幅にも使わなくなる。それだけに使っていた補助処理は残さない
- 依存: github.com/rivo/uniseg は既存の間接依存で、ライセンスは MIT。project.license（MIT）と両立する。直接使うため go.mod の `// indirect` 表記を外す。新しい依存は加えない

### 単位分割の補助関数を共有する経路（決定）

単位分割の補助関数（partitionUnits）は、プロンプトの切り詰めの経路（残りの幅 0 以下）でも使っている。
この補助関数の単位を書記素に変えるので、プロンプトの切り詰めの経路でも単位が書記素になる。
この経路の処理の流れ（先頭から収まる単位を残し、guardFit で測って末尾側の単位を取り除き、収まらなければプロンプトを空にする）は変えない。
既存のプロンプトの切り詰めのテストが変更なしで通ることで、挙動を保つことを確かめる（AC-7）。

### 表示範囲の決め方（変更後、残りの幅が 1 以上の経路）

1. 入力全体とカーソルが実際の表示幅で収まるかどうかの判定と、収まるときの表示は変えない（SPEC a4）
2. 収まらないときは、入力全体を書記素の列に分ける。カーソルが末尾以外にあるときは、カーソルの書記素を特定し、書記素の列を「カーソルの書記素より前の列」と「後の列」に分ける
3. カーソルが末尾のとき: 入力の末尾から、幅の合計が「残りの幅 − 1」（カーソルブロック 1 桁分を引いた値）以下になる最長の書記素の列を残す。終了位置は入力の末尾、開始位置は残した列の先頭の書記素の始まり（残せる書記素がなければ入力の末尾）（FR1）
4. カーソルの書記素の幅が残りの幅より大きいとき: 入力を表示しない。既存のカーソル位置の文字が単独でも収まらない場合（CD3）と同じ扱い（FR3）
5. 前の列の幅の合計 + カーソルの書記素の幅が残りの幅以下のとき: 開始位置は 0。後の列の先頭から、残った幅に収まる最長の書記素の列を加える。終了位置は最後に加えた書記素の終わり（加えられなければカーソルの書記素の終わり）（FR2, FR3）
6. それ以外のとき: 終了位置はカーソルの書記素の終わり。開始位置は、前の列の末尾から幅の合計が「残りの幅 − カーソルの書記素の幅」以下になる最長の書記素の列の、先頭の書記素の始まり（残せる書記素がなければカーソルの書記素の始まり）（FR1, FR3）
7. 組み立てた行を実際の表示幅で測って縮める既存の処理（guardFit）は残す。縮めるときは書記素単位で、既存と同じ側（カーソルから遠い側。5 では後の列を先に、次に前の列）から取り除く。カーソルの書記素は取り除かない。縮めきれないときは、既存と同じく入力を表示しない（FR4）
8. カーソル位置の rune だけを反転表示する描画は変えない。反転表示の位置は、既存と同じく rune 単位でカーソル位置から求める（SPEC a2）

### 事後条件

- 入力を表示するとき、開始位置と終了位置は常に書記素の境目（入力の先頭・末尾を含む）である（FR1, FR2）
- カーソルが末尾以外で入力を表示するとき、表示範囲はカーソルの書記素全体を含む（FR3）
- m.width > 4 のとき、View の結果は改行を含まず、表示幅は m.width − 2 以下（FR4）
- スクロール時、表示幅が許す限り、カーソルの書記素（カーソルが末尾のときは入力の最後の書記素）が表示される（FR4）
- 入力長に対して線形の時間で終わる。入力全体の書記素への分割は 1 回、各書記素の幅の測定は 1 回、guardFit の測り直しの回数の上限は既存のまま（NFR2）
- 次のものは変えない（NFR1, SPEC a2, a4, a8）
    - 幅 0〜4 の経路
    - 入力全体が実際の幅で収まる場合の経路
    - カーソル位置の rune だけを反転表示する描画
    - HandleKey などの編集操作と、cursorPos が rune 単位であること
- minibuffer.go の幅の単位を説明するコメントは、書記素を単位とする内容に合わせる

### テストで使う数値

- プロンプト `(search): ` の表示幅は 10
- 入力は `aaaaa` + 家族の絵文字（U+1F468 U+200D U+1F469 U+200D U+1F467 U+200D U+1F466）+ `bbbbb`。17 rune、実際の表示幅 12。家族の絵文字は rune 位置 5〜11 にあり、表示幅は 2
- m.width 24（残りの幅 10）でカーソルが末尾のとき
    - 変更後: 残す列は `aa` + 家族の絵文字 + `bbbbb`（開始位置は rune 3）
    - 変更前: 開始位置が rune 9 になり、`👧‍👦bbbbb` と表示される
- m.width 24 でカーソルが位置 0 のとき
    - 変更後: 表示範囲は `aaaaa` + 家族の絵文字 + `bbb`（終了位置は rune 15）
    - 変更前: 終了位置が rune 9 になり、`aaaaa👨‍👩‍` で切れる
- m.width 15 は残りの幅 1 で、表示幅 2 の家族の絵文字は入らない
- m.width 27 は残りの幅 13 で、カーソルが末尾なら入力全体とカーソルブロック（12 + 1）が収まる

## Acceptance Criteria (MANDATORY)

「表示上の文字列」は、View の結果から端末の装飾用エスケープシーケンスを除いた文字列を指す。「1 行の条件」は、View の結果が改行を含まず、表示幅が m.width − 2 以下であることを指す。
AC-1〜AC-4 と AC-6 のプロンプト・入力は「テストで使う数値」のもの。

- [ ] AC-1（FR1, FR4 / SPEC AC1, TS-1）: m.width 24、カーソルが末尾のとき、表示上の文字列に `👨‍👩‍👧‍👦bbbbb` が続けて含まれ、1 行の条件を満たす
- [ ] AC-2（FR2, FR4 / SPEC AC2, TS-2）: m.width 24、カーソルが位置 0 のとき、表示上の文字列に `aaaaa👨‍👩‍👧‍👦` が続けて含まれ、1 行の条件を満たす
- [ ] AC-3（FR1, FR2, FR3, FR4 / SPEC AC3, TS-3）: m.width 15〜27 の各幅とカーソル位置 0〜17 のすべての組み合わせ（カーソルが家族の絵文字の途中の rune にある位置 5〜11 を含む）で、表示上の文字列が、家族の絵文字の結合文字列全体を含むか、U+1F468・U+1F469・U+1F467・U+1F466・U+200D のどれも含まないかのどちらかであり、1 行の条件を満たす
- [ ] AC-4（SPEC TS-4）: AC-1〜AC-3 と AC-6 のテストは、ほかの確認の前に、プロンプトの表示幅 10、入力の rune 数 17、入力全体の実際の表示幅 12、家族の絵文字の表示幅 2 を確かめ、どれかが崩れていれば、崩れた値と期待する値を示して致命的な失敗で即座に止める（既存の checkFamilyEmojiFixture と同じ形）
- [ ] AC-5（FR1, FR2 / SPEC Edge Cases）: 国旗（U+1F1EF U+1F1F5）と肌色の修飾子付きの絵文字（U+1F44D U+1F3FD）のそれぞれについて、入力 `aaaaa` + その並び + `bbbbb`、プロンプト `(search): ` で、m.width 15〜27 の各幅とカーソル位置 0〜12 のすべての組み合わせで、表示上の文字列が、その並び全体を含むか、その並びの rune をどれも含まないかのどちらかであり、1 行の条件を満たす。テストは最初に、その並び全体の表示幅が 2 で、rune ごとの幅の合計が 2 より大きいことを確かめ、崩れていれば致命的な失敗で止める
- [ ] AC-6（FR3）: m.width 15（残りの幅 1）で、カーソルを家族の絵文字の rune 位置 5〜11 の各位置に置いたとき、表示上の文字列のうちプロンプトより後ろの部分に空白以外の文字がなく（入力の文字も U+200D も表示されない）、1 行の条件を満たす
- [ ] AC-7（NFR1, NFR2 / SPEC AC4, TS-5）: minibuffer_test.go の既存テスト（LinearTime 系、TS7_JoinedSequenceGuard、VS16 系、ZWJInput 系、プロンプトの切り詰めのテストを含む）が変更なしで通り、go test ./... がすべて通り、gofmt で差分が出ない。変更したファイルは internal/ui/minibuffer.go と internal/ui/minibuffer_test.go だけで、go.mod と go.sum の変更は github.com/rivo/uniseg を直接の依存にすることに伴うものだけ

    - assertBoundedSingleLine（minibuffer_test.go）: 1 行の条件の確認
    - mustNotPanic（pane_render_test.go、同じテストパッケージ）: パニックをテストの失敗として報告
    - stripANSI（model_view_test.go、同じテストパッケージ）: 表示上の文字列を得る
- 追加するテスト用の補助関数

| 補助関数 | 責務 | 契約 |
|----------|------|------|
| 前提の確認（AC-4） | フィクスチャの数値を確かめる | 事前条件なし。プロンプトの表示幅 10、入力の rune 数 17、入力全体の実際の表示幅 12、家族の絵文字の表示幅 2 がすべて成り立つときだけ通常どおり戻る。崩れていれば、崩れた項目・期待する値・実際の値を示して致命的な失敗で止める |
| 丸ごとか皆無かの確認（AC-3, AC-5） | 結合文字列が途中で切れていないことを確かめる | 事前条件: 表示上の文字列と、対象の並びを受け取る。事後条件: 表示上の文字列が対象の並び全体を含むか、対象の並びのどの rune も含まないときは何も報告しない。それ以外は、致命的でない失敗として表示上の文字列を示して報告する |

- 前提の確認だけを致命的な失敗にする。1 行の条件と表示内容の確認は致命的でない失敗にし、表形式のテストでは組み合わせごとの失敗がすべて報告されるようにする
- AC-3 と AC-5 は m.width × カーソル位置の表形式にし、サブテスト名に幅とカーソル位置を含める
- AC-6 の判定は、表示上の文字列のうちプロンプトより後ろの部分だけで行う。プロンプト `(search): ` 自体が `a` を含むため
- テストを先に書き、変更前のコードで失敗することを確かめてから実装する
    - AC-1・AC-2 は変更前のコードで失敗する（「テストで使う数値」を参照）。AC-3 も AC-1・AC-2 と同じ組み合わせを含むので失敗する
    - AC-6 は、カーソルが U+200D（位置 6 など）にあるとき、変更前のコードでは U+200D だけが表示範囲に入るので失敗する
    - AC-5 は、変更前のコードでは並びが rune ごとの単位に分かれるので、境界がかかる組み合わせで失敗する。失敗する組み合わせがなかったときは、そのことを実装報告に記録する
- 見えない文字（U+200D）や絵文字の部品は、レビューで読めるようにコードポイント表記で書く
- AC-7 はテストを書かず、テストの実行結果、gofmt の結果、差分のファイル一覧で判定する。LinearTime 系のテストが時間内に終わることで、線形の時間で終わる性質を保つことを確かめる
