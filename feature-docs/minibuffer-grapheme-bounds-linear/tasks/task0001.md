# Task Plan: task0001 — Linear-time grapheme cluster locator for the minibuffer

## Goal

The minibuffer's grapheme cluster locator (`graphemeClusterBounds` in `internal/ui/minibuffer.go`) returns exactly the same bounds as today, but in time linear in the input length — including for input shaped as a period followed by a long run of spaces and a letter — and time-bounded regression tests fail if it ever becomes quadratic again.

## Requirements

FR1, FR2, NFR1, NFR2, NFR3

## Scope

### Files to Create

None.

### Files to Modify
- `internal/ui/minibuffer.go` — replace the locator's scan with a grapheme-cluster-only forward pass that carries segmentation state; update its doc comment accordingly (signature, results and callers unchanged)
- `internal/ui/minibuffer_test.go` — add the time-bounded regression tests for View, Left/Ctrl+B and Right/Ctrl+F, a timed single-key helper, and direct locator edge-case tests; existing tests are left untouched

## Design

### Root cause (context)

The locator currently walks the input with the segmentation library's combined-boundary iterator (rivo/uniseg), which on every step also computes word, sentence and line boundaries. The sentence rule for a terminator followed by spaces looks ahead over the remaining spaces at each space, so a single locator call costs quadratic time on input shaped as "." + n spaces + "A". The locator only needs grapheme cluster boundaries.

### Locator contract (unchanged — FR2)

| Item | Contract |
|------|----------|
| Signature | graphemeClusterBounds(runes, p) → (start, end), rune offsets — unchanged |
| Precondition | 0 <= p < rune count; callers never ask about the end position (unchanged) |
| Postcondition | [start, end) is the extended grapheme cluster containing rune p, where clusters are those obtained by segmenting the WHOLE input starting at its first rune, never a sub-slice — identical to the current results |
| Out-of-range p (p >= rune count, including an empty input) | returns (p, p+1) without panicking — unchanged |
| Byte offsets | never leave the function (unchanged) |
| Callers | View (cursor not at the end), Left/Ctrl+B, Right/Ctrl+F — not modified |

### Processing flow (FR1)

1. Take the whole input as text; set the running rune position to 0 and the segmentation state to the library's "state unknown / start of text" value.
2. Obtain the first grapheme cluster of the remaining text from the library's grapheme-cluster-only stepping function — the same function `partitionUnits` in this file already uses — passing the current state, and keep the state it returns for the next step.
3. Count the cluster's runes. If p lies before (running position + that count), return [running position, running position + count) and stop scanning.
4. Otherwise advance the running position by the count and repeat step 2 on the remaining text with the carried state.
5. If the text is exhausted without reaching p, return the defensive (p, p+1).

The state returned by each step MUST be passed into the next step (never reset to the "unknown" value between clusters), so that context-dependent clustering (regional-indicator pairing, emoji ZWJ sequences) matches whole-input segmentation. The combined-boundary iterator is no longer used by the locator. Only the locator's body and doc comment change; `partitionUnits`, `guardFit`, View's windowing logic and HandleKey are untouched.

### Regression test fixture and helpers (NFR1)

- Input: "." followed by 100000 spaces followed by "A" (100002 runes), the same size as the existing linear-time tests. From the measured quadratic growth, the pre-change locator needs about 60 s per call at this size, beyond `linearTimeLimit` (10 s); at 8000 spaces it needs only about 0.4 s and would not detect a regression.
- View is timed with the existing timed-View helper (`runViewTimed`), at a width where the input does not fit on one line (for example the widths the existing linear-time tests use).
- A new timed single-key helper mirrors `runViewTimed`: it performs one HandleKey call in its own goroutine, recovers a panic and reports it as a test failure, fails the test if the call does not return within `linearTimeLimit`, and abandons a timed-out goroutine (same treatment as the existing helper). The cursor position is read only after the helper has observed completion.
- Each key (Left, Ctrl+B, Right, Ctrl+F) is exercised on its own freshly prepared, visible minibuffer with the input set and the cursor placed.
- The test file already contains tests labelled TS1–TS4 and TS7 from an earlier feature; name the new tests after this fixture (period followed by spaces) so they cannot be confused with those.

## Test Notes

- AC-1 to AC-3 are unit tests in the minibuffer test file, timed with `runViewTimed` and the new timed single-key helper; together they are the automated counterpart of the SPEC reproduction procedure.
- AC-4: write AC-1 to AC-3 first and run them against the unmodified locator; each should fail after waiting about `linearTimeLimit`. Timed-out goroutines keep running in the background of the test binary during this red-phase run — expected, as with the existing linear-time tests.
- AC-5 expected clusters: three regional indicators + "a" → [0,2) [2,3) [3,4); "a" + man-ZWJ-woman-ZWJ-girl (5 runes) + "b" → [0,1) [1,6) [6,7). Include positions inside a multi-rune cluster (they return that cluster's bounds). Negative p is not pinned by this task.
- AC-6: existing tests are the equivalence oracle for the pre-change results; do not edit or delete any of them — a failure there means the locator change is wrong.
- The timed single-key helper must stay clean under the race detector: read the minibuffer state only after completion has been signalled.
