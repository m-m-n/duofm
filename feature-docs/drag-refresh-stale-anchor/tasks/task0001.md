# Task Plan: task0001 — Cancel a drag session when its pane's displayed list changes

## Goal

A drag session armed on a pane is cancelled at its next motion or release
when that pane's displayed entry list (post-filter) no longer matches the
press-time list name for name and in order, leaving marks untouched. When the
list still matches, the drag continues from the original anchor without
re-marking names of files that no longer exist.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, FR7, NFR1, NFR2, NFR3, NFR4

## Scope

### Files to Create
- `internal/ui/model_update_mouse_refresh_test.go` — model-level regression tests for this feature (SPEC TS-1..TS-8), driven through the Model's update entry point with temp-directory panes and real refresh messages

### Files to Modify
- `internal/ui/model_update_mouse.go` — the drag session gains a press-time displayed-name snapshot; the press records it; motion and release verify it before resolving the row and restrict the baseline before applying marks
- `internal/ui/pane_drag.go` — three new Pane helpers: displayed-name snapshot, displayed-name match, and baseline restriction to existing names
- `internal/ui/pane_drag_test.go` — unit tests for the three new Pane helpers
- `internal/ui/model_update_mouse_test.go` — only if a shared test helper needs a small extension; every existing test keeps its assertions

## Design

Follows IMPLEMENTATION.md D1 (check at the point of consumption; refresh
paths untouched) and D2 (the load-completion cancellation is kept).

### Drag session state

The drag session (today: armed, active, pane, anchor, baseline) gains one
field: the ordered sequence of the names of the drag pane's displayed
entries at press time, including the parent entry when it is shown. The
sequence is held independently of the pane's own entry storage. The
zero-value session carries an empty sequence.

### Pane helpers (pane_drag.go)

Identifiers are suggestions; the contracts are binding.

| Helper | Precondition | Postcondition |
|--------|--------------|---------------|
| snapshotDisplayedNames() → ordered name sequence | none | Returns a new sequence holding the name of every displayed (post-filter) entry in display order, parent entry included. Later changes to the pane's entries do not change the returned sequence, and changes to the sequence do not change the pane. |
| displayedNamesMatch(names) → bool | none | True exactly when the sequence has the same length as the pane's current displayed entries and every position holds the same name. Modifies neither the pane nor the sequence. |
| existingMarks(baseline) → name-to-marked map | baseline is a name-to-marked map (as produced by the existing mark snapshot) | Returns a new map holding exactly the baseline entries whose names appear in the pane's current full (pre-filter) entry list — the same list the preserve-cursor refresh uses to drop marks of vanished files. Names hidden by the filter but still listed are kept. Modifies neither the pane nor the baseline. |

### Processing flows

Press on an entry (not a double-click):
1. Everything up to arming the session is unchanged.
2. When arming, record the pressed pane's displayed-name snapshot in the
   session together with the anchor and the baseline.

Motion or release while the session is armed:
1. Before resolving the target row, check the session's snapshot against the
   drag pane's current displayed names.
2. No match: reset the session to the zero value (IMPLEMENTATION.md
   Conventions). For this event the pane's marks, cursor and scroll offset
   do not change. Later motions are ignored because the session is no
   longer armed; the release path's existing unconditional reset still
   applies.
3. Match: restrict the session baseline to names that still exist
   (existingMarks), then continue with the existing row resolution,
   still-a-click check, activation and mark application, unchanged.
   Replacing the session baseline with the restricted map or restricting a
   copy per application are both acceptable, as long as the pane's mark set
   after any application never contains a name absent from the pane's
   current full entry list.

### Invariants

- Only the drag session's own pane is checked (FR4). The other pane's lists
  are never read for this decision.
- No refresh path is modified, and neither is the preserve-cursor refresh
  (NFR2).
- The directory-load-completion cancellation and its tests are unchanged
  (NFR3).
- The double-click detector is not touched by the new cancellation, the same
  as the load-completion cancellation.
- When the displayed list does not change during a gesture and every
  baseline name is still listed, click, drag and double-click behave exactly
  as today (NFR1).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (SPEC TS-1): with a temp-directory model, press a left-pane entry (armed, no motion), add a file to the left pane's directory, and process an auto-refresh message. Right after a motion to a different row, the session is neither armed nor active. After the release, the left pane's mark set equals the set captured right after the refresh.
- [ ] AC-2 (SPEC TS-2): press and move in the left pane so a range is marked (active session), delete a file that is not marked from the left pane's directory, and process an auto-refresh message. The mark set right after the refresh equals the set right before it. A motion and release on another row leave the mark set unchanged, and the session is neither armed nor active after the motion.
- [ ] AC-3 (SPEC TS-3, TS-6, TS-7): in each of three cases — (a) no file change, (b) only an existing file's content (size) changes, with names and order unchanged, (c) a filter is applied to the left pane before the press and a file that does not match the filter is added — after the auto-refresh message the session is still armed with the same pane and anchor, and a following motion marks exactly the press-time marks plus every displayed entry from the original anchor to the motion row, parent entry excluded.
- [ ] AC-4 (SPEC TS-4): after a left-pane press, adding a file only to the right pane's directory and processing an auto-refresh message leaves the left session's armed, active, pane, anchor and baseline unchanged. A following left-pane motion marks exactly the range from the original anchor to the motion row.
- [ ] AC-5 (SPEC TS-5): the AC-1 setup, refreshed once through an exec completion message and once through a shell command completion message instead of the auto-refresh message: after the motion and release, the left pane's mark set equals the set captured right after the refresh.
- [ ] AC-6 (SPEC TS-8): with two left-pane files marked and then hidden by an applied filter, press inside the filtered list, delete one of the two hidden files on disk, and process an auto-refresh message (the displayed list does not change). After a motion and release to another row, the deleted file's name is not in the mark set, the other hidden file is still marked, and the range from the original anchor to the motion row is marked.
- [ ] AC-7: Pane helper unit tests: the displayed-name snapshot is unaffected by a later replacement of the pane's entries and includes the parent entry; the match is true for an identical sequence and false for a different length, a different name at one position, and the same names in a different order; the existing-name restriction drops names absent from the full entry list, keeps names hidden by the filter but still listed, and leaves its input map unchanged.
- [ ] AC-8: `go test ./...` passes, including every existing test in the ui package (the drag-dir-load-stale-marks TS-1..TS-5 tests and the existing click, drag and double-click tests) without any change to their assertions; gofmt reports no files to reformat; `go vet ./...` reports nothing.

## Test Notes

- Write AC-1, AC-2 and AC-6 first and confirm they fail against the current
  code before implementing the fix (SPEC AC8: fail before the fix, pass
  after). The AC-3, AC-4 and AC-5-style continuation checks are expected to
  pass both before and after.
- Keep the new model test file free of references to the new Pane helpers
  and to the new session field (assert only through armed, active, pane,
  anchor, baseline and the pane's mark set), so that the file alone
  compiles against the pre-fix code and the verify phase can re-check SPEC
  AC8 there.
- Check session state after the motion and before the release: the release
  resets the session unconditionally, so a check after the release cannot
  tell a cancelled session from a finished one.
- The auto-refresh message is a no-op unless the model has a positive refresh
  rate and no dialog, and its handler updates disk space, so the test model
  needs a disk-space monitor (the existing drag-load test model builder
  already provides one) and a positive refresh rate.
- AC-3 (b): keep the default name-based sort so a size change cannot reorder
  entries.
- AC-3 (c) and AC-6: rows map to indices in the filtered list; pick filter
  patterns that keep enough entries visible for the anchor and motion rows.
- AC-6: mark the two files before applying the filter (for example through
  the pane's mark toggle at the cursor, or by placing names in the pane's
  mark set), so both are baseline marks that the filter hides.
- AC-5: the exec and shell completion handlers refresh the active and the
  inactive pane; use completion messages without an error, and no shell
  logger is needed.
- AC-7 lives in the Pane helper test file; AC-1..AC-6 live in the new model
  test file.

## Out of Scope

- Any change to the refresh paths or to the preserve-cursor refresh.
- Any change to the directory-load-completion cancellation.
- Mark handling on directory change, filter change, hidden-file toggle, or
  operations that clear marks.
- New E2E tests.
- Status messages or other visual feedback for the cancellation.
- Detecting a directory change whose name sequence is identical.
